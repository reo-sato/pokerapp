## 読むときの注意（数え方の偏り）

1. **10/19 の「言われない」は多めに出る**: 10/19 の記録は、ライブがハンドを早く閉じて聞き取りを止めた分の発話が無い（台帳 E が
   10/24 に直した。聞き流した発話の書き起こし `offplay.jsonl` は 10/19 には無い）。言われなかったのか、録れていないのかを分けられない。
   特に終盤の行（ハンドを終わらせるフォールド・ターン / リバーの行）。
2. **組むのに使った読み**: Whisper・ライブの規則・短い語の分類器・第 2 の耳の候補・音で読んだ額。決まり文句の下のアクション
   （雑談に「アクションを言った」と仮に置く読み）は使わない（`--guesses` で使う）。第 2 の耳の候補は種類と額まで合うときだけ組む
   （雑音の発話にも付くので）。どの読みで組んだかは `--dump` の `source`。
3. **p_button** は真にボタンを入れたハンドだけ。オーナーはボタンが違うと気づいたハンドに入れることが多いので、多めに出る。
4. **p_open_fold** はプリフロップを数えない（BB のオプションが分からない）。真のアクションにベットの無いところのフォールドは 0。
5. **持ち上げ（秒 / 1 席）** の分母は「配られた人数 × ハンドの始まりから時刻の分かる最後の行まで」で、降りたあとの席も入る
   （= 多めの分母 → 持ち上げの間隔は長めに出る）。
6. 8 人卓でフォールドの順が音で決まらないハンドも母数に入れた（オーナーは声・記憶・整合性・離脱を総合して決めている）。
7. 目で確かめたハンド: 開発データ 11（845da8e6#1・#6、1f838667#15・#20、fded6f75#1・#3、9db1e032#4、7b897671#2、9d1d8536#2、
   05cccd6c#4、15cad555#3）。確かめる中で直した組み方 3 つ（ボードの位置ではなく読めた時刻でストリートを決める・同点は Whisper の
   読み・第 2 の耳の候補は額まで合うときだけ）。直したあとの誤り 0。
8. **読みの当たりの割合**は、発話の選択肢のうち真の行を説明したものを「当たり」とする（同じ行を 2 つの読みが同じように説明すれば
   Whisper → 救い出し → 短い語の順で選ぶ = F1 の同点の決まり）。決まり文句の下のアクションの読みは選択肢から除いたので、ほかの読みの
   今の値の見込み（softmax）は少し高めに出る。

## F3 値を差し替えたときの感度（2026-10-25）

### F3a 順位のひっくり返りの試算（`tools/param_flips.py`）

今の値で 1 回探し（誤ったハンドはオラクルの `guided_search` で真に届いた記録、正しいハンドは推定器の候補）、差し替えた値で
**探し直さずに**採点し直す。誤ったハンドで真が候補のどれよりも高くなれば「直る見込み」、正しいハンドで真でない候補が真を抜けば
「壊れる見込み」。対象: 開発データ = 誤りで真に届いた 15・正しい 142、10/19 = 誤りで真に届いた 24（うち今の値でも真のほうが高い
= 探しきれない 5）・正しい 25。

|---|---|---|
| 1 つずつ（言われない 9 組・余計な語・離脱 6 組・取り違え 4 組・耳 3 組） | どれも 0 / 0〜2 | どれも 0〜2 / 0〜1 |

## F4 値の提案（オーナーが採否を決める）

1. **`short_cap` 1 → 2.5**（`integration/estimator.py:READING_OVERRIDES`）。根拠: 短い語の分類器の読みの当たりがどちらのデータでも
   今の見込みを大きく上回る（0.80 / 0.61・0.77 / 0.52、当てはめ a +1.2〜1.6）。物差しで開発データ 142 → 143・10/19 26 → 28、失った
   ハンド 0、要確認なしの誤りは増えない。2.5 は当てはめの a（+1.2〜1.6）を 1 に足した値で、細かく合わせてはいない。入れるときは
   README §6 の手順（`bench_hands.py --twice --search-check`・`compare_versions.py`・`docs/estimator.md` §3.3 と §6）。開発データは
   標本内なので、精度は次の新しいセッションで見る。
2. **入れない（v1 の値では直らない）**: 言われない率・余計な語・取り違え・持ち上げ・第 2 の耳の候補の値。1 つずつでも、数えた値を
   まとめても、直るハンドと壊れるハンドがほぼ同じ。数えた値は B（v2）の生成モデルの値の出発点にする（卓の人数ごとに違う値 = 離脱の
   幅・言われないチェック / コール・余計な語は、v2 で卓の人数を特徴にするときに使う）。
3. B の推定器の直し（言われなかった賭け `f9d5c34`・`a1663d8`）が verify-v1 に入ったら、提案 1 を同じ手順で測り直す。
