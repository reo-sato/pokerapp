# 使い方ガイド

## 起動モード

```bash
python main.py            # GUI（ハンドロガー画面）
python main.py --cli      # CLI（音声のみ・画面なし）
python main.py --cli --log-file   # CLI。ログを端末に出さない（店舗 PC の「ハンドロガー (CLI)」= start_logger.cmd）
python main.py --players  # プレイヤー登録画面（別画面）
python main.py --ledger   # 会計（台帳）入力 + 注文確定画面（別画面）
python main.py --viewer-api  # お客さん向けのハンド閲覧（画面 + 読み取り専用 API, 要 [api] extra）
python main.py --viewer-api --host 0.0.0.0 --port 8788   # 店の Wi-Fi のスマホから開く（下の「お客さんがスマホで…」）
python main.py --export-phh logs/<セッションID>.json   # JSON → PHH 変換
```

GUI と `--cli` はどちらも**音声でハンドを記録**します。配信や省リソースなら `--cli` が手軽です。

## 読み上げの基本

店舗の言い方（席番号もベット / レイズの語も言わない）に合わせて読みます。**誰のアクションかは手番の順**で決まります
（ボタンの次の席から。ボタンはハンドごとに回ります）。

```
600            ← 額だけ = ベットかレイズ（どちらかは場の状況で決まる）
コール         ← コールは毎回言う（金額は言わなくてよい）
フォールド     ← 降りた人の札が席から離れればフォールド
チェック       ← チェックも毎回言う
```

- **コール・チェックは毎回言います**（2026-09-29 から。前の「連続する同じアクションの 2 回目以降は省略」の運用はやめました）。
  言われなかったチェック / コールは、あとの札の動きから補いますが、補った行は**いつも要確認**です。
- **ベット / レイズは額だけ**言います（「600」「2千点」）。額だけの発話はベットかレイズです。**レイズの額はいつもトータル**
  （「〜まで」の額。上乗せ分は言わない）。いまのベット以下の額（コールの額の言い直し・ポットの読み上げなど）は記録しません。
- **フォールドは席の札で決まります**（下の「フォールドは札で決まる」）。「フォールド」は基本的に言ってください（札の離脱と組にします）。
- **チェックアラウンドはストリートが変わるとき**に言います（前のストリートを閉じる言葉。「チェック、アンド」と聞こえても
  チェックアラウンドと読みます）。新しいストリートの札の直後（3 秒以内）に聞こえたチェックアラウンドは、前のストリートのことです。
- **残りの人数**: 「ヘッズアップ」（残り 2 人）・「スリープレイヤーズ」「3 ウェイ」（残り 3 人）など。ストリートの移りに言います（任意）。
  ベットに向き合っていた人がまだ残っていれば、その人はコールしたとみます（言われなかったコールを要確認にせず補う）。
  人数が合わなければ知らせて要確認です。コールのすぐあとの「3 レイ」「3 レイズ」のような語も残りの人数として読みます
  （「コール 3 レイ」= コール + 3 ウェイ）。
- **ストリートの札より前にそのストリートのアクションは言いません。** 言った場合は前のストリートのアクションとみて組み直します
  （CLI に「● 「1200」はターンの札が置かれる 13 秒前に話されていたので、フロップのアクションとみて組み直しました…」）。
  「ターンです」「ラストカード」「リバーです」はアクションではありません（言わなくてもよい）。
- **確認の形の文はアクションにしません**（「コールですか？」「レイズ 2400 でよろしいですか？」）。そのあとに言う確定の言葉
  （「コール」）だけを読みます。
- **言い間違えたら「失礼しました」**（「失礼いたしました」「大変失礼しました」も可）と言い、正しいアクションを続けて言います
  （「600点」→「失礼しました。800点。」= 800 のベット）。**直前のアクションの訂正**か、**ストリートの最初からの言い直し**かは、
  そのあとのアクションとの辻褄で選びます（CLI に「● 「失礼しました」— 直前のアクション（…）を取り消しました…」。そのハンドは
  要確認）。ハンドの最初からやり直すことはありません（前の「アクションリセット」はこれに置き換えました）。
- **チェックレイズは「レイズ 1200」とだけ**言います（「チェック、レイズ」と区切って書き起こされると 2 人のアクションと区別できない）。
- 続けて言っても構いません。「フォールド、フォールド、コール」のように 1 息で言った複数のアクションは、言った順に分けて記録します。
- **金額**: 半角数字（`500`）・漢数字（`五百` / `1万`）・仮名（「ロッピャク」= 600、「センテン」= 千点、「2センテン」= 2000、
  「ベト ナナ」= ベット 7）。「2千500」= 2500、「1万6千100」= 16100、「7千ロッピャク」= 7600。「千」「万」のあとに意味の通らない
  語が来たら、前の数だけを額にして要確認です。
- 席番号やポジション名を言っても構いません（「シート3 コール」「BTN コール」= その席。手番の順より優先）。
- 「チェック」のような短い言葉も拾います。拾えていないときは `python tools/audio_check.py listen` で
  「短い音 N 秒 — 認識に回さず」と出ていないかを見ます（出ていれば `audio.min_speech_sec` を下げる）。
- 認識は発話より数秒遅れることがあり、忙しい場面ではその遅れがたまります（プレーの切れ目で追いつきます。
  発話は捨てません）。遅れている間に `n` / `w` などを打つと、**打つ前に話し始めた発話の反映を待ってから**入ります
  （「聞き取った発話を先に反映しています… 残り N 件」）。前のハンドのアクションが次のハンドに入ることはありません。

### フォールドは札で決まる（RFID の卓）

- 席の札が **3 秒離れたまま**戻らない（`engine.fold_absent_sec`）か、**卓の中央（ボードのリーダー）を通った**ら、その席のフォールドです。
  CLI に `← 札が離れた` / `← 札が中央を通過` と出ます。札が戻れば、少なくともその時刻まではフォールドではないので取り消して組み直します。
- 「フォールド」の語と札の離脱は **1 対 1** に組みます（1 つの離脱が 2 つの「フォールド」を吸わない）。
  - 札が離れかけている席があれば、その席のフォールドです。
  - 「フォールド」と言われても手番の人の札が席に残ったまま次のストリートの札が置かれたら、その人は降ろさずチェック / コールにします（要確認）。
  - 札が残ったまま別の席の札が離れたら、その「フォールド」は離れた席のことです。
- 手番でない席の札が離れたら、その前の人のアクションが聞き取れなかったとみて、間の人をチェック / コールで補います（要確認）。
- ベットに全員が降りたあと、勝った人が素早く札を投げても構いません（降りた人の札が先に離れているので区別できます）。
- 札の離脱でフォールドを決めないようにするには `engine.rfid_folds` を `false`（音声の「フォールド」を次の手番の人に付ける従来の動き）。

## ハンド 1 回の流れ

RFID がある卓（店舗, ADR-0062）:

```
（手札を配る）                ← 1) 2 席以上に札が置かれるとハンドが始まる（n /「ハンド開始」は不要）
コール                        ← 2) アクションを手番の順に読み上げる（コール・チェックは毎回）
1200
フォールド
（フロップ・ターン・リバー…）
1000
コール                        ← 3) ベッティングが終わる
ショウダウン                  ← 4) ショーダウンでは必ず言う
ツーペア                      ← 5a) 見せた人の役名（見せるたびに必ず）
フォールド                    ← 5b) 見せずにマックした → 残った人の勝ち
```

- 画面（`--cli`）に `● ハンド 5 開始（手札が配られました / ボタン 席3）` と出ます。**配ったあとに「ハンド開始」と
  言ったり `n` を打ったりしても二重には始めません**。配る前に「ハンド開始」と言う運用もそのまま使えます。
- **ほかが全員フォールドしたら、残った人の勝ちで確定**します（`● ハンド 5 終了 — 勝ち: 席3 …（ほかは全員フォールド）`）。
- **ショーダウン**（2 人以上残ってベッティングが終わった）では、ディーラーは必ず「ショウダウン」と言い、すぐには決めません。
  - **役名 = 次に見せる人が見せた**（アウトオブポジションから順。ボタンの次の席から、2 人ならボタンでない方）。手札で役名に合う
    席がまだ見せていない中に 1 つだけあれば、その席です。CLI は「見せた（ツーペア）」と出ます。
  - 店の言い方の役名も読みます: 「キングヒット」「ナナのペア」「ポケットキングス」「エーシーズ」（ワンペア）、「Nヒット」
    （手札の N とボードの N のワンペア、またはボードのペアを無視した 2 ペア）、「エースファイブツーペア」、「ナナのセット」
    「トリップス」（スリーカード）、「エースキングフル」（フルハウス）、「キングハイストレート」「エースハイフラッシュ」、
    「クワッズ」、役が無ければ手札の名前（「クイーンジャック」「エースハイ」）。2 人の手をつないだ「キングハイにクイーンハイ」も読みます。
    役名は言い切りで言ってください（「キングハイですね」のような確認の形は記録では読みません）。
  - **「フォールド」= 見せずにマック**。まだ誰も見せていなければ一番アウトオブポジションの人、誰かが見せた（役名を言った）
    あとなら**まだ見せていない次の人**がマックしたとみます。アウトオブポジションが見せて役名を言ったあと、インポジションが
    見せずに降りたときも「フォールド」と言ってください。
  - **見せずにマックした人は、手札が強くても負け**です。手札で見てマックした人の方が強かったハンドは「要確認」になります。
  - 残った全員が見せたら手札とボードで決めます。**役名もマックも 8 秒無ければ**、残った全員が見せたとして手札で決めます
    （「ハンド終了」と言っても、次の手札を配っても決まります）。side pot の勝者が別でも、引き分けでも正しく配ります。
  - 役名は手札の判定と突き合わせます。違えば要確認です。手札が読めていない席も役名から決めます。
  - オールインで手を開いたら、その場で手札の名前を言います（ボードが出きる前の名前は見せた順にだけ使い、勝者は手札で決めます）。
  - 手札かボードが読めていないと「勝者を手札で判定できません（席5 の手札 1/2 枚）— w <席> で入力してください」と出ます。
    `w <席>` を打ってください。読めていない札のどれでも勝者が同じなら、その勝者に決めます（要確認）。札しだいで勝者が変わり、
    打たずに次の手札を配ったときは、**チップを動かさずに**終えます（各席が出した額を返す。勝者なし・要確認）。
- 分けたとき（チョップ）は、手札が読めていれば手札で決めます（引き分けは等分）。読めていなければ `w <席> <席>` で分けた席を入れます。
- 自動で決まったあとに `w <席>` を打っても、同じ席なら何も変わりません。違う席なら「確定済みです」と出るので、
  スマホの訂正画面で直してください。
- ボードは次のハンドを配る前に片付けます。

RFID が無い場合（従来）:

```
ハンド開始                    ← 1) 新しいハンドを始める
シート3 レイズ 600            ← 2) アクションを順に読み上げる（席を言わなければ手番の順）
シート1 コール
シート2 フォールド
（フロップ後…）
シート1 チェック
シート3 ベット 1000
シート1 コール
シート1 ウィナー              ← 3) 勝者を言うとハンドが確定・保存される
```

- **「ハンド開始」で始め、「ウィナー」で終える**のが基本リズムです（ほかが全員フォールドしたときは自動で確定）。
  RFID が無いと札の離脱が無いので、「フォールド」は次の手番の人に付きます。
- ストリート（プリフロップ→フロップ→…）は RFID でボードが入ると自動で進みます。RFID 無しの場合は
  アクションの流れから推定します。
- 自動の開始・判定を止めるには `config.json` の `engine.auto_new_hand` / `engine.auto_winner` を `false` にします。

### ハンドロガー（`--cli`）のコマンド

| 打つもの | 意味 |
|---|---|
| `q` | 終了（聞き取りが追いつくのを待ち、確定していないハンドを閉じて保存。`session_layer.enabled` ならセッションは「終了」になる） |
| `n` | 新しいハンド（RFID があれば不要） |
| `w <席>` | 勝者。分けたときは `w <席> <席>` |
| `r <席> <金額>` | 買い足し（リバイ）。スタック 0 の席は買い足すまで配られない |
| `name <席> <名前>` / `name <席> -` | 次のハンドからその席の人 / 空席（次のハンドから配られない） |
| `blinds <SB> <BB>` | 次のハンドからブラインドを変える（例 `blinds 200 400`） |
| `button <席>` | ボタンを手で直す。ハンドの途中ならそのハンドのボタンを直して組み直す（要確認）、ハンドの外なら次のハンド |
| `cb <位置>` / `cs <席>` | ミスディール訂正: ボードの N 枚目を取り消し / その席の札を読み直し |
| `rr` | 読み取り装置（ESP32）を再起動（卓に札が無いときに送る） |
| それ以外 | 読み上げ文として読む（例 `チェック` / `600` / `失礼しました`）。マイクが無くてもこれで進行できる |

コマンドは全角でも構いません（`ｎ` / `ｗ　１`）。

### ボタンの救済（ディーラーがボタンを動かし忘れたとき）

- ディーラーはボタンの次の席から 1 枚ずつ 2 周配ります。手札を最初に読んだ順（1 枚目と 2 枚目）が、別の席をボタンとした
  配り方に 1 か所の食い違いもなく合い、いまのボタンとは 2 か所以上食い違うときだけ、そのハンドのボタンを直して記録を組み直します
  （要確認, `engine.button_from_deal` 既定 true）。読み取りの時刻がそろわないとき（1 人で席ごとに 2 枚ずつ置いた等）は何もしません。
- 手で直すときは `button <席>`（上の表）。次のハンドのボタンは直した席から進みます。

### RFID の卓での扱い（入力は要りません）

- **フォールドした手札がボードのリーダーの上を通っても、ボードの札にはなりません。** そのハンドで席のリーダーが
  読んだ札は、卓モニタにその席の「マック」として出るだけです。
- **ボードの札は、置いてから約 2 秒載り続けると数えます。** 一瞬通過した札は数えません。配った時刻は
  最初に見えた時刻で記録します。
- **フロップの札が 1 枚読めないとき、ターンの札をフロップに入れません。** 一番右のボードのリーダーだけで読んだ札はターン・リバー、
  一番左のリーダーで読んだ札はフロップ、それ以外はフロップの最初の札から 10 秒（`rfid.flop_window_sec`）より後ならターン以降です。
  読めなかった位置は記録で `??`（例 `3c Kh ?? Kc 9s`、CLI は `?`）。ストリートは枚数ではなく位置で決めます。フロップは 2 枚
  読めればフロップが始まったとみます。
- **ミスディールの配り直しは、そのまま配れば反映されます。** 手札は、前の札が約 6 秒見えなくなり、新しい札が
  載り続けると差し替えます。札を持ち上げて見るだけでは差し替わりません。差し替えたハンドは要確認
  （`needs_review`）になります。すぐ直したいときは、ハンドロガーの `cs <席>` / `cb <位置>` も使えます。
- **ボードは 1 枚だけ差し直せます。** 間違えた札を取り、**同じ場所に**正しい札を置いてください（flop の 1 枚を
  差し直しても turn にはなりません。turn / river も同じ場所に置けば差し替わり、外してから時間が空いても
  大丈夫です）。反映は、前の札を取ってから約 3 秒後か、新しい札を置いてから約 2 秒後の遅いほうです。
  **前の札を先に取ってから**新しい札を置くのが確実です（先に置く場合は 2 秒以内に前の札を取る）。flop を全部外して
  配り直した場合も、そのまま配れば直ります。river まで配ったあとで turn などを差し直した場合も、新しい札は
  取った札の位置に入ります（前の札を取ってから 3〜6 秒ほどで反映。それまでは「差し直し確認中」）。
- **読みにくい位置の札は差し直しとみなしません。** 置いてから一度でも読めなくなった札（卓モニタで「外れた」が
  出たり消えたりした札・ログに「読み直しました」が出た札）は、載ったまま読めないだけのことがあるためです。
  その札を本当に差し直すと、新しい札は次の位置に入り、次の札（river）を置いた時点で詰め直されます。
- **読めなくなっていた札が戻ると、差し替えは取り消されます。** 札が読めない間に次の札（例: river）を置くと、
  いったん差し直しとして記録されることがありますが、前の札がまた読めれば元の並び（turn → river）に戻ります。
  札がリーダーにしっかり読める位置に置くのが一番確実です（下の「置く位置」）。
- **卓モニタは、外した札を「外れた N s」と薄く表示します。** 札を外したのに「外れた」が出ないときは、その札は
  まだどこかのリーダーに読まれています（手に持ったままリーダーに近い・ボードの上に置いた 等）。
- **置いた札が読めていれば、数える前から「確認中 N s」（差し直しなら「差し直し確認中」）と点線で出ます。**
  約 2 秒で普通の表示に変わります。置いたのに「確認中」にすら出ないときは、その札はどのリーダーにも読めて
  いません。リーダーの境目を避けて置き直すか、他の札に重ねずに置いてください。
- **回収した札とバーンカードは、ボードのリーダーから外れた位置に置いてください。** 席で読めていない札が
  ボードのリーダーの上に置かれたままだと、ボードの札として数えてしまいます。
- **置く位置**: ボードの札は、リーダーの境目を避けて**リーダーの真上**に置くと安定して読めます。ボードのリーダーが
  5 枚より少ないと境目に来る位置が出るので、1 枚ずつ置いて卓モニタに「確認中」がすぐ出て、そのまま置いておいても
  「外れた」が出ない位置を確かめ、フェルトに印を付けておくと確実です。どのリーダーが読んでも位置は配った順で
  決まるので（turn を真ん中と隣のどちらのリーダーで読んでもかまいません）、リーダーを動かした・台数を変えた
  ときは `config.json` の board の並び（左から右）を合わせるだけです。すでに札が載っているリーダーの上に置いた
  札は、見つかるまで最大 2 秒ほど遅れます（札の無いリーダーの上ならすぐ見つかります）。
  **ボードのリーダーが 3 台の卓（店舗の実卓）**: flop 3 枚を 1・2 台目のリーダーの上に置き、**flop と turn の間を
  少し空けて turn を 3 台目のリーダーの上に**置きます（ログの「左から 3 台目」。turn をリーダーの境目に置かない）。
  river は turn の隣、同じ 3 台目の上です。

### 読み取り装置（ESP32）の再起動

- 使えないリーダーがあると、CLI に「● ⚠ RFID: 使えないリーダーがあります: ボードの左から 2 台目のリーダー（reader 9）…」と出ます。
  ボードのリーダーが 2 ハンド続けて 1 枚も読まなかったときも知らせます。
- **`rr`** で読み取り装置を再起動します（卓に札が無いときに送ります。札が載っていれば片付くのを待ちます）。結果は
  「● RFID: 読み取り装置を再起動しました — 11 台とも使えます。」のように出ます。
- 使えないリーダーがあれば、卓に札が無い状態が 10 秒続いたときに**自動で**再起動します（1 つの不調につき 2 回まで、
  `rfid.auto_restart` 既定 true。`false` なら知らせるだけ）。
- **ファームウェアが古い**（再起動の命令が使えない）と、その旨の案内が出ます。そのときは **ESP32 の給電アダプタを抜いて数秒待って
  挿し直します**。店舗の卓は給電アダプタで動いているので、**PC との USB を抜き挿ししても ESP32 は再起動しません**。
  リーダーのコードが抜けた・挿し替えたときも同じです（リーダーの準備は起動時だけ）。直ったかは
  `python tools/rfid_relay.py watch`（RDP でなければ `python tools/probe_pcsc.py watch`）で左・真ん中・右と席に札を置いて確かめます。

### RDP で操作しているとき（RFID の中継）

RDP のセッションの中のアプリからはリーダーが見えません。管理者で `installer\rfid_relay_task.ps1` を 1 回実行すると、
中継（タスク `PokerRFIDRelay`、PC の起動時）がリーダーを読み、PC の中（`127.0.0.1:8792`, `rfid.relay_port`）だけでロガーに渡します。
ロガーは中継が動いていれば中継から読みます（CLI に「RFID: リーダー 11/11 台を中継（RDP の外の読み取り）から読んでいます。」）。
確かめるのは `python tools/rfid_relay.py status` / `watch`、再起動は `python tools/rfid_relay.py restart`。

### 言い間違い・言い直しに強い設計

既定の `pokerkit` バックエンドは**ポーカーのルールを把握**しているので、多少のズレを自動で整えます。

- ベットに直面しているのに「チェック」と言った → **コールに補正**し、`needs_review` を付けます。
- コール額を言い間違えても → **正しいコール額**（場の状況から計算）を採用します。
- 聞き取れなかったチェック / コールは、次のストリートの札・ほかの席の札の離脱から補います（要確認）。
- **言い直し**は次の人のアクションにしません（8 秒以内・あいだにほかのアクションが無いとき）: 同じ額のベット / レイズ、
  「オールイン」の言い直し、直前の賭けの額の言い直し（「1800」→「1700」= 1700 に直す、要確認）。いまのベットと同じ額のすぐあとの
  「コール」（「センテン、コール」）は、ここまでのアクションの言い直しとして記録しません。
- いまは使えない額（最小レイズに届かないなど）は、音の近い使える額にすることがあります（要確認）。
- 自信が低い・矛盾するものは `needs_review`（要確認）として記録され、後から見直せます。

### 音声のテスト（何と聞こえたかを見る）

1. **マイクの確認**（最初に 1 回・配る人が替わるたび）: `python tools/audio_check.py list` → `level` → `listen`
   （[トラブルシューティング: マイク](troubleshooting.md#マイクが認識されない録音されない)）。`listen` は本番と同じ経路で
   聞き取り、「何と聞こえたか → どのアクションになったか」を出します。初回は音声認識モデル（約 1.5 GB）の
   ダウンロードもここで済みます。マイクは名前で固定できます（`audio.device_name`、Bluetooth のつなぎ外しで番号がずれても同じマイク）。
2. **ハンドロガー**（`--cli`）: 聞き取った文を `[聞き取り] 「レイズ 600」→ raise 600 席3` と表示し、
   記録したアクションが続けて出ます。アクションとして読めなかった発話も「アクションとして読めず」と出ます。
   Whisper が読めなかった発話は第 2 の耳（日本語専用の音声認識）で聞き直し、読めれば「第 2 の耳「六百」→ bet/raise 600」と出ます（要確認）。
3. **スマホ画面のテスト表示**: お客さん用の画面の URL に **`?test`** を付けて開く（例
   `http://192.168.1.136:8788/?test`）と、ハンドの各アクションの下に**聞き取った文**と、補正したときは
   **その内容と理由**（「ベットがあるのにチェック → コールにした」など）が出ます。`?test` を付けない端末（お客さん）の表示は変わりません。
4. 生イベントの記録（`logs/<セッションID>.events.jsonl`, `recording.enabled`）は既定で on です（あとで再生・評価に使う。off にしないでください）。
   発話の音声も残すなら `audio.save_audio` を true にします（卓の会話も入るのでテスト中だけ）。

## お客さんがスマホでハンドを見る

お客さんが店の Wi-Fi で自分のスマホから、**自分が座ったセッション・ハンド・カード**を見られます
（ログイン不要。名前を選ぶだけ）。

### 準備（最初に 1 回）

ハンドロガーが「誰がどの席か」を記録するように、`config.json` の `session_layer.enabled` を `true` に
します（店舗 PC ではインストール先のフォルダで次の 1 行。メモ帳で直接書き換えるより安全です）。

```
cd C:\PokerHandLogger
.\venv\Scripts\python.exe tools\set_config.py session_layer.enabled true
```

### ハンドロガー（`--cli`）で席とお客さんを入れる

- 起動時の「席」に人数（例 `6`）か、札を置く**席番号**（例 `2 4 5 8`）を入れます。
- 続く「席N プレイヤー名」に**お客さんの名前**を入れます。**名前を入れずに Enter** した席は
  `PlayerN` になり、どのお客さんにも結び付けません（空席・名前を出したくない人）。
- **同じ名前は同じお客さん**です（前回の来店と同じ名前なら、履歴がつながります）。表記がゆれると
  別の人になります（例: 「たろう」と「太郎」）。
- **席替え**: `name <席> <名前>`（例 `name 3 花子`）で**次のハンドから**その席の人を変えます。
  `name <席> -` で空席（誰にも結び付けない・次のハンドから配られない）にします。ハンドの途中で打っても、そのハンドは元の人のままです。
- `q` で終えると、そのセッションはお客さんの画面で「終了」になります。

### 画面を出す

- デスクトップの「**お客さん用 ハンド履歴 (スマホ)**」（`start_viewer.cmd`）を起動します。表示される
  この PC の IPv4 アドレスを使い、お客さんはスマホのブラウザで **`http://<PC の IPv4>:8788/`** を開きます
  （例 `http://192.168.1.136:8788/`）。QR コードにして卓に置くと便利です。
- 名前を選ぶ → セッション → ハンド一覧 → ハンドの詳細（ストリートごとのアクション・ボード・
  ホールカード・収支）。ホールカードをどこまで見せるかは下の「手札の公開範囲」。
- 画面を先に起動しておいて構いません。あとから始めたセッションやハンドは、画面の「↻ 再読込」で出ます
  （画面を起動し直す必要はありません）。
- **本人確認が無いので、誰でも他の人の名前を選べます。** **店の Wi-Fi の中だけ**で使ってください。

### 手札の公開範囲（ADR-0067 D6）

お客さんの画面に出すホールカードの範囲を選べます（スタッフの画面はいつも全部見えます）。

- **全員分**（既定）: 記録した手札をすべて見せる。
- **自分 + 見せた手札**: 自分の手札と、ショーダウンで見せた手札だけ。見せずにマックした手札・フォールドした
  手札は伏せる（カードの裏で表示）。
- 店の設定: `config.json` の `viewer_api.hole_cards`（`all` / `own_and_shown`）。
  `.\venv\Scripts\python.exe tools\set_config.py viewer_api.hole_cards own_and_shown`（店舗サーバーを起動し直すと効く）。
- セッションごと: iPad のスタッフ用画面で卓を開き、上の「お客さんの画面の手札」で選ぶ（「店の設定」に戻すこともできる）。
- 店内の画面は名前を選ぶだけなので、他の人の名前を選べばその人の手札が見えます（目安の設定）。店外の画面
  （閲覧リンク）は本人だけなので守られます。
- 手元の PC で試すときは `python main.py --viewer-api`（`http://127.0.0.1:8788/`）。
  `--host` / `--port` は `config.json` の `viewer_api.bind_host` / `bind_port` より優先します。
- `--viewer-api` 単独は読み取り専用で、注文は受け付けません（503）。会計画面（`--ledger`,
  `viewer_api.enabled=true`）を使う日は、会計画面が同じ画面を出すので `start_viewer.cmd` は要りません
  （同じポート 8788 を使うため、両方は起動できません）。

画面は `mobile/`（Expo）の web 版で、ビルドを `api/static/player/` に同梱しています（店舗 PC に Node は
不要）。`mobile/` を変えたら `python scripts/build_player_web.py` で作り直してコミットします。

## 店舗サーバー（サインイン時に自動で動かす）

**店舗サーバー**は、お客さんのスマホの画面・スタッフの iPad の画面・注文の受付・卓モニタを、画面を持たずに
動かします（`python main.py --serve`, ADR-0065）。一度登録すると、**店舗 PC がサインインしたときに自動で動き**
（店舗 PC は通電で起動して自動サインインします）、止まっても 5 分以内に起動し直します。窓は出ません。
録音（ハンドロガー）は含みません（今までどおり RDP で起動）。**サインアウトすると止まります**（RDP は右上の × で閉じる）。

### 登録する（最初に 1 回）

1. デスクトップの「**店舗サーバー 自動起動の登録**」（`server_autostart.cmd`）をダブルクリックします。
2. 「動いています」と出れば完了です。表示された IPv4 アドレスを使います。
3. 止めて登録を消すには、PowerShell で `C:\PokerHandLogger\server_autostart.cmd remove`。

店舗サーバーが動いている間は、次のショートカットは要りません（同じ画面を店舗サーバーが出しているので、起動しても
断られます）: 「会計 + スマホ注文 API」・「お客さん用 ハンド履歴 (スマホ)」・「卓モニタ (iPad から閲覧)」。
会計の操作は iPad のスタッフ用画面で行います（会計を書くのは 1 か所だけ）。

うまく動かないときはログ `logs\store_server.log` を見ます。手で起動して確かめるなら `start_server.cmd`
（この窓を閉じると止まります。自動起動が動いているときは断られます）。

## スタッフが iPad で会計・注文を操作する

スタッフは iPad（Safari）から、会計・注文の確定・座席・ハンドの操作ができます（スタッフ用画面, ADR-0064）。
iPad 用に別の PC は要りません。

### 準備（最初に 1 回）

スタッフだけが知る合言葉（トークン）を決めて、店舗 PC のインストール先のフォルダで次を実行します
（`<トークン>` を置き換える。英字を含めてください。数字だけだと数値として保存されます）。

```
cd C:\PokerHandLogger
.\venv\Scripts\python.exe tools\set_config.py viewer_api.staff_token <トークン>
```

店舗サーバー（上）を使わず会計画面から出す場合は、さらに次の 2 行も実行します。

```
.\venv\Scripts\python.exe tools\set_config.py viewer_api.enabled true
.\venv\Scripts\python.exe tools\set_config.py viewer_api.bind_host 0.0.0.0
```

### 使う

1. 店舗サーバーが動いていること（上）。使っていなければ、店舗 PC で「**会計 + スマホ注文 API**」
   （`start_ledger.cmd`）を起動します。
2. iPad の Safari で **`http://<PC の IPv4>:8788/staff/`** を開き、トークンを入れてログインします。
   共有ボタンの「ホーム画面に追加」でアプリのように開けます。
3. 会計画面から出している場合、会計画面を閉じると iPad からの操作もできなくなります（画面は開けても
   書き込みは 503 になります）。

画面は `staff/`（Expo）の web 版で、ビルドを `api/static/staff/` に同梱しています（店舗 PC に Node は
不要）。`staff/` を変えたら `python scripts/build_staff_web.py` で作り直してコミットします。

### お客さんに「店の外から見られるリンク」を渡す（クラウドにつないだ店舗だけ）

店舗 PC をクラウドにつないでいれば（`docs/cloud-setup.md`）、お客さんは店の外からでも自分の記録
（セッション・ハンド・会計）だけを見られます。

1. iPad のスタッフ用画面 →「プレイヤー管理」→ その人の「**閲覧リンク (QR)**」。
2. 出てきた QR コードを、お客さんのスマホのカメラで読み取ってもらいます。一度開けば、そのスマホでは
   30 日のあいだそのまま見られます（期限が切れたら同じリンクでもう一度開くだけ）。
3. スマホをなくした・リンクを人に見られたときは「**取り消す**」。もう一度「閲覧リンク (QR)」を押すと
   新しいリンクになり、前のリンクでは見られなくなります。

- リンクは本人専用です。人に渡すと、その人にも同じ記録が見えます。
- 店の外からは注文できません（注文は店内のスマホの画面から）。

## ドリンク注文（任意）

注文受付を有効にするには、`config.json` で `viewer_api.enabled` を `true` にして
**`python main.py --ledger`**（会計画面）を起動します。会計画面が viewer API を同じプロセス内で
立ち上げ、プレイヤーはスマホのメニュー（`menu.json`、店側で編集）から注文を送れます。

注文は即座に台帳に記帳されません。スタッフが会計画面の「注文リクエスト」欄で**確定**すると、
単価（メニューから自動入力・上書き可）× 数量で台帳に order として記帳されます。誤った注文は
**却下**できます（台帳には何も書かれません）。注文を受け付けられるのは会計画面を開いている間だけです。

## 真のアクション履歴を入れる（テストのデータ蓄積）

通しで何ハンドもプレイして、ハンドごとに**実際に起きたアクション列**（真の履歴）を入れておくと、記録がどれだけ
合っていたかを数え、直す順番を決められます（`docs/dogfood/measurement-plan.md`）。

1. 店舗 PC で「真のアクション入力 (iPad から)」（`start_truth.cmd`）を起動し、iPad / スマホで
   `http://<PC の IP>:8791/` を開く（卓モニタと同じ Wi-Fi。ポート 8791 を LAN に許可する =
   `docs/installation.md` §0 の 8790 と同じ手順）。既に動いていれば二重には起動しません。
2. **進行中のハンドは、手札を配ったときから**一覧のいちばん上に「進行中（プリフロップ）」で出ます（5 秒以内）。プレーしながら
   入れられ、入れたところまで「保存」して、開き直して続きを入れられます（勝った席が未定でも保存できる）。ボードは記録（RFID）の
   札で自動で入り、ターン・リバーも数秒ごとに入ります（手で選んだ位置はそのまま）。ハンドが終わると、保存した内容が同じハンドに
   付きます。進行中は「記録どおり」にはできません。
3. **どのハンドも、まず記録を見ずに入れます**（左に「ブラインド」と出る。発話と札の流れと ▶ の音声は見られます）。
   - アクションは「次: 席 N の番」のボタンで順に足す（コールの額とストリートは自動、ベット / レイズはトータルの額を入れる）。
     「＋ 行を追加」で最後に 1 行足せます。行の席・アクション・額はあとから直せます（手番に合わない行は赤くなる）。
     覚えていない行には「自信なし」（?）を付けます。
   - **ボタン**: ディーラーがボタンを動かし忘れたときは実際の席を選びます（手番の順が変わる。記録と違えば
     「記録は席 N（ディーラーがボタンを動かし忘れた）」と出ます）。
   - ベッティングが終わると、残っている席ごとに **「席 N が見せずに降りた」** のボタンが出ます（ショーダウンのマック）。
     残りが 1 人になれば、その席が勝った席に入ります。ショーダウンで終わったハンドは、入れたボードと手札で勝者を判定して
     入れます（「手札で判定: 席 N」。引き分けは人が選ぶ）。
   - ボードと手札はカードをタップして選びます（ボードは記録から自動で入ります）。
   - 「保存」すると記録と並べて見せ、**記録と違う行を黄色**で出します。▶ の音声で確かめて正しい方に直し、もう一度「保存」します
     （直すところが無ければそのまま「保存」）。最初に入れた内容は残ります。
   - 練習のセッションでは「記録を見る」で先に記録を見られますが、押さないでください（記録に引きずられます）。
4. **評価のセッション**では `ground_truth.evaluation` を true にします
   （`cd C:\PokerHandLogger; .\venv\Scripts\python.exe tools\set_config.py ground_truth.evaluation true`）。最初に保存するまで
   「記録を見る」「記録どおり」が使えません（サーバーも受け付けない）。画面を開き直すだけで効きます。
5. 照らし合わせのとき、記録が合っていれば **「✓ 記録どおり」**。要確認のハンドは、要確認の行を左の ✓ ですべて確かめる
   （ハンド全体が要確認なら「ハンド全体も確かめた」の ✓ も）と「記録どおり」にできます。
6. **保存のときの確かめ**: 降りた席のアクション（前の行でフォールドした席の行）や反映できない行（その先はストリートが付かない）が
   あれば、理由を出して「このまま保存しますか」と確かめます。直せるなら直してから保存します（このまま保存したハンドは評価では
   数えない）。ボードの枚数とストリートのずれ・手札が一番強い席が見せずに降りた・RFID が読んだ札が入れた札に無い、なども知らせます。
7. **評価から外す**: 入力が不完全・中断・ボタンが動いていない などのハンドは「評価から外す」に印を付け、理由をメモに書きます。
8. **メモ**（気づいたこと）は開発側が毎ハンド読みます。要望もここに書いて構いません。
9. 一覧の上に入力済みハンドの一致率（ハンド / アクション / ボード / 勝者）が出る。保存先は
   `logs/<セッション>.ground_truth.json`。集計はコマンドでもできる:
   `python tools/measure_capture_accuracy.py --session logs/<sid>.json --ground-truth logs/<sid>.ground_truth.json`。

真の履歴は「実際に起きた全アクション」（言われなかったチェック / フォールドも含む）を入れます。
入力者の名前は画面の「入力者」に入れておくと、その端末で覚えます。

### 台本のハンドと読み上げ集（正解が先に分かるテスト）

- **台本のハンド (声だけ)**（`start_script.cmd`）: 6 人の仮想の卓・30 ハンドの台本を声だけで読みます（RFID は使わない）。
  iPad で `http://<PC の IP>:8791/script` を開き、1 ハンドずつ出る行を読んで「ハンド N を始める」。勝った席は画面がロガーに送ります。
  正解は台本なので真のアクションの入力は要りません。
- **札の確認 (RFID)**（`start_cards.cmd`）: 席 4・5・6 で、配った順・ボタンの動かし忘れ・持ち上げて戻す・卓の中央へマック・
  フロップを 3 枚同時・ターンの置き直しの手順を「始める → やってみる → できた / ちがった」で確かめます。
- どちらも、真のアクション入力の画面（ポート 8791）が動いていなければ別の窓で一緒に起動します（その窓は開いたままに）。
- **読み上げ集**（`http://<PC の IP>:8791/corpus`, `tools/read_corpus.py`）: 画面に 1 つずつ出る句を、卓で配るときと同じ声で読み
  「次へ」。句ごとの音声を正解と一緒に `logs/corpus/` に残します（マイク 2 本まで同時）。録りながら本番と同じ聞き取りを裏で回すので、
  終わった画面の残りが 0 になってからハンドロガーを始めます。「ログをまとめる」が直近の読み上げ集も zip に入れます。

### 店舗 PC を触れないときの見直しページ

開発側が、開発データのハンドを入力画面と同じ形（左 = 記録・推定・発話の時系列、右 = 真のアクションの編集）にした 1 枚のページを
claude.ai に出すことがあります（`tools/review_page.py`）。発話には音声の番号が付き、音声は別にチャットで送られます。
ページで真のアクションを直して保存すると、開発側が入力画面と同じ検査をして読み戻します。

## ログを送る（レビュー用）

テストのあと、デスクトップの **「ログをまとめる (送付用)」**（`pack_logs.cmd`）をダブルクリックすると、直近 12 時間の
セッションのログがデスクトップの `pokerlogs_<日時>.zip` 1 つにまとまり、エクスプローラでその zip が選ばれた状態で
開きます。その 1 ファイルをチャットに添付してください。

- 入るもの: ハンドの記録（`<セッション>.json`）・センサーの入力（`.events.jsonl`）・聞き取った文（`.transcripts.jsonl`）・
  卓状態・真のアクション（`.ground_truth.json`）・発話の音声（`logs\audio\<セッション>\*.wav`、合計 25 MB まで）・
  直近の読み上げ集・そのセッションの時間帯の `pokerapp.log`・`config.json`（トークン類は伏せる）・`rfid_cards.json`。
- **「ログをまとめる (音声付き・送付用)」**（`pack_logs_audio.cmd` = `--audio`）は発話の音声を必ず全部入れます。1 つの zip が
  25 MB を超えるときは `pokerlogs_<日時>_1of3.zip`・`_2of3.zip`… に分けるので、**全部を添付**してください。
- 発話の音声は `config.json` の `audio.save_audio` が true のとき `logs\audio\<セッション ID>\` に保存されます
  （ファイル名は発話の始まりの時刻 = `.transcripts.jsonl` の `audio_file`）。
- オプション（PowerShell で `C:\PokerHandLogger\pack_logs.cmd --audio` のように付ける）: `--audio`（音声を必ず入れる）/
  `--no-audio` / `--hours 48`（直近 48 時間）/ `--session <ID>` / `--part-mb 25`（分ける大きさ、0 = 分けない）/
  `--text`（zip を添付できないとき: テキスト 1 ファイル、音声なし）。

## 設定 (`config.json`)

初回起動時に `config_default.json` から `config.json` が作られます。

> **使う席・プレイヤー名・スタック・SB/BB・1 ハンド目のボタン席・ログ保存先は起動時に対話入力**します（`config.json` では
> 設定しません）。「席」には人数（`6` = 1〜6 番）か、**札を置く席の番号**を空白区切りで入れます（`2 4 5 8` = その番号の席。
> 卓の空いている席を飛ばして座るとき）。席番号は RFID の席のリーダー（`seat N`）と同じ番号にします（手札が別の席にあれば、
> ハンドを始めて 5 秒後に「席の設定が違うかもしれません」と出ます）。途中の休み・参加は `name`、ブラインドは `blinds` で変えます。

`config.json` で設定できる主な項目:

| セクション | キー | 既定 | 説明 |
|---|---|---|---|
| `audio` | `enabled` | `true` | マイク入力を使うか（`false` = キーボードの読み上げ文だけ） |
| | `device_id` | `0` | 入力マイクの番号（システム既定が 0） |
| | `device_name` | `""` | マイクの名前（の一部）。優先順に「\|」で区切る（例 `Wireless Mic Rx\|DJI Mic Mini 2`）。どれも見つからなければマイクを開かない。空なら `device_id` |
| | `sample_rate` | `16000` | 録音サンプルレート |
| | `whisper_model` | `medium` | 認識モデル。`small` 等で軽量化可 |
| | `language` | `ja` | 認識言語 |
| | `min_speech_sec` | `0.15` | 認識に回す最短の有音秒数 |
| | `speech_rms` | `300` | 有音とみなす入力レベル（離れた席の会話まで拾うなら上げる） |
| | `vad_threshold` | `0.5` | 声か（Silero VAD）の閾値。声でない音は Whisper にかけない。`0` で使わない |
| | `beam_size` | `5` | Whisper のビーム幅（下げると速く、精度は少し下がる） |
| | `temperature_fallback` | `false` | 自信の低い書き起こしをやり直すか（雑音で数分遅れたので既定 off） |
| | `cpu_threads` | `0` | Whisper の CPU スレッド数（0 = faster-whisper の既定 4）。`python tools/audio_check.py bench` で測って決める |
| | `save_audio` | `false` | 認識に回した発話の音声を `logs/audio/<セッション>/` に保存（テスト中だけ） |
| | `second_ear.enabled` | `true` | 第 2 の耳（Whisper が読めなかった発話を聞き直す。モデル約 170 MB は更新で取得） |
| `rfid` | `enabled` | `false` | RFID を使うか（任意） |
| | `transport` | `http` | `http`（ESP32）/ `pcsc`（リーダー直結） |
| | `bind_host` | `127.0.0.1` | HTTP 受信アドレス。ESP32 から受ける場合は PC の LAN IP に変更（無認証のため信頼できるネットワークのみ） |
| | `bind_port` | `8787` | HTTP 受信ポート |
| | `card_master_file` | `./rfid_cards.json` | タグ→カード対応表 |
| | `commit_sec` | `2.0` | ボードの札を数えるまでに載り続ける秒数（`pcsc`。一瞬の通過を除く） |
| | `gap_sec` | `1.5` | この秒数までの読み落ちは載り続けているとみなす |
| | `release_sec` | `6.0` | 配り直しで差し替えるまで、前の札が見えない秒数。`null` で自動の差し替えを止める |
| | `redeal_window_sec` | `30.0` | ボードの 1 枚だけの差し直しとみなす時間（flop の札）。前の札が消えてからこの秒数以内に同じ場所へ置いた札。最後に配った turn / river は時間を問わない。`null` で止める |
| | `redeal_confirm_sec` | `3.0` | ボードの差し直しで、前の札が見えないことを確かめる秒数（短いほど早く反映、読み落ちとの区別は弱くなる） |
| | `flop_window_sec` | `10.0` | フロップの最初の札からこの秒数より後の札はターン以降（リーダーの位置で分からないとき）。`null` で従来どおり |
| | `auto_restart` | `true` | 使えないリーダーがあれば、卓に札が無い状態が 10 秒続いたら読み取り装置を自動で再起動（`false` = 知らせるだけ） |
| | `relay_port` | `8792` | RFID の中継（RDP の外の読み取り）のポート（PC の中だけ） |
| `recording` | `enabled` | `true` | 生イベントの記録（再生・評価・事後推定の入力。off にすると再生できない） |
| `engine` | `backend` | `pokerkit` | ルール準拠の再構築。問題時は `legacy` に戻せる |
| | `auto_new_hand` | `true` | 手札を配ったら新しいハンドを始める |
| | `auto_winner` | `true` | 勝者を自動で決める |
| | `rfid_folds` | `true` | フォールドを席の札の離脱で決める（席の在否が取れる `pcsc` のとき） |
| | `fold_absent_sec` | `3.0` | 札がこの秒数離れたままならフォールド |
| | `button_from_deal` | `true` | 手札を読んだ順からボタンの動かし忘れを見つけて直す |
| `session_layer` | `enabled` | `false` | 誰がどの席かを記録する（お客さん向けのハンド閲覧に必要） |
| `viewer_api` | `bind_host` / `bind_port` | `127.0.0.1` / `8788` | お客さん向け画面の待ち受け（`--host` / `--port` が優先） |
| `ground_truth` | `evaluation` | `false` | 評価のセッション（真のアクションの入力画面で、最初に保存するまで記録を見られない） |

`rfid.flop_window_sec` と `rfid.relay_port` は `config_default.json` に無い項目です（書かなければ上の既定。変えるときだけ足す）。
古い `config.json` に無い項目も、上の既定で動きます（`recording.enabled` だけは、項目が無い `config.json` では記録しません）。

1 項目だけ変えるときは `python tools/set_config.py <項目> <値>`（例 `session_layer.enabled true`）。
値を省くと今の値を表示します。

> `camera` セクションは**廃止予定（レガシー）**で使用しません。`session` セクションと `audio.initial_prompt` は
> 現在のコードでは参照されません（席/ブラインド等は起動時入力、Whisper プロンプトは内蔵語彙を使用）。

困ったときは [トラブルシューティング](troubleshooting.md) を参照してください。
