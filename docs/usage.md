# 使い方ガイド

## 起動モード

```bash
python main.py            # GUI（ハンドロガー画面）
python main.py --cli      # CLI（音声のみ・画面なし）
python main.py --players  # プレイヤー登録画面（別画面）
python main.py --ledger   # 会計（台帳）入力 + 注文確定画面（別画面）
python main.py --viewer-api  # お客さん向けのハンド閲覧（画面 + 読み取り専用 API, 要 [api] extra）
python main.py --viewer-api --host 0.0.0.0 --port 8788   # 店の Wi-Fi のスマホから開く（下の「お客さんがスマホで…」）
python main.py --export-phh logs/<セッションID>.json   # JSON → PHH 変換
```

GUI と `--cli` はどちらも**音声でハンドを記録**します。配信や省リソースなら `--cli` が手軽です。

---

## 読み上げの基本

1 つのアクションは **「席 + アクション + 金額」**の順で読み上げます（金額は不要なアクションもあります）。

```
シート3 ベット 500     ← 席3 が 500 ベット
シート1 コール         ← 席1 がコール（金額は言わなくてOK）
シート2 フォールド     ← 席2 がフォールド
```

- **席**: `シート3` / `seat 3`（全角数字も可）。
- **金額**: 半角数字（`500`）または漢数字（`五百` / `1万` 等）。
- 区切りは自然な間（ま）で構いません。1 アクションずつ読み上げてください。

### 席番号を言わない運用（店舗, ADR-0061）

席番号を言わない場合、**誰のアクションかは手番の順で決まります**。そのため:

- **全員のアクションを順番どおりに言います（フォールドも省略しない）**。1 つ抜けると、そのあとのアクションが
  1 人ずつずれて記録されます。
- 続けて言っても構いません。「フォールド、フォールド、コール」のように 1 息で言った複数のアクションは、
  言った順に分けて記録します。**チェックレイズは「レイズ 1200」とだけ言います**（「チェック、レイズ」と区切って
  書き起こされると、2 人のアクションと区別できないため）。
- 「チェック」のような短い言葉も拾います。拾えていないときは `python tools/audio_check.py listen` で
  「短い音 N 秒 — 認識に回さず」と出ていないかを見ます（出ていれば `audio.min_speech_sec` を下げる）。
- **勝者は `w <席>` で打ちます**（「ウィナー」だけでは席が分かりません）。
- 認識は発話より数秒遅れることがあり、忙しい場面ではその遅れがたまります（プレーの切れ目で追いつきます。
  発話は捨てません）。遅れている間に `n` / `w` などを打つと、**先に言われた発話の反映を待ってから**入ります
  （「聞き取った発話を先に反映しています… 残り N 件」）。前のハンドのアクションが次のハンドに入ることはありません。

### アクション語彙

| 読み上げ（日本語 / 英語） | 意味 |
|---|---|
| ベット / bet | ベット |
| コール / call | コール |
| レイズ / raise | レイズ（金額は **最終的な「〜まで」**の額） |
| チェック / check | チェック |
| フォールド / fold | フォールド |
| オールイン / all in | オールイン |
| ショーダウン / showdown | ショーダウンへ進む |
| **ハンド開始** / new hand | 新しいハンドを開始 |
| シートN ウィナー / wins | そのハンドの勝者を確定（**ハンドを書き出す**） |

## ハンド 1 回の流れ

```
ハンド開始                    ← 1) 新しいハンドを始める
シート3 レイズ 600            ← 2) アクションを順に読み上げる
シート1 コール
シート2 フォールド
（フロップ後…）
シート1 チェック
シート3 ベット 1000
シート1 コール
シート1 ウィナー              ← 3) 勝者を言うとハンドが確定・保存される
```

- **「ハンド開始」で始め、「ウィナー」で終える**のが基本リズムです。
- ストリート（プリフロップ→フロップ→…）は RFID でボードが入ると自動で進みます。RFID 無しの場合は
  アクションの流れから推定します。

### RFID の卓での扱い（入力は要りません）

- **フォールドした手札がボードのリーダーの上を通っても、ボードの札にはなりません。** そのハンドで席のリーダーが
  読んだ札は、卓モニタにその席の「マック」として出るだけです。
- **ボードの札は、置いてから約 2 秒載り続けると数えます。** 一瞬通過した札は数えません。配った時刻は
  最初に見えた時刻で記録します。
- **ミスディールの配り直しは、そのまま配れば反映されます。** 手札は、前の札が約 6 秒見えなくなり、新しい札が
  載り続けると差し替えます。札を持ち上げて見るだけでは差し替わりません。差し替えたハンドは要確認
  （`needs_review`）になります。すぐ直したいときは、ハンドロガーの `cs <席>` / `cb <位置>` も使えます。
- **ボードは 1 枚だけ差し直せます。** 間違えた札を取り、**同じ場所に**正しい札を置いてください（flop の 1 枚を
  差し直しても turn にはなりません。turn / river も同じ場所に置けば差し替わり、外してから時間が空いても
  大丈夫です）。反映は、前の札を取ってから約 3 秒後か、新しい札を置いてから約 2 秒後の遅いほうです。
  **前の札を先に取ってから**新しい札を置くのが確実です（先に置く場合は 2 秒以内に前の札を取る）。flop を全部外して
  配り直した場合も、そのまま配れば直ります。river まで配ったあとで turn などを差し直した場合も、新しい札は
  取った札の位置に入ります（前の札を取ってから 3〜6 秒ほどで反映。それまでは「差し直し確認中」）。
- **読みにくい位置の札は差し直しとみなしません。** 置いてから一度でも読めなくなった札（卓モニタで「外れた」が
  出たり消えたりした札・ログに「読み直しました」が出た札）は、載ったまま読めないだけのことがあるためです。
  その札を本当に差し直すと、新しい札は次の位置に入り、次の札（river）を置いた時点で詰め直されます。
- **読めなくなっていた札が戻ると、差し替えは取り消されます。** 札が読めない間に次の札（例: river）を置くと、
  いったん差し直しとして記録されることがありますが、前の札がまた読めれば元の並び（turn → river）に戻ります。
  札がリーダーにしっかり読める位置に置くのが一番確実です（下の「置く位置」）。
- **卓モニタは、外した札を「外れた N s」と薄く表示します。** 札を外したのに「外れた」が出ないときは、その札は
  まだどこかのリーダーに読まれています（手に持ったままリーダーに近い・ボードの上に置いた 等）。
- **置いた札が読めていれば、数える前から「確認中 N s」（差し直しなら「差し直し確認中」）と点線で出ます。**
  約 2 秒で普通の表示に変わります。置いたのに「確認中」にすら出ないときは、その札はどのリーダーにも読めて
  いません。リーダーの境目を避けて置き直すか、他の札に重ねずに置いてください。
- **回収した札とバーンカードは、ボードのリーダーから外れた位置に置いてください。** 席で読めていない札が
  ボードのリーダーの上に置かれたままだと、ボードの札として数えてしまいます。
- **置く位置**: ボードの札は、リーダーの境目を避けて**リーダーの真上**に置くと安定して読めます。ボードのリーダーが
  5 枚より少ないと境目に来る位置が出るので、1 枚ずつ置いて卓モニタに「確認中」がすぐ出て、そのまま置いておいても
  「外れた」が出ない位置を確かめ、フェルトに印を付けておくと確実です。どのリーダーが読んでも位置は配った順で
  決まるので（turn を真ん中と隣のどちらのリーダーで読んでもかまいません）、リーダーを動かした・台数を変えた
  ときは `config.json` の board の並び（左から右）を合わせるだけです。すでに札が載っているリーダーの上に置いた
  札は、見つかるまで最大 2 秒ほど遅れます（札の無いリーダーの上ならすぐ見つかります）。
  **ボードのリーダーが 3 台の卓（店舗の実卓）**: flop 3 枚を 1・2 台目のリーダーの上に置き、**flop と turn の間を
  少し空けて turn を 3 台目のリーダーの上に**置きます（ログの「左から 3 台目」。turn をリーダーの境目に置かない）。
  river は turn の隣、同じ 3 台目の上です。

### 言い間違い・言い忘れに強い設計

既定の `pokerkit` バックエンドは**ポーカーのルールを把握**しているので、多少のズレを自動で整えます。

- ベットに直面しているのに「チェック」と言った → **コールに補正**し、`needs_review` を付けます。
- コール額を言い間違えても → **正しいコール額**（場の状況から計算）を採用します。
- ディーラーが**フォールドを言い忘れて次の席に飛んだ** → 飛ばされた席の**フォールドを自動補完**します
  （言い表したい時は、行動した席を `シート5 …` のように明示すると確実です）。
- 自信が低い・矛盾するものは `needs_review`（要確認）として記録され、後から見直せます。

### 音声のテスト（何と聞こえたかを見る）

1. **マイクの確認**（最初に 1 回）: `python tools/audio_check.py list` → `level` → `listen`
   （[トラブルシューティング: マイク](troubleshooting.md#マイクが認識されない録音されない)）。`listen` は本番と同じ経路で
   聞き取り、「何と聞こえたか → どのアクションになったか」を出します。初回は音声認識モデル（約 1.5 GB）の
   ダウンロードもここで済みます。
2. **ハンドロガー**（`--cli`）: 聞き取った文を `[聞き取り] 「シート3 レイズ 600」→ raise 600 席3` と表示し、
   記録したアクションが続けて出ます。アクションとして読めなかった発話も「アクションとして読めず」と出ます。
3. **スマホ画面のテスト表示**: お客さん用の画面の URL に **`?test`** を付けて開く（例
   `http://192.168.1.136:8788/?test`）と、ハンドの各アクションの下に**聞き取った文**と、補正したときは
   **その内容と理由**（「ベットがあるのにチェック → コールにした」「声のないフォールド（あとで言われた席から補った）」
   など）が出ます。`?test` を付けない端末（お客さん）の表示は変わりません。
4. 後から原因を調べられるよう、テストの間は `python tools/set_config.py recording.enabled true` で生イベントの記録
   （`logs/<セッションID>.events.jsonl`）も残しておくと確実です。

## 出力

- ハンドごとに **`logs/<セッションID>.json`** に追記されます（上書きしません）。
  - 各ハンドに `actions`（アクション列）/ `players`（席・結果）/ `pots`（メイン/サイドポット）/
    `winner_seat` / `review_required` などを含みます。
- **PHH 変換**: `python main.py --export-phh logs/<セッションID>.json`
  （pokerkit 互換の Poker Hand History を書き出します）。
- `review_required: true` のハンドや `needs_review: true` のアクションは、**人の目で確認**することを
  おすすめします。

## お客さんがスマホでハンドを見る

お客さんが店の Wi-Fi で自分のスマホから、**自分が座ったセッション・ハンド・カード**を見られます
（ログイン不要。名前を選ぶだけ）。

### 準備（最初に 1 回）

ハンドロガーが「誰がどの席か」を記録するように、`config.json` の `session_layer.enabled` を `true` に
します（店舗 PC ではインストール先のフォルダで次の 1 行。メモ帳で直接書き換えるより安全です）。

```
cd C:\PokerHandLogger
.\venv\Scripts\python.exe tools\set_config.py session_layer.enabled true
```

### ハンドロガー（`--cli`）で席とお客さんを入れる

- 起動時の「席N プレイヤー名」に**お客さんの名前**を入れます。**名前を入れずに Enter** した席は
  `PlayerN` になり、どのお客さんにも結び付けません（空席・名前を出したくない人）。
- **同じ名前は同じお客さん**です（前回の来店と同じ名前なら、履歴がつながります）。表記がゆれると
  別の人になります（例: 「たろう」と「太郎」）。
- **席替え**: `name <席> <名前>`（例 `name 3 花子`）で**次のハンドから**その席の人を変えます。
  `name <席> -` で空席（誰にも結び付けない）にします。ハンドの途中で打っても、そのハンドは元の人のままです。
- `q` で終えると、そのセッションはお客さんの画面で「終了」になります。

### 画面を出す

- デスクトップの「**お客さん用 ハンド履歴 (スマホ)**」（`start_viewer.cmd`）を起動します。表示される
  この PC の IPv4 アドレスを使い、お客さんはスマホのブラウザで **`http://<PC の IPv4>:8788/`** を開きます
  （例 `http://192.168.1.136:8788/`）。QR コードにして卓に置くと便利です。
- 名前を選ぶ → セッション → ハンド一覧 → ハンドの詳細（ストリートごとのアクション・ボード・
  **記録した全員分のホールカード**・収支）。
- 画面を先に起動しておいて構いません。あとから始めたセッションやハンドは、画面の「↻ 再読込」で出ます
  （画面を起動し直す必要はありません）。
- **本人確認が無いので、誰でも他の人の名前を選べます。** 当面は全員分のカードを見せる運用です
  （セッションごとに公開範囲を決める機能は今後, ADR-0059）。**店の Wi-Fi の中だけ**で使ってください。
- 手元の PC で試すときは `python main.py --viewer-api`（`http://127.0.0.1:8788/`）。
  `--host` / `--port` は `config.json` の `viewer_api.bind_host` / `bind_port` より優先します。
- `--viewer-api` 単独は読み取り専用で、注文は受け付けません（503）。会計画面（`--ledger`,
  `viewer_api.enabled=true`）を使う日は、会計画面が同じ画面を出すので `start_viewer.cmd` は要りません
  （同じポート 8788 を使うため、両方は起動できません）。

画面は `mobile/`（Expo）の web 版で、ビルドを `api/static/player/` に同梱しています（店舗 PC に Node は
不要）。`mobile/` を変えたら `python scripts/build_player_web.py` で作り直してコミットします。

## ドリンク注文（任意）

注文受付を有効にするには、`config.json` で `viewer_api.enabled` を `true` にして
**`python main.py --ledger`**（会計画面）を起動します。会計画面が viewer API を同じプロセス内で
立ち上げ、プレイヤーはスマホのメニュー（`menu.json`、店側で編集）から注文を送れます。

注文は即座に台帳に記帳されません。スタッフが会計画面の「注文リクエスト」欄で**確定**すると、
単価（メニューから自動入力・上書き可）× 数量で台帳に order として記帳されます。誤った注文は
**却下**できます（台帳には何も書かれません）。注文を受け付けられるのは会計画面を開いている間だけです。

## 設定 (`config.json`)

初回起動時に `config_default.json` から `config.json` が作られます。

> **席数・プレイヤー名・スタック・SB/BB・ログ保存先は起動時に対話入力**します（`config.json` では設定しません）。

`config.json` で設定できる主な項目:

| セクション | キー | 既定 | 説明 |
|---|---|---|---|
| `audio` | `device_id` | `0` | 入力マイク（システム既定が 0） |
| | `sample_rate` | `16000` | 録音サンプルレート |
| | `whisper_model` | `medium` | 認識モデル。`small` 等で軽量化可 |
| | `language` | `ja` | 認識言語 |
| `rfid` | `enabled` | `false` | RFID を使うか（任意） |
| | `transport` | `http` | `http`（ESP32）/ `pcsc`（リーダー直結） |
| | `bind_host` | `127.0.0.1` | HTTP 受信アドレス。ESP32 から受ける場合は PC の LAN IP に変更（無認証のため信頼できるネットワークのみ） |
| | `bind_port` | `8787` | HTTP 受信ポート |
| | `card_master_file` | `./rfid_cards.json` | タグ→カード対応表 |
| | `commit_sec` | `2.0` | ボードの札を数えるまでに載り続ける秒数（`pcsc`。一瞬の通過を除く） |
| | `gap_sec` | `1.5` | この秒数までの読み落ちは載り続けているとみなす |
| | `release_sec` | `6.0` | 配り直しで差し替えるまで、前の札が見えない秒数。`null` で自動の差し替えを止める |
| | `redeal_window_sec` | `30.0` | ボードの 1 枚だけの差し直しとみなす時間（flop の札）。前の札が消えてからこの秒数以内に同じ場所へ置いた札。最後に配った turn / river は時間を問わない。`null` で止める |
| | `redeal_confirm_sec` | `3.0` | ボードの差し直しで、前の札が見えないことを確かめる秒数（短いほど早く反映、読み落ちとの区別は弱くなる） |
| `recording` | `enabled` | `false` | 生イベントの記録（再現・検証用、任意） |
| `engine` | `backend` | `pokerkit` | ルール準拠の再構築。問題時は `legacy` に戻せる |
| `session_layer` | `enabled` | `false` | 誰がどの席かを記録する（お客さん向けのハンド閲覧に必要） |
| `viewer_api` | `bind_host` / `bind_port` | `127.0.0.1` / `8788` | お客さん向け画面の待ち受け（`--host` / `--port` が優先） |

1 項目だけ変えるときは `python tools/set_config.py <項目> <値>`（例 `session_layer.enabled true`）。
値を省くと今の値を表示します。

> `camera` セクションは**廃止予定（レガシー）**で使用しません。`session` セクションと `audio.initial_prompt` は
> 現在のコードでは参照されません（席/ブラインド等は起動時入力、Whisper プロンプトは内蔵語彙を使用）。

困ったときは [トラブルシューティング](troubleshooting.md) を参照してください。
