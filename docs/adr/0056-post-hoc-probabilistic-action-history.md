# ADR-0056: アクション履歴は「事後・確率的」に推定する（ライブは暫定表示に降格）

## Status

Accepted（2026-09-22 に verify-v1 へマージ。P0a/P0b 実装済。P0a は ADR-0049 G3 の
「RFID 最近傍読みを actor 証拠に採用（active 席限定）」を supersede する — 配布直後は全席が
active なので G3 では防げない。G1/G4/T4 と G3 の監査 reason は共存）

## Date

2026-09-12

## Context

要件定義書 `sprc_v4.docx` は当初からアクション履歴の**確率的推定**を要求している（改訂履歴 v3.0
「アクター推定を**尤度ベースに全面改訂**」/ FR-26 席ごとの推定確率 / FR-27 集中度 / §5.4
`estimate_actor -> dict[int, float]` / FR-25・FR-35 RFID フォールド検知 / FR-30 ストリート遷移）。
オーナーも「**ベイズ推定を用いたアクション履歴推定は当初からの方針**」と確認している。

実装は ISSUE-0009（2026-06-03）で尤度を「golden fixtures が揃うまで」後回しにし、暫定の
**決定的ポリシー**（固定優先順位の actor 決定 / silent-fold 合成 cap=2 / ヒューリスティック
confidence）を採用した。fixtures は揃った（5 件, ADR-0011）が再評価は行われず、暫定が既定として
定着した（**ISSUE-0031**）。ADR-0009 自身が「golden fixtures が揃えば再評価」と書いている以上、
本 ADR は方針転換ではなく **予定されていた再評価**である。

Fable 5.1 による設計監査（2026-09-12）を実施し、指摘のうち中核 3 件を本リポジトリで**実測検証**した:

1. **ディーラーボタンが回っていない**（検証済: 6-handed で 3 ハンド連続、最初の actor は毎回 seat 3、
   ブラインドも毎回 seat 1/2）。仕様 FR-05b はハンドごとの回転を要求。turn-order prior は仕様でも
   実装でも**最重要の証拠**なのに、2 人超の卓では (n-1)/n のハンドで誤っている → **ISSUE-0032**。
2. **RFID の「カード検出（appear）」が actor 証拠として明示発話席より優先されている**
   （検証済: `_resolve_actor` が `_pop_nearest_rfid_seat` の結果を `event.seat` より先に採る）。
   ホールカード配布は数秒で 16 件の検出を生むため、**配っただけで誤 silent fold が起きる**。
   golden `out-of-turn-rfid` は「新ハンド 0.8 秒後に seat 1 のカードが出現 → seat 3 を fold 合成し
   seat 1 に call（confidence 0.888）」を**正解として固定**しており、配布時と区別できない
   → **ISSUE-0033**。オーナーが唯一リアルタイム精度を要求した fold を、この機構が壊している。
3. **早期確定が事後推定の入力を破壊している**: 音声は decode 完了時刻でスタンプされ音声自体は
   保存されず、ASR の代替候補・単語タイムスタンプは捨てられ、RFID の消失遷移は記録されず、
   生イベント sidecar は**既定 off**（2026-09-12 の実機セッションは sidecar を残していない）。

## Decision

### D1. 記録の正本は「事後推定」。ライブは暫定表示に降格する

- **ライブ経路**（`IntegrationThread`）は引き続きハンドログを書くが、その内容は **provisional**
  （暫定）と位置づける。スタッフの画面表示・進行補助がその役割。
- **正本**は、記録した観測列から**オフラインで推定**した `hand_estimate`。読み取り時のオーバーレイ順は
  **live ⊕ estimate ⊕ staff corrections**（人手の訂正が最上位, ADR-0036 の型を踏襲）。
- 元のハンドログは不変（append-only の原則を維持）。推定は別 sidecar に `estimator_version` /
  `params_hash` / `tier` 付きで書き、**再推定で上書きできる**。

### D2. 推定器は「pokerkit の合法手列に対する制約付きビーム探索」

- **状態** = (pokerkit state after prefix, 次の未消費発話 index, 席ごとの fold 区間)。
- **遷移** = ①発話を現 actor の合法手に対応付ける ②発話を spurious として読み飛ばす
  ③発話を消費せず**サイレントアクション**を置く（fold は高め / check・call は低め / bet・raise は
  「金額不明」ペナルティ付きで極小）。**`SILENT_FOLD_CAP=2` は廃止**し、席ごとの幾何減衰する
  サイレント事前確率に置き換える（4 席飛びが自動的に極小になる）。
- **合法性はハード制約**（pokerkit が拒否する系列は確率 0）。ADR-0033 の L 因子はゲートに戻る。
- **観測尤度**: キーワード事後確率（ASR の n-best / 単語信頼度）/ 金額整合 / 席・**ポジション名**
  言及（FR-26 の 4 行目。`position_map` 前提 = D5）/ サイレント事前確率 / spurious 事前確率 /
  **RFID プレゼンスの非対称な扱い**（D4）/ **デッキ整合**（同じカードが別席・ボードに出たら
  ホールカードではあり得ない）/ 終端制約（宣言されたウィナーはポット受給資格を持つ）。
- **決定的**（乱択を使わない）ので ADR-0011 の replay 決定性がそのまま保たれる。particle filter は
  この理由で採らない。CRF / 学習モデルはラベルが無いので採らない（D7 の計測後に再評価）。
- **出力** = MAP 系列 + N-best + 位置ごとの事後周辺確率。**2 tier**（ハンド確定直後の速報 /
  セッション後の完全版）を同一フォーマットで出す。

### D3. pokerkit は「ライブのルール権威」かつ「事後の制約オラクル」の両方

ADR-0012（live 既定 pokerkit）は維持する。やめるのは「**イベント時点で唯一の真実を書き切る**」役割だけ。

### D4. RFID プレゼンスは非対称な証拠として扱う（仕様 FR-10/25/35 を改訂）

実運用ではプレイヤーがカードを持ち上げる・手に持つため、**不在は fold を意味しない**。仕様の
「3 回連続ミスで fold イベント」（FR-10/§8.3）は閾値調整で解けない（「20 秒持っている」と
「folded」を分ける閾値は存在しない）。よって:

- **カードが戻った** → その区間の fold を**強く否定**する。
- **ハンド終了まで戻らなかった** → fold を**中程度に支持**する（**事後にしか判定できない** = 本 ADR の要）。
- **不在それ自体** → 弱い支持にとどめ、単独では fold を決めない。

fold の時刻は**区間**で報告する: `[前の宣言アクション終了, 次の宣言アクション開始] ∩ ストリート窓`。
その区間内に「最終離席」があればそれを点推定に、無ければ区間の中点 + `source: turn_order`。
ADR-0055 のスカラー `absent_since` は「合成時点で評価する」ため不十分であり、**プレゼンス遷移の
記録**に置き換える（ADR-0055 の意図は維持、機構は差し替え）。

### D5. 仕様の改訂と踏襲（`sprc_v5` として起こす）

| 仕様 | 決定 |
|------|------|
| **FR-05b（ボタン回転）** | **そのまま実装する**（未実装 = ISSUE-0032）。`button_seat` / `position_map` / `turn_order` を記録し、ポジション名言及を解釈可能にする |
| FR-26 / §5.4（席ごとの加算スコア） | **証拠チャネルは踏襲、スコア関数は系列推定に格上げ**。`0.90` / `0.05` / `+0.09` は廃止（0.05 は「間の席が黙って降りた確率の積」として自然に導出される） |
| FR-27（次点との差 0.3 で review） | **踏襲。ただし統計量を事後周辺確率の margin に定義し直す**（config 化して後で較正） |
| FR-28（actor 確定後にターンを進める） | ライブ表示では踏襲。**記録では廃止**（確定を遅らせるのが本 ADR） |
| FR-30（ストリート遷移は RFID 枚数優先） | **改訂**。pokerkit ではベッティング完了が遷移条件で、`advance_street` は no-op（現状すでに死んでいる）。ボード配布時刻は**時間制約**として推定に入れる |
| FR-10 / FR-25 / FR-35（RFID フォールド検知） | **改訂**（D4）。`active_seats` は「いまカードが載っている席」= 表示用の量であり、ゲーム状態の入力ではない |
| FR-15/16/17（確定型/確認型/宣言型） | **踏襲**（未実装）。「コールですか？」を call と読む現状の誤りを、spurious 事前確率で扱う |
| §7 ディーラー運用（席・ポジションを毎回言う） | **踏襲し、運用として徹底する**。最も安価で効果が大きい |

### D6. 記録（sidecar）を必須化し、観測を落とさない

- `recording.enabled` を **既定 on** にする。推定器は sidecar 無しでは動かない。
- 記録するのは**観測**であって解釈ではない: 音声そのもの（WAV + サンプルオフセット）、
  Whisper のセグメント / 単語タイムスタンプ / n-best / `no_speech_prob`、**RFID の appear/disappear
  遷移と poll サイクル境界**、セッションヘッダ（config / firmware 定数 / ボタン席 / 単調時計↔壁時計アンカー）、
  スタッフ操作、参考としてライブの解釈。
- **時計を統一する**（順序・オフセットは `time.monotonic`、壁時計はアンカー経由）。現状は 3 箇所で
  `time.time()` を別々の段階で押している。
- `reconstruction_event` は draft（`0.1`）なので additive に拡張できる。ISSUE-0010 の
  「decode 後を境界とする」判断は**撤回**する。

### D7. 数値を決める前に計測する（先に壊れるものを見つける）

推定器は**金額を発明できない**。ディーラーが call/check/bet を宣言しない頻度が高ければ、
確率的にしても `amount_unknown` が並ぶだけになる。よって **estimator v0 の前に**、実セッション 1 本で:

1. **無宣言アクションの割合**（種別ごと）— これが make-or-break。
2. **時刻のズレ**（発話開始 ↔ decode 完了 ↔ RFID 検出）のヒストグラム + クラップテスト。
3. **不在時間の分布**（ショーダウンまで残った席の不在時間 = 誤 fold の起きやすさ）と、
   席で見た UID がボードリーダーに出る頻度（マック札の混入）。

### D8. ヒューリスティック confidence を記録の正本から外す

`derive_confidence` / `REVIEW_THRESHOLD` / `SYNTH_FOLD_CONFIDENCE` は事後確率ではなく、FR-27 とも
合成できない。**ADR-0033 を Superseded** とし、較正ハーネス（`tools/calibrate_confidence.py` /
`tests/test_confidence_calibration.py`）は**事後確率のプロパティ**に向け直す（範囲・ASR 信頼度に
対する単調性・非合法は 0 を維持。P8「合成 fold は常に review」は、**裏付けのある**サイレント fold を
review 不要にできることと矛盾するので差し替える）。`confidence` フィールドは型・範囲を保ったまま
**「MAP アクションの事後確率」に意味を定義し直す**（consumer は「高いほど良い」としか扱っていない）。

## Consequences

### 良くなること

- 仕様（FR-26/27, §5.4）と実装が初めて一致する。ADR-0009 が予告した再評価を実行したことになる。
- **後から来る証拠**（次に誰が動いたか / 誰がショーダウンに残ったか / 誰のカードが戻らなかったか）を
  使える。サイレント fold の最強の証拠は事後にしか手に入らない。
- 曖昧さが **握りつぶされず数値で出る**。レビュー UI は「もう一つの読み」を提示できる。
- 再推定できる。モデルを改善したら過去のセッションを推定し直せる（元ログは不変）。

### 代償・リスク

- **音声を保存する**（約 115 MB/時, FLAC で半分）。保存期間・取り扱いの運用判断が要る。
- 記録が必須になる（sidecar off での運用は「推定なし」= ライブの暫定記録だけになる）。
- ライブ表示と正本が食い違い得る（「画面ではこう出ていた」の説明が要る）。`docs/usage.md` の
  「自動 fold 補完」の説明は書き直す。
- ラベル付き ground truth が無いと FR-27 の `0.3` もサイレント事前確率も詰められない。
  仕様 Phase 7（実卓テスト・閾値チューニング）で 1 セッション分のラベル付けを予算化する。
- 作業量が大きい（P0〜P8）。**P0 は既存データを壊し続けているので最優先**。

## Alternatives considered

1. **FR-26/§5.4 をそのまま実装する**（アクション単位の局所分布）— 却下。各アクションで確定するため
   FR-28 と同じ早期確定の問題が残り、サイレント fold の事後証拠を使えない。証拠チャネルだけ引き継ぐ。
2. **ライブのまま確率化する**（ストリーミング推定）— 却下。オーナー要件が「カードは事後で可・
   リアルタイムが要るのは fold の時刻とターン/リバーの配布時刻」なので、複雑さに見合わない。
   ライブは暫定表示で足りる。
3. **particle filter / 学習モデル** — 却下（D2 の理由: 決定性とラベル不在）。
4. **現状維持 + ヒューリスティックの改良** — 却下。ISSUE-0033 の誤 fold は優先順位の調整では消えず、
   捨てている情報（ASR 代替候補・プレゼンス遷移・音声）は改良では戻らない。
