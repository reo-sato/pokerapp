# ADR-0068: 卓の進行の決まり（オーナーの説明 2026-09-25〜10-07）— フォールドは札の離脱・コールとチェックは毎回言う・ショーダウンは役名で見せる

## Status

Accepted（2026-10-13 に記録。各決まりは下の日付に決まり、その日に実装済。ADR-0061 の「無言の連続」と ADR-0062 の
ショーダウンの決め方の一部を置き換える）

## Date

2026-10-13（決まりそのものは 2026-09-25〜2026-10-07）

## Context

店舗のテスト（2026-09-25〜10-08）のあいだ、文書は CHANGELOG と作業ログだけを更新する運用だった（CLAUDE.md §7b）。
その間にオーナーが卓の進行について説明し、そのまま engine（`integration/engine.py`）・読み取り（`audio/recognizer.py`）・
RFID（`rfid/reader_thread.py`）・推定器（`integration/estimator.py`）の規則になったものが多い。説明は作業ログに散らばって
いて、どれがいまも有効な決まりか、どの ADR の何を置き換えたかを 1 か所で読めなかった。

前提（ADR-0061 / ADR-0062）:

- ディーラーは席番号もポジション名もベット・レイズの語も言わない運用を目指している（「600」「2千点」と額だけ）。
- ハンドは手札を配ると始まり、勝者は全員フォールド・マック・手札から決める（ADR-0062）。
- 記録の正本は事後の推定（ADR-0056）に移す途中で、ライブの規則は暫定の表示と推定器の再生器を兼ねる。

本 ADR は、オーナーの説明でできた卓の進行の決まりを日付・言葉・コードの順に集める。新しく決めることは無い（記録）。

## Decision

各決まりを R1〜R11 とする。「オーナー」の引用は作業ログのまま。

### R1. フォールドは席の札の離脱で決める（2026-09-25, 2026-10-06 に補強）

- オーナー（09-25）:「フォールドはリーダーからのカード離脱を主にして、音声から読み取る必要はありません。したがって、
  次のアクション者にフォールドを割りあてる必要はありませんし、フォールドと聞こえたからと言ってハンドが残っているならば
  別な解釈を試す必要があります。」
- オーナー（10-06）:「例外的に無言でフォールドされることはあっても、札が保持されたまま口頭でフォールドされることは
  基本的にありません。」
- コード:
  - `engine.rfid_folds`（既定 true、席の在否が取れる PC/SC の RFID のとき）。席の札が `engine.fold_absent_sec`（3 秒）
    離れたまま戻らない / 卓の中央（ボードのリーダー）を通過 → その席のフォールド。札が戻れば、少なくともその時刻までは
    フォールドではない（入れたフォールドを取り消して組み直す）。
  - 手番でない席の札が離れた = その前の人のアクションが聞き取れなかったとみて、間の人をチェック / コールで補う（要確認）。
  - 音声の「フォールド」は次の手番の人に付けない。札が離れかけている席があればその席、手番の人の札が残っていれば保留し、
    次のアクション・次のストリートの札の前にその席のフォールドにする（`spoken_fold`, reconstruction_event 0.8, 09-27）。
  - 10-06: 「フォールド」と言われても手番の人の札が席に残ったまま次のストリートの札が置かれたら、その人は降ろさずチェック /
    コール（要確認, `HELD_FOLD_STAYED_SEC`）。札が残ったまま別の席の札が離れたら、その語は離れた席のこと
    （`FOLD_WORD_DEPARTURE_SEC`、判断は `spoken_fold_drop` = reconstruction_event 0.15 として記録し、再生も同じ）。
    「フォールド」の語と札の離脱は 1 対 1 に組む。
  - 札の離脱・戻り・確定は `events.jsonl` の rfid の `kind` / `observed_at`（reconstruction_event 0.5）。
  - ショーダウン（ベッティングが終わったあと）の離脱はマックにしない（札を前に出すため。オーナー「プレイされたハンドは
    絶対離れてない」）。見せずに降りた人はディーラーの「フォールド」で決める（R5）。

### R2. コール・チェックは毎回言う（2026-09-29。ADR-0061 に足した「無言の連続」を置き換える）

- オーナー:「今後の運用ではコール、チェックを省略しないことにするので、このルール（連続する席の同じアクションは
  2 回目以降を言わない, 2026-09-26）は有名無実あるいは削除推奨」。フォールドは言わなくてもよい（R1 の札の離脱）。
- コード（`integration/engine.py`）:
  - 言われなかったチェック / コールを補った行は**いつも要確認**（聞き取れなかった所）。直前と同じアクションなら要確認に
    しない `silent_repeat` を外した（「ヘッズアップ」・「N ウェイ」で裏付けたコールは要確認にしない = 従来どおり）。
  - 「チェック」「コール」のあとのベット / レイズは次の手番の人のもの。仮に置いて札の離脱で組み直す処理
    （`reinterpret` / `silent_run_ambiguous`）を外した。旧記録の `reinterpret` の信号は何もしない（enum には残す）。
  - 席・ポジションを言ったベットの間の席は、札が離れていればフォールド、残っていれば聞き取れなかったチェック / コール
    （`implied_before_spoken_seat`, 要確認）。

### R3. フロップの 1 枚が読めないとき: ターンの札をフロップに詰めない・勝者が決まらなければチップを動かさない（2026-09-29）

- オーナー（d0f055fb ハンド 5 のメモ）:「フロップのうち一枚が読めてない。フロップは必ず 3 枚出るので、同時に出てなかった
  場合に、ターンカードをフロップに充当してはいけない。フロップあるいは他のボードカードが不明でショーダウン勝者は分からない
  場合はチップ移動は無し」
- コード:
  - RFID（`rfid/reader_thread.py:_not_a_flop_card`, config `rfid.flop_window_sec` 既定 10 秒）: フロップの位置に空きがあっても、
    いちばん右側の board reader だけで読んだ札・フロップの最初の札から 10 秒より後に見え始めた札は 4 枚目以降にする。
    左側の reader で読んだ札はフロップ（遅れて読めた札）。左右の目安は `_FLOP_EDGE` = 0.6（契約 `rfid-usb-ccid.md` §4）。
  - ボードの記録は位置どおりで、読めなかった位置は `??`（例 `3c Kh ?? Kc 9s`, `hand` schema 1.6）。ストリートは枚数ではなく
    位置で決める。フロップは 2 枚読めれば始まったとみる。
  - ショーダウンで札が読めていない: 読めていない札のありうるすべてで勝者が同じならその勝者（要確認）。札しだいで勝者が
    変わるなら**チップを動かさない**（`winner_source="undetermined"`、`winner_seat` は null、各席が出した額を返して確定、
    要確認）。それまでに `w <席>` が打たれればその席。`tests/test_showdown_unknown_cards.py`。

### R4. ディーラーがボタンを動かし忘れたときの救済（2026-09-29）

- オーナー（9d1d8536 ハンド 4 のメモ）:「この回に限ってディーラーがボタンを動かすのを忘れた。ハンド読み込む時間が最速と
  最遅になっている連番の席を見つけて、そこがボタンになるように修正する」と「1 枚目と 2 枚目両方考慮すれば？」
- コード:
  - 手で: `button <席>` をハンドの途中で打つと**そのハンド**のボタンを直して記録を組み直す（要確認。iPad の control
    `set_button` も同じ）。ハンドの外なら従来どおり次のハンドのボタン（仕様 FR-05g）。
  - 自動（config `engine.button_from_deal`, 既定 true）: 手札を最初に読んだ時刻（1 枚目と 2 枚目）が、別の席をボタンとした
    配り方（ボタンの次の席から 1 枚ずつ 2 周）に 1 か所の食い違いもなく合い、いまのボタンとは 2 か所以上食い違うときだけ
    直す。読んだ順は `deal_order` の信号（reconstruction_event 0.11）として記録し、再生も同じ判断をする。
  - 真のアクションの入力画面でボタンを選べる（ADR-0043 追記）。`tests/test_button_rescue.py`。

### R5. ショーダウン: 役名 = 見せた・見せたあとの「フォールド」= 次の人のマック・8 秒で手札・ショーダウンは必ず宣言（2026-09-30, 2026-10-07）

- オーナー（09-30, 3 通）:
  1. 「ショーダウンすべきタイミングで、マックする者は素早くマックしてディーラーがフォールドを宣言するので、次のハンドまで
     判定を待つ必要はない」
  2. 「アウトオブポジションがハンドショウするのに対して、ディーラーは役名を宣言します。この宣言ののち、レアケースですが
     インポジションが勝っているハンドをマックすることもあり得るので、役名の宣言はハンドショウとして扱ってください」
  3. 「ハンドショウの際にはリーダーからハンドが外れるため、この宣言は必ず行わないと誰がフォールドしたかわからなくなる
     ので、運用でカバーして役名の宣言は必ず行うようにしたい」
- オーナー（10-07）:「ショウダウンの際には必ずショウダウンが発声されます。つまり、ショウダウンが宣言されなかった場合には
  フォールドでハンドが終了しています」
- コード（`integration/engine.py`）:
  - 役名（「ツーペア」「キングヒット」など店の言い方, 10-01）= 次に見せる人が見せた（`_showdown_show`。アウトオブ
    ポジションから順。手札で役名に合う席がまだ見せていない中に 1 つだけあればその席）。前は役名でハンドを終えていた
    （09-26）。
  - 見せたあとの「フォールド」= まだ見せていない次の人のマック。見せる前の「フォールド」はアウトオブポジションのマック
    （ADR-0062 のまま）。見せずにマックした人は手札が強くても負け（手札の方が強ければ要確認）。
  - 残った全員が見せたら手札で決める。役名もマックも無いまま `SHOWDOWN_MUCK_SEC` = 8 秒たったら、残った全員が見せたと
    して手札で決める（次の配布を待たない。その時刻までに話し始めた発話は聞き終えてから）。記録に `showdown_end`
    （reconstruction_event 0.12）を残し、再生も同じ時点で決める。
  - 役名は見せた席の手札の判定と突き合わせる（違えば要確認）。`showdown[].announced`（hand schema 1.7）。
  - ベットに降りた（札が離れた）あとの役名でそのフォールドを取り消すのは、離れた席が最初に見せる席のときか、役名が
    残っている人の手と合うときだけ（10-06。降りた手を見て言った役名で勝者が逆になっていた）。
  - 10-07 の決まり（ショーダウンは必ず宣言）は**推定器だけ**に入れた: 声（崩れた「ショーダウン」の音・役名を含む）が
    無ければショーダウンの記録を低く（`p_showdown_heard` = 0.76）、あれば全員降りて終わった記録を低く（0.03）。
    **ライブの規則は変えない**（声は 4 回に 1 回ほど聞き取れないので、声が無いことでライブの記録を変えると誤りが増える）。

### R6. チェックアラウンドはストリートが変わるときの言葉・「チェック、アンド」・N ウェイ（2026-10-06）

- オーナー:「チェックアラウンドはストリート遷移の際に発声します。この際に、前ストリートのチェックは省略されている可能性も
  あります。チェック、アンドは多分チェックアラウンドの聞き間違いです。」
- オーナー:「コールでストリート遷移が確定した直後に N ウェイを宣言することで、コール 3 レイなどの聞き間違いが生まれて
  いますね」
- コード:
  - いまのストリートでまだ誰も動いていず、その札が見えてから `CHECK_AROUND_STREET_CHANGE_SEC` = 3 秒より前に話し始めた
    チェックアラウンドは、閉じた前のストリートのこと（記録しない）。前のストリートを札で閉じたときに補ったチェックは
    その裏付けにして要確認を外す。前のストリートが閉じていなければ従来どおり残りの全員のチェック。
  - 読み取り: チェックのすぐあとの「アンド」「ハンド」はチェックアラウンド（「チェック、ハンド終了」は従来どおり）。
    チェックアラウンドが閉じたストリートの言い直しなら、その直前に続けて言ったチェックも言い直し（`before_check_around`,
    reconstruction_event 0.17）。
  - 数のすぐあとの「レイ」「レイズ」「ベイク」「ベン」などを残りの人数（N ウェイ）として読む（「3 ベット」「スリーカード」・
    席番号は従来どおり）。`tests/test_street_change_words.py`。

### R7. 口頭の訂正「失礼しました」（2026-10-06。同じ日に入れた「アクションリセット」を置き換える）

- オーナーの答え:「口頭の修正プロンプトを利用する」。最初に入れた「アクションリセット」（ハンドのアクションを最初から
  やり直す合図, `8cd9fbd`）のあとの説明:「ハンドのアクションを最初からやり直すことはありません。ハンドの進行を優先して、
  ストリートの最初からやり直すか、直前のアクションを訂正することになると思います。失礼しました。をトリガーとして、
  その後のアクションとの辻褄を含めてより自然な方を選び取ってください。」
- コード:
  - 合図 = 「失礼しました」「失礼いたしました」「大変失礼しました」（`audio/recognizer.py:_CORRECTION_CUE`。発話のどこに
    あってもよい）。会話の「失礼失礼」「失礼します」は合図にしない。
  - 解釈は 3 つ（`integration/engine.py:_handle_correction`）: 直前のアクションの訂正（`prev`）・ストリートの最初からの
    言い直し（`street`）・訂正なし（`none`）。解釈ごとにハンドを組み直し、合図のあとの記録の不自然さ + 解釈の重み
    （`CORRECTION_PRIOR` = 0 / 0.6 / 0.9）がいちばん小さいものを採る。続く発話ごとに選び直し、次のストリートの札・
    ハンドの終わりで決める。そのハンドは要確認。`tests/test_spoken_correction.py`。

### R8. 「これで終わりです」はディーラーが言わない = 聞き違い（2026-10-06）

- オーナー:「これで終わりです。と発声することはありません。常にほかの語の聞き間違いです」
- コード: 発話全体が「これで／ここで終わり(です|ます)」のときだけ印 `garbled_call`（reconstruction_event 0.16）。語の
  2 秒前〜1 秒後（`GARBLED_FOLD_BEFORE_SEC` / `_AFTER_SEC`）に札が離れた席があればその席のフォールドの語、なければベットに
  向き合った手番のコール（要確認）、どちらでもなければ記録しない。同じ扱いを語尾の「ド」が無い「フォール」（0.17）・
  「コールド」「コード」（10-06 夜）にも広げた。

### R9. 「Nヒット」は 2 ペアのこともある（2026-10-06）

- オーナー:「２ペアの場合、ボードにあるペアを無視して、ハンドとボードでペアを作った数字＋hitを宣言することがあります。」
- コード: 読み取りで N を `hit_rank`（reconstruction_event 0.16）に載せ、見せた席の特定と手札の判定との突き合わせで、手札の
  N とボードの N で組になっている席のワンペア・2 ペアを合うとみる（2 ペアでも役名の食い違いにしない）。

### R10. ディーラーは札の離脱を見てからフォールドを宣言する（2026-10-06）

- オーナー（報告に「札は語のあとに離れることが多い」と書いたことへ）:「フォールドに関して、ディーラーはほぼ全ての例で札の
  離脱を見てフォールドを宣言するため、札の離脱が遅れている場合、ラグが入っています」
- 確かめたこと: firmware は札が 3 周続けて読めなかったら離れたとする（`PRESENCE_HOLD_MISSES = 3`、11 台で 1 周 0.3〜0.35 秒）
  ので、記録上の離脱は実際より約 0.7〜1.1 秒遅れ、語とほぼ同時（中央値 +0.16 秒）になる。
- コード: ライブの規則はもうこの順で扱っている（語が先なら、あとで記録された離脱を待って組にし、フォールドの時刻を語の
  時刻にする = `_fold_time`、15 秒以内）ので変えない。推定器は「フォールド」の語から記録上の離脱までの分布を、実測に
  合わせて語のあと側へ広げた（`docs/worklog/2026-10-06-fable-fixes.md`）。説明の向きの訂正は `3662cf2`。

### R11. ストリートの札より前にそのストリートのアクションは無い（2026-10-07）

- オーナー:「当然ですが、ターンカードのディールや、ターンカード/チェックアラウンドの宣言に先立ってターンのアクションが
  宣言されることはありません。」
- コード（`integration/engine.py`, `tests/test_street_timeline.py`）:
  - ストリートの札を読んだら、その札の 3 秒（`BEFORE_CARD_FIX_MARGIN_SEC`）以上前に話した声のアクションがそのストリート
    以降に入っていないか見て組み直す。チェック・コールは閉じたラウンドの言い直しとして外し、確かなベット・レイズは前の
    ストリートを閉じた「チェック」を外して前のストリートの賭けにする（要確認）。どちらも前のラウンドを閉じたアクション
    から 6 秒（`LEFTOVER_AFTER_CLOSE_SEC`）のうちに話した語だけ（それより離れていれば札の読み取りが遅れた）。
  - 札より前（`FOLD_BEFORE_CARD_SEC` = 2 秒）に離れた札を次のストリートのアクションにしたら要確認（記録は変えない）。
  - 札の時刻を使うのはフロップの 3 枚が 8 秒以内（`FLOP_CARDS_SPREAD_SEC`）に読めたハンドだけ。
  - 推定器: 札より前のアクションは「札が遅れて読めた」ときだけありうるとして札 1 枚に 1 回の項（0.01）。札が読めなかった
    ターン・リバーはディーラーの「ターンです」「ラストカード」「リバーです」を境目にする。

## Alternatives Considered

- **音声の「フォールド」を次の手番の人に付ける（09-25 まで）** — 札が残った人を降ろして以降の手番がずれ、コールが降りた人に
  付いた（09-27 c2cd4a53）。R1 で不採用。
- **手番でない席の札の離脱を「手番前のフォールド」とみて順番を待つ（設計監査の案, 09-25）** — オーナーの答えは「前の人の
  聞き落とし」。待つと補うべきアクションが入らない。
- **「無言の連続」を残し、言わなかったチェック / コールを要確認にしない（09-26）** — 運用を「毎回言う」に変えたので、補った
  行は聞き取れなかった所。要確認で見つけられる方を採った（R2）。仮に置いたベットの組み直しも不要になり外した。
- **ショーダウンの判定を次の配布まで待つ（ADR-0062）/ 一定時間で判定しない** — マックは素早く「フォールド」と言われるので
  待つ必要が無い（オーナー）。8 秒で手札に進む（R5）。役名でハンドを終える 09-26 の形は、役名のあとにインポジションが
  勝っている手をマックすることがあるので不採用。
- **「ショーダウン」の声が無ければライブでもフォールドで終える** — 声は 4 回に 1 回ほど聞き取れない。ライブは変えず、推定器の
  証拠にとどめた（R5）。
- **ターンの札をフロップの空きに詰める（従来）** — フロップは 3 枚同時。詰めるとリバーで前に出した札をフォールドにする
  （R3）。読めない札を仮の札で埋めて勝者を決めるのも、チップを誤って動かすので不採用。
- **「アクションリセット」= ハンドのアクションを最初からやり直す合図（10-06 に一度実装）** — オーナー「最初からやり直す
  ことはありません」。直前 / ストリート / なしの 3 つから辻褄で選ぶ形に置き換えた（R7）。CLI のコマンドで言い直す案も、
  オーナーは声の合図を選んだ。
- **ラウンドを閉じた発話の余りのアクションを一般の規則で捨てる** — 店舗のログで数えると、チェックアラウンドの言い直し以外は
  1 回だけだった。チェックアラウンドに限った規則にした（R6）。

## Consequences

- Positive:
  - 席番号もベット・レイズの語も言わない運用で、フォールド・ショーダウン・ストリートの区切りが札と短い宣言で決まる。
  - 補った行・決まらない勝者・聞き違いの読み替えに要確認が付き、真のアクションの入力と推定器が拾える。
  - 店舗のログの誤りの型（早く終わったハンド・1 席ずれ・勝者の逆転）の多くがこれらの決まりで直った（ISSUE-0039）。
- Negative / trade-offs:
  - **運用への依存が増えた**: コール・チェックを毎回言う、ショーダウンでは役名を必ず言う・「ショウダウン」と言う、
    訂正は「失礼しました」。言わなければ要確認が増える・推定器の誤りになる。
  - 決まりの多くは店舗のディーラー 1 人（オーナー: 「ずっと同じ人」）の言い方から決めた。別のディーラーでは確かめていない。
  - 時間の閾値（3 秒・8 秒・6 秒・10 秒）は店舗の数十〜百ハンドの実測から置いた値で、較正していない。
  - ライブの規則と推定器で扱いが違う決まりがある（R5 の 10-07 は推定器だけ）。
- Neutral / new constraints:
  - 規則を足すときは `docs/estimator.md` の「ライブの規則と推定器の関係」（規則を足すときの 3 点）に従う。
  - 記録の形の変化はすべて additive（hand 1.6 / 1.7、reconstruction_event 0.5〜0.17）。旧記録は読める。
