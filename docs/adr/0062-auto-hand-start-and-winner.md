# ADR-0062: 手札が配られたらハンドを始め、勝者はフォールド・マック・手札から決める（ショーダウンのマックを優先）

## Status

Accepted（2026-09-25, 実装済。店舗での確認は未）

## Date

2026-09-25

## Context

店舗 PC で、音声（ワイヤレスマイク）と RFID をつないでハンドを回した（ISSUE-0038）。
**ハンドが一度も始まらなかった**。ディーラーは `n` も「ハンド開始」も言わない運用のため、聞き取ったアクションが
すべて「進行中のハンドが無い」（`no_active_hand`）で保留された。
勝者も、席番号を言わない運用では「ウィナー」だけでは決まらない。

そのほかにも分かったこと:

- 金額を仮名で書き起こした（「ベトナナ」= ベット 7）。
- 「レイズ、コール」の「コール」を「ゴール」と書き起こした。
- ハンドの終わりに「ハンド終了」と言っていた。

オーナーの決定（同日）:

- ハンドの始まり = **手札が配られたら自動**。前のハンドが終わったあと、最初の手札が RFID に置かれたら
  新しいハンドを始める。ボードは配る前に片付ける。
- ショーダウンの勝者 = **手札とボードから自動判定**。
- 金額 = **言った数字どおり**（「ナナ」= 7）。
- ショーダウンのマック: **ベッティングが終わった直後の「フォールド」は、一番アウトオブポジションから順に
  フォールドさせ、残った人を勝者にする**。
  - 実際には勝っている手を、アウトオブポジションが見せずにマックすることがある。
  - その場合に手札で判定すると、勝者を誤って記録してしまう。これは避けなければならない。

## Decision

### D1. 手札が 2 席以上に配られたら新しいハンドを始める（`engine.auto_new_hand`, 既定 true）

- ハンドが無いとき（前のハンドは確定済み / まだ始めていない）に卓の席の札を読んだら、次のハンドの札として
  集める。**15 秒の間に 2 席以上**そろったら配布と判断する（`DEAL_WINDOW_SEC`）。片付けの途中で 1 枚だけ別の
  席に触れた札は、窓を過ぎると捨てる。卓で使っていない席のリーダーは数えない。
- 始めるハンドの開始時刻は最初の札の時刻。集めた札はそのハンドの手札に入れる（RFID は `on_new_hand` で
  リセットされ、載っている札を読み直す）。
- **前のハンドがプレー中のまま**（アクション・ボードがある / ベッティングが終わった）次の札が来たとき:
  - 次の札とみなす札: 手札 2 枚がそろった席に来た別の札 / `replaces` 付きの札 / 別の席かボードにあった札。
  - 2 席以上そろったら、前のハンドを確定してから始める（D2 のルールで決まらなければ仮の勝者 = `estimated`, 要確認）。
  - 手札がそろっていない席に来た新しい札は、読み遅れた手札としていまのハンドに入れる。
- **まだ何も起きていないハンド**に来た札は、同じハンドの配り直し（ADR-0058）として扱う。
  ミスディールでボタンを進めないため。
- **配る前に話された発話を先に反映する**。認識は 1 発話 3 秒ほど遅れる（ADR-0061）。
  - 配布を検出しても、`speech_backlog()`（`AudioThread.backlog`）が 0 になるまで始めない（最大 60 秒）。
  - 話し始めが配布より後の発話が届いたら、そこで始める。
  - これで前のハンドの最後のコールやマックが、前のハンドに入る。
- 配った時点で始めたハンドに、アクション前の「ハンド開始」/ `n` / staff の new_hand が届いたら無視する。
  二重に始めるとボタンが 2 つ進むため。お知らせだけ出す。
- 配る前に「ハンド開始」で始めていたら、配った札はそのハンドの手札にする（従来の運用もそのまま使える）。

### D2. 勝者を自動で決める（`engine.auto_winner`, 既定 true, pokerkit backend のみ）

- **ほかが全員フォールドしたら**、残った人の勝ちで即確定する（`winner_source="fold"`）。
- **2 人以上残ってベッティングが終わったら（ショーダウン）、その時点では決めない**。見せずにマックした人は、
  手札が強くてもポットを失うため。
  - **「フォールド」= マック**。席が言われなければ、残っている中で**一番アウトオブポジション**
    （ボタンの次の席から。heads-up はボタンでない方）の人がマックしたとみなす。
    - 記録: `action=fold` / `street="showdown"` / `reason=showdown_muck`。
    - 1 人になったらその人の勝ち（`winner_source="fold"`）。
    - 手札で見るとマックした側の方が強かったとき（オーナーの挙げたケース）も、勝者はマックしなかった人のまま。
      念のため `mucked_stronger_hand` で要確認にする。これはディーラーが「後から見せずに降りたインポジション」に
      「フォールド」と言ってしまった場合にも気づくためでもある。
    - 3 人以上が残っているときに順番で決めた場合は `muck_order_assumed`（要確認）。順番どおりにマック
      したとは限らないため。
    - 席番号・ポジション名が言われたらその席。
  - **誰もマックしなかったとき**だけ、RFID の手札とボード 5 枚で判定する（`winner_source="cards"`）。
    - 判定するのは「ハンド終了」・席の無い「ウィナー」・`n`・次のハンドの配布のとき。
    - pot ごとに、その pot の対象の席のうち一番強い手へ配る（`end_hand_awards`）。
      - 短いスタックのオールインで side pot の勝者が別でも正しく配る。
      - 同じ強さは等分し、端数はボタンの次の席から 1 枚ずつ。
    - `showdown` に見せた各席の役を残す。2 人以上に配ったら `pot_awards`。
  - 手札かボードが読めていない（または同じ札が 2 か所）と判定しない。
    - 「ハンド終了」なら `w <席>` を案内する。
    - 席の無い「ウィナー」なら従来の推定（ADR-0047 B5）。
    - 次の配布なら仮の勝者（`estimated`, 要確認）。
- 自動で確定したハンドのあとに届いた `w` / 「ウィナー」:
  - 同じ席ならお知らせだけ。
  - 違う席なら保留レコード（`winner_after_hand_end`）+ 訂正画面の案内。記録は append-only なので書き換えない。
- 配った直後の（アクションの無い）ハンドに届いた `w` は、前のハンドへの宣言とみなし、新しいハンドを終わらせない。
- ベッティングが終わったあとの `check` / `call` などは、保留レコード（`betting_over`）にする。

### D3. 聞き取り

- 語彙: 「ゴール」= call、「ベト」= bet、「ハンド終了」= `end_hand`（制御語。ADR-0049 G1 の低信頼保留の対象）。
- **仮名の数**: アクションの語の直後にある仮名の数の読みを、漢数字にしてから読む。
  - 例: ナナ = 7、ロッピャク = 600、センゴヒャク = 1500、イチマンニセン = 12000。
  - 語の直後だけにするのは、「ゴール」の「ゴ」や「〜にします」の「に」を金額と取り違えないため。
  - 数の読みの直後がカタカナの別の語なら数としない（「です」「で」「枚」などは可）。
  - 数字が 2 つ並ぶ読み（ニサン）と、単位の無い促音形（イッ）も数としない。

### D4. 記録（additive）

- `hand` schema `1.4`: `winner_source`（fold / cards / estimated。宣言で決めたハンドでは出さない）+
  `showdown`（`[{seat, hole_cards, hand, best}]`）。`pot_awards` は手札で 2 人以上に配ったときにも入る。
- `action` schema `1.5`: action の enum に `end_hand`（保留レコードにだけ現れる）。
- engine: `rules_aware` / `acting_order()` / `current_pots()` / `end_hand_awards()`（legacy は最小実装）。
  判定は `core/showdown.py`（pokerkit の役判定を使う純粋関数）。
- CLI: お知らせ（ハンドの開始・勝者・ショーダウン・判定待ち）を `● …` で表示（`on_notice`）。

## Alternatives Considered

- **ベッティングが終わった瞬間に手札で判定する**: マックした人の手札が強いと勝者を誤る（オーナーの指摘）。不採用。
- **マックに関係なく手札を優先する**（最初の案）: 同上。見せずにマックした人はポットを失うのがルール。不採用。
- **「フォールド」を最もインポジションの人のマックにする / RFID で札が中央を通った席をマックとみなす**:
  - 前者はオーナーの運用と逆。
  - 後者は、勝った人の札も回収時に中央を通るので、誰が先に降りたか分からない。
  - 席が言われたときだけ席を採る。
- **一定時間マックが無ければ手札で判定する**: ディーラーの宣言が遅れると誤る。「ハンド終了」か次の配布で判定する。
- **席のリーダーがすべて空になったら次のハンドとみなす**: 札が残っているリーダーが 1 台あると始まらない。
  2 席への配布で判断する。
- **配布を検出したらすぐ始める（発話を待たない）**: 認識の遅れで前のハンドの最後のアクションが新しいハンドに入る。
  待つ（上限 60 秒）。
- **仮名の数を文全体で読む**: 「ゴール」「に」などを金額と取り違える。語の直後だけにする。

## Consequences

- Positive:
  - `n` も「ハンド開始」も言わずにハンドが回る。
  - 全員フォールドは即確定する。
  - ショーダウンは、マックを優先したうえで手札で決まる。side pot の勝者が別でもスタックが正しくなる。
  - 「ベトナナ」「ゴール」が読める。
- Negative / trade-offs:
  - ショーダウンのハンドは「ハンド終了」か次の配布まで確定しない（記録は遅れて出るが内容は同じ）。
  - 席番号を言わない限り、マックはアウトオブポジションから順とみなす。
    - アウトオブポジションが見せたあとにインポジションがマックしたときに「フォールド」と言うと、勝者が逆になる
      （手札で見て不自然なら要確認）。
    - このときディーラーは「フォールド」と言わない（手札で判定される）。
  - 手札が読めていない席に、次のハンドの最初の札が来ると、その札を前のハンドの手札として拾うことがある
    （読み遅れと区別できない）。
  - 片付けの途中で 2 席の札が 15 秒以内に読めると、早めに次のハンドが始まる。
- Neutral:
  - replay（`integration/replay.py`）は既定で自動を使わない（既存の golden は不変）。
    店舗のセッションは setup.json の `auto_new_hand` / `auto_winner` で再生する。
    replay は発話の認識待ちを持たない（配布の検出ですぐ始める）。
