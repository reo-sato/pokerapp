# ADR-0051: ハンドリプレイ UI — 1 画面のテーブル図 + 4 ストリート列

- **Status**: Accepted
- **Date**: 2026-09-11
- **Related**: ADR-0044（共有コンポーネント方式 / staff hands read。本 ADR が **D3 のみ supersede**）/
  ADR-0036（ハンド訂正オーバーレイ）/ ADR-0017（viewer API / mobile）/ ADR-0037（staff iPad app）

## Context

ADR-0044 D3 のリプレイ表示は「参加者 → ストリートごとのカード → 結果」を**縦に積む**形で、
1 ハンド見るのにスマホで数画面ぶんスクロールする。GGPoker のハンドログのように
**一目でハンド全体（誰が何を持ち、どこでいくら入れ、どう終わったか）が分かる**体験になっていない。

要望: **スマホ縦 1 画面・スクロールなし**で、上半分にテーブル、下半分に 4 ストリートを列で。

## Decision

### D1: 画面を上下に二分する固定レイアウト

- **上半分 = テーブル図**: 席をテーブル外周にリング配置し、中央にボード・ポット・勝者・ブラインド。
- **下半分 = 4 列**: プリフロップ / フロップ / ターン / リバーを**常に 4 列**描く
  （アクションが無いストリートも列は残し `—` を出す）。列見出しにはその街で**新しく開いた**
  ボード（flop 3 枚 / turn 1 枚 / river 1 枚）と街終了時ポットを出す。
- `HandReplay` は ScrollView を持たず `flex: 1` で親の高さを埋める。**高さは埋め込み側が与える**。

### D2: テーブル図は「最終状態で固定」

列タップでのストリート連動・自動再生は**持たない**。理由: 1 画面で全体を俯瞰するのが目的であり、
状態を持つと「今どの街を見ているか」を覚える必要が生まれて俯瞰性が落ちる。時系列は下の 4 列が
すでに左から右に表している。連動・再生は要望が出てから additive に足せる（ADR-0044 D3 で
ステップ再生を scope 外にした判断を踏襲）。

### D3: 席はボタン位置ではなく**席番号順**のリング配置

`seatRingLayout(count)`（`handReplayModel.ts` の純関数）が席の中心位置を % で返す。先頭の席を
**下中央**（見ている人の手前）に置き、そこから時計回り。**BTN / ポジション情報はデータに存在せず、
推定は ADR-0044 D3 で scope 外**と決めているため、並びは席番号順であってポジション順ではない
（ポジション表記も出さない = 推定由来の silent failure を UI に持ち込まない）。

### D4: 狭い列では**ポーカーの原語表記**を使う

列幅は 400px 画面で約 88px しかなく、日本語ラベル（「オールイン」等）と金額を並べると見切れる。
列の中だけ `compactActionLabel`（Fold / Check / Call / Bet / Raise / All-in）と
`formatChipsCompact`（600 / 1.5k / 12.2k / 120k）を使う。卓上で通じる語彙そのままで幅は半分以下。
**日本語ラベル（`actionLabel`）は共有テキスト書き出し（`handReplayText.ts`）で従来どおり**。

### D5: 状態は「幅を食わない形」で示す

要確認 / 訂正済は文字バッジ（「要確認」「訂正済」= 6 文字ぶんの幅）をやめ、
**行左の 2px 色ストライプ + 1 文字記号**（`!` / `✎`）にする。色は既存パレットの warn / accent。

### D6: 溢れは「列の中だけ」スクロールする

1 列あたり 20 行以上入る設計だが、多人数 × 多アクションの極端なハンドでも欠落させないため、
列本体を ScrollView にする。**画面自体はスクロールしない**という要件は保ったまま、
データを隠さない安全弁になる。

## Consequences

- 1 ハンドがスマホ 1 画面で完結する（400×860 実測で 3 アーキタイプとも `scrollHeight == clientHeight`）。
- ADR-0044 の **D1（`shared/hand_replay/` 正本 + copy-sync + drift test）/ D2（依存は RN primitive のみ）/
  staff hands read API は不変**。supersede するのは D3 の**表示形式**だけ。
- 埋め込み側が高さを与える契約になったため、`mobile/src/screens/HandDetailScreen.tsx` は
  ScrollView を外し（ヘッダ 1 行 + リプレイ flex:1 + フッタの小ボタン）、
  `staff/src/screens/HandTab.tsx` は drill-in で固定高（560）を与える
  （訂正パネルはその下にスクロールで到達 = staff 専用ツールなので従来どおり）。
- 縦スクロールで全アクションをテキストで追う手段は UI から無くなる。代替は
  **「📤 共有 / コピー」のテキスト書き出し**（`handReplayText.ts`、変更なし）と staff 訂正パネルの
  全アクション一覧。
- staff E2E は旧 UI の文言（「結果」「訂正済」「ベット」）を見ていたため新 UI に追随させた。

## やらないこと

- BTN / ポジション推定（ADR-0044 D3 の判断を維持）
- ストリート連動・自動再生・アニメーション（D2。要望が出たら additive）
- `handReplayText.ts` / 訂正パネル / staff hands read API の変更

## 追記（2026-09-11）: 強調・省略の表示規則（D7）

実際に 1 画面表示を見たうえで、俯瞰性を上げるために以下を追加した。いずれも**描画のみ**の規則で、
データ・ポット計算・テキスト書き出しには影響しない。

- **プリフロップで fold した席は減光する**（`preflopFoldedSeats` / opacity 0.4）。そのハンドに
  実質関与していない席を沈め、攻防に残った席に目が行くようにする。**ポストフロップの fold は
  減光しない**（フロップまで参加した席はハンドの一部）。
- **本人の席は琥珀の地 + 金の縁**（`selfSeat` prop。mobile が `findOwnRow` で解決して渡す。
  staff は「本人」が存在しないため未指定 = 強調なし）。彩度の高い黄色はホールカードと文字の
  コントラストを落とすため、ダーク基調になじむ暗い琥珀を使う。**勝者かつ本人**のときは地は琥珀の
  まま縁だけ勝者の緑を優先する（🏆 と緑の名前で勝者は読める）。
- **本人のアクション行**も 4 列側で薄い琥珀の地にする。ストリートを追うときに自分の手番が即座に
  見つかる。要確認 / 訂正済の左ストライプとは別チャンネルなので競合しない。
- **プリフロップ列では fold 行を出さない**（`visibleColumnActions`）。大半の席が降りるプリフロップで
  実質的な攻防が埋もれるため。降りた席はテーブル図側の減光で示すので情報は失われない。
  **フィルタは描画専用**で、`buildReplayModel` のポット境界（potStart/potEnd）も
  `handReplayText.ts` のテキスト書き出しも**全アクションを見たまま**（数値・書き出しは不変）。

## 追記（2026-09-11）: アクション行の「誰が」と種別色（D8）

4 列のアクション行は席番号しか出していなかったため、テーブル図と番号を突き合わせないと誰の
アクションか分からなかった。また種別が同色のテキストだったため、列を流し読みしたときに
「攻めた/降りた」の区別が付かなかった。次の 2 点を追加する（いずれも描画のみ）。

- **行を 2 段にしてプレーヤー名を出す**。列幅は約 88px しかなく、名前・アクション・金額を 1 行に
  並べると必ず省略が出る。1 段目 = `席番号 + 名前`（9px, muted）、2 段目 = `アクション名 + 金額`。
  旧 UI は列の下半分が空いていたため、段を増やしても 1 画面の制約は崩れない（400×860 で再実測、
  3 アーキタイプとも `scrollHeight == clientHeight`）。名前は `action.player_name` を優先し、
  無ければ席→参加者名（`model.seats`）、それも無ければ `席N` に落とす（古い記録でも欠落しない）。
- **アクション種別ごとに色を与える**（`ACTION_COLORS` / `actionColor`）。色相は
  **アグレッション順**に並べ、色を覚えなくても強弱が読めるようにする:
  fold = 灰 `#6b7680` → check = 鋼 `#8ba3b8` → call = 青 `#5ab0f0` → bet = 緑 `#7fd48a` →
  raise = 橙 `#ffa35c` → all-in = 赤 `#ff5f6d`（`blind` は灰、未知の種別は通常テキスト色）。
  色が種別を担うようになったので、**金額は青（accent）から通常テキスト色に戻す**
  （2 色が競合して種別色が読みにくくなるため）。
- 本人行は地の琥珀（D7）に加えて **1 段目の名前も金色**にする。列の中で自分の手番を最短で
  見つけられる。

色は補助チャンネルであり、**テキスト（Fold/Check/Call/Bet/Raise/All-in）は常に併記**する
（色覚特性に依存しない）。`handReplayText.ts` の書き出しは日本語ラベルのまま変更しない。
