# ADR-0054: ミスディールの載せ替えは「明示コマンド」で訂正する（absence から推測しない）

## Status

Accepted（2026-09-24 **部分的に ADR-0058 が置き換え**: 実卓ではディーラーに入力を求められないため、配り直しは「前の札が消え、新しい札が載り続けた」ときに自動で反映する。消えたことだけを根拠にしない点は本 ADR と同じ。明示の `cb` / `cs` はそのまま残る）

## Date

2026-09-12

## Context

実運用の質問から出た要件: **ゲームの性質上、一度読み込ませたカードを外して、新しいカードを
正のハンド / ボードとして読み込ませることがある**（ミスディール、カード露出、誤配）。

現状（ADR-0053 / ISSUE-0026 時点）はこれに対応できない:

| ケース | 現状の挙動 |
|--------|-----------|
| ボードの誤った 1 枚を外して置き直す | 誤った札が位置を持ち続け（**ハンド内 append-only**）、置き直した札は**次の空き位置**を取る。ボードに 1 枚余分が残り、**枚数でストリートが誤って進む** |
| 席のホールカードを差し替える | `_hole_cards[seat]` は **2 枚で打ち止め**なので、差し替えた札は**黙って無視**される |
| ハンド全体のやり直し | `n`（新ハンド）で全部リセットされる = **対応済**（進行中のハンドは JSON に書かれず捨てられる） |

つまり「**ハンドごと配り直す**ミスディール」は既に扱えるが、「**1 枚だけ差し替える**」（ボードの
露出カードの張り替え等、ルール上ハンドは続行する）が扱えない。

### なぜ append-only にしたのか（= 素朴な修正がだめな理由）

ISSUE-0026 で **「カードが見えなくなったら位置を解放する」を明確に捨てた**。理由は
**absence が信用できない**こと:

- 隣接リーダーの磁界が重なると 1 枚を 2 台が読み、デバウンスが台ごとに落ちる（ISSUE-0025）。
- 結合の弱い台では**載っているのに一瞬読めない**ことが実機で頻発する（2026-09-12 の通しで
  `Tc` が同じ位置で 10 回以上再検出された）。

解放すると、この一瞬の読み落ちが「載せ替え」と解釈され、空いたスロットを別の札が奪い、
**同じ札が 2 か所に出る / 枚数が水増しされてストリートが誤って進む**。実機で観測済みの壊れ方
なので、absence からの推測には戻さない。

## Decision

**ミスディールは「ディーラーが宣言する明示イベント」として扱い、明示コマンドでのみ訂正する。**
absence からの自動判定は **行わない**（推測しない）。

### 1. 訂正の粒度は 2 つ

- **`correct_board <位置>`** — ボードの N 枚目の記録を取り消す。engine は `_board_positions[N]` を
  削除し、RFID は `forget_board_position(N)` でその位置の割り当てを解放する。
  **他の位置は動かさない**ので、真ん中の 1 枚だけ差し替えてもボードの順序が壊れない。
- **`correct_seat <席>`** — その席のホールカード記録を捨て、載っている札を読み直す。
  engine は `_hole_cards[seat]` を削除し、RFID は `forget_seat_cards(seat)` でその席のリーダーの
  デバウンスを落とす（2 枚上限にも引っかからなくなる）。

ハンド全体のやり直しは従来どおり **`n`（新ハンド）**。訂正コマンドは追加しない。

### 2. 解放と同時にデバウンスを落とす（= 冪等で自己修復的）

訂正は「**いまここに記録されているものを捨てて、物理的に載っているものを読み直す**」と定義する。
board reader のデバウンスもまとめて落とすので:

- 位置を持っている札 → 再発火して **同じ位置に戻る**（`_board_indexes` に残っているため）。
- 空いた位置 → 次に現れた**新しい札**が取る。
- 取り消した札を**まだ外していない**場合 → 同じ札が同じ位置に戻るだけ。外してから打ち直せばよい。

つまり **隠れた状態を持たず、再実行でやり直せる**。「取り消した札をハンド内で禁止する」
ブロックリストも検討したが、不可視の状態が増えて「なぜ読まれないのか」が分からなくなるため採らない。

### 3. 訂正したハンドは `needs_review`

訂正が入ったハンドには監査痕として `needs_review` を立てる（人間がログを確認できるように）。
訂正そのものは正常な運用だが、**記録を後から書き換えた**という事実は残す（ADR-0036 のハンド訂正
オーバーレイと同じ思想）。

### 4. ストリートは戻さない

カードを 1 枚差し替えても「フロップはフロップ」でルール上の進行は変わらない。枚数が戻れば
枚数ベースの自動遷移は no-op になる（`_try_advance_street_from_rfid` は現ストリートなら何もしない）。
pokerkit backend ではそもそもストリートはベッティングが権威（ADR-0009）。

### 5. 操作面は staff の明示操作のみ（音声語彙は足さない）

- **CLI**: `cb <位置>` / `cs <席>`（`--cli` のコマンド。`q`/`n`/`w`/`r` と同じ列）。
- **staff API / iPad**: control queue の `correct_board`（`index`）/ `correct_seat`（`seat`）
  （ADR-0039 の経路にコマンド種別を additive 追加）。
- **音声語彙（`ACTION_KEYWORDS`）には追加しない**。「訂正」は卓上の会話に現れうる一般語で、
  誤爆すると**正しい記録を消す**方向に働く。注文確定を staff-in-the-loop にした ADR-0018 と同じ判断。
  必要になったら別 ADR で追加する。

### 6. 状態変更経路は増やさない

訂正も他の操作と同じく **`AudioEvent` として queue に積み、IntegrationThread が適用**する
（ISSUE-0012）。RFID 側の解放は engine から `on_card_correction` フックで呼ぶ（`on_new_hand` と
同じパターン）。フックが無い構成（RFID 無し / テスト）では engine 内の記録取り消しだけが起きる。

## Consequences

### 良くなること

- ミスディールの 1 枚差し替えが**記録を壊さずに**行える（ボードの順序も保たれる）。
- ホールカードの差し替えが**黙って無視されない**。
- absence からの推測を入れないので、ISSUE-0025/0026 の壊れ方は**再発しない**（append-only は維持。
  例外は明示コマンドのときだけ）。
- iPad（staff アプリ）からも同じ操作ができる（control queue は既存経路）。

### 代償・残る制約

- **スタッフの明示操作が要る**。ディーラーが黙って差し替えるとログは直らない（設計上の選択）。
- 訂正の**取り消し**（undo）は無い。打ち間違えたら物理配置を直して打ち直す（冪等なので収束する）。
- 席の訂正は**その席の 2 枚を丸ごと読み直す**（1 枚だけの指定はできない）。席のカードは順不同で
  位置概念が無いため。実運用では 2 枚とも置き直せばよい。
- **音声からは操作できない**（上記 §5）。
- staff iPad アプリの UI ボタンは未実装（API は通っているので後続タスク）。

## Alternatives considered

1. **absence + タイムアウトで自動解放**（N 秒見えなければ載せ替えと判断）— 却下。実機の読み落ち
   間隔が実測で数秒あり、安全な閾値を引けない。誤判定は「同じ札が 2 か所」= ISSUE-0026 の再来。
2. **ボード全体を読み直す**（`correct_board` を位置なしにする）— 却下。再検出順は poll 順なので、
   同じ台に載った複数枚の順序が入れ替わりうる（契約 §4 の既知の制約）。位置指定なら順序が保たれる。
3. **取り消した UID をハンド内ブロックリストに入れる** — 却下。物理的に載っているのに読まれない
   不可視状態が生まれ、デバッグが難しくなる。冪等な再実行で足りる。
4. **音声「訂正」語彙を追加** — 却下（§5）。誤爆のコストが非対称（正しい記録を消す）。
