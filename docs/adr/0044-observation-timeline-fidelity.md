# ADR-0044: 観測の時刻精度 — fold の実時刻とボード配布時刻を記録する

## Status

Accepted

## Date

2026-09-12

## Context

アクション履歴は最終的に **音声録音の時系列と突き合わせて再生**される。オーナーの要件整理
（2026-09-12）:

- **カード内容（ホール / ボード）は事後に正しければよい**。リアルタイム精度は不要。
- **フロップ 3 枚の内部順序は無意味**。どの 3 枚かだけが重要。
- **実時刻が必要なのは 2 つだけ**:
  1. **fold の時刻** — 音声の時系列と組み合わせてアクション履歴を再生するため。
  2. **ターン / リバーの配布時刻** — ベッティングラウンドの区切りとしてアクションの時刻に対応するため。

現状はこの 2 つがどちらも取れていない。

| 要求 | 現状 |
|------|------|
| fold の実時刻 | ディーラーが宣言しない fold は **後続アクションが来て初めて合成**され（`fold_through`）、`timestamp` に **「次の人が行動した時刻」**が入る（`_append_synth_fold` が `_now_iso()`） |
| ターン / リバーの配布時刻 | **どこにも記録されない**。`HandSummary.board` はカード名の配列だけで、`RFIDEvent.timestamp` は解釈後に捨てられる（生イベント sidecar は既定 off） |

上位の設計課題（確率的推定への drift = ISSUE-0031）とは独立に、**どの推定器を採るとしても
観測の時刻は入力として必要**なので先に確保する。

## Decision

### 1. fold の時刻は「マック観測」で与える。ただし fold の**判定**には使わない

RFID スレッドが席ごとに「**カードが全部消えて戻っていない時刻**」（epoch）を保持する
（`RFIDThread.seat_cards_absent_since(seat)`）。engine は合成 silent-fold を記録するとき、
この時刻が取れていれば `ActionRecord.timestamp` に使う（`_synth_fold_timestamp`）。

**不在を fold の判定材料にはしない。** 実運用ではプレイヤーが**カードを持ち上げて見る・手に持つ**
（オーナー確認済み）ため、不在は fold を意味しない。fold かどうかの判定は従来どおり合法手 +
actor 推定が行い、**確定した fold の時刻だけ**を差し替える。判定と時刻を分けるのが本 ADR の要点。

安全弁:

- 時刻が **ハンド開始 〜 現在**の範囲外なら採用しない（前ハンドの回収などを弾く）。
- 新ハンドで観測を捨てる（`reset_for_new_hand`。ハンド終了時にディーラーが全席のカードを回収するため）。
- ミスディール訂正（ADR-0043）でもその席の観測を捨てる。
- 観測の取得が例外を投げても記録は続行（処理時刻にフォールバック）。
- 時刻が物理観測由来であることは `source.rfid=True` で示す。**confidence は据え置き**
  （判定材料にしていないので、較正済みの値を動かさない = ADR-0033 を壊さない）。

**既知の限界**: プレイヤーが長時間カードを手に持ってからマックすると、観測時刻は「持ち上げた
瞬間」になり実際の fold より早くなる。フック未注入なら従来どおり処理時刻（= 挙動不変）。

### 2. ボード各枚の配布時刻を `HandSummary` に残す

`HandSummary.board_timeline`（additive）に `[{"index": 1..5, "card": ..., "dealt_at": ISO}]` を
index 昇順で記録する。

- 時刻は **最初に検出した瞬間**で固定する。結合の弱いリーダーは同じ札を何度も再検出する
  （実機で 1 分に 10 回以上観測）ので、再発火で上書きしない。
- **ターン = index 4 / リバー = index 5** の `dealt_at` がそのままラウンドの区切り。
- **フロップは 3 枚の最小値**がラウンド開始。フロップ内の順序は意味を持たない（要件どおり）ので、
  index 1..3 の並びに意味を求めない。
- ミスディール訂正で位置を取り消したら、その位置の時刻も捨てて差し替え後に採り直す。

schema は `hand` `1.0` → **`1.1`**（optional フィールド追加 = additive、`versioning-and-freeze.md` §2）。

### 3. スコープ外（本 ADR では決めない）

推定方式そのもの（尤度ベースのアクター推定・事後確率・系列推定）は **ISSUE-0031** の論点であり、
Fable 5.1 の設計監査を経て別 ADR で決める。本 ADR は **その入力となる観測の時刻精度**に限定する。

## Consequences

### 良くなること

- サイレントフォールドの時刻が「次の人が動いた時刻」ではなく **実際に札が席を離れた時刻**になる。
  音声録音との突き合わせが成立する唯一の情報源。
- ターン / リバーの配布時刻がハンドログに残り、ベッティングラウンドの境界を時間軸で特定できる。
- どちらも **観測の記録**であって解釈ではないので、後続でどんな推定器を採っても入力として使える
  （早期確定で情報を捨てない = ISSUE-0031 の方向と整合）。

### 代償・残る制約

- カードを長く手に持つプレイヤーでは fold 時刻が早めに出る（上記の既知の限界）。
- ホールカードの**配布**時刻は記録していない（要件に無いため）。必要なら同じ仕組みで追加できる。
- `board_timeline` は RFID 経路のみ（他ソースでは空配列）。
- マック観測は **ライブ経路のみ**。生イベント sidecar（既定 off）には現れないので、
  事後推定に使うなら sidecar への記録が別途要る（ISSUE-0031 の検討事項）。

## Alternatives considered

1. **不在 + タイムアウトで fold を自動判定する**（仕様 FR-25/35 の素朴な読み方）— 却下。
   プレイヤーがカードを持ち上げる運用と両立しない。仕様の「RFID フォールド検知」をそのまま
   実装すると誤 fold を生む。確率的な扱いに格上げすべき論点として ISSUE-0031 に送る。
2. **生イベント sidecar を常時 on にして事後に全部やる** — 本 ADR では採らない。sidecar を既定 on に
   するかは推定方式の決定と一体（ISSUE-0031）。ただし本 ADR の観測はその方向と矛盾しない。
3. **`board_timeline` を持たず `RFIDEvent` の生時刻だけ sidecar に残す** — 却下。sidecar は既定 off で、
   通常運用のハンドログに時刻が残らない。要件（ターン/リバーの時刻）はハンドログ側に必要。
