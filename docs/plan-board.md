## 3. トラック同士のぶつかり

### 3-1. 日程が実態と合っていない（D）

`docs/estimator.md` の手順は「10/17 まで音声の改善 → 10/20〜10/24 に 5〜6 人卓 2 セッションで準備の確認（誤り 6 以下・
要確認なしの誤り 0）→ 届かなければ 11 月初めまでにオーナーが選ぶ」。しかし:

- 10/20〜10/24 の 5〜6 人卓のセッションの記録（作業ログ・開発データ）がまだ無い。
- 10/19 の 8 人卓では推定器の全部正しいハンドが 20/109（verify-v1 の版で 24/107）、要確認は 109/109。監査 4 回目は
  「この種の卓では誤り 6 以下に届かない」と書いている。
- B（v2）に進むなら推定器は作り直しになり、11 月初めまでに固定できる版は無い。

→ 11 月初めの判断の中身（(a) 合格の条件を変える / (b) 推定器を要確認の候補を出す道具にとどめる / (c) v2 ができるまで
判断を延ばす）を、B の段取りと一緒に決める必要がある。

### 3-2.（解消）C の比べる相手が古い版だった・C の結果が v1 の採点に縛られる

C の打ち切りで解消。打ち切りの判断は版の差（内容の指紋 `508cac7e08b8` と verify-v1 の差）では変わらない大きさ
（② 提案つき −1・③ LLM が選ぶ −7、事前登録の打ち切りの基準 = Opus で ②③ とも +5 未満）。

### 3-3. E と A がどちらも音声の読みに触れる

E（音声の取りこぼし）は聞き取り・VAD・`audio/` を、A は `audio/recognizer.py` の読みの規則を触りうる。E が直しに入る
ときは verify-v1 を先に取り込み、`audio/recognizer.py` を触るなら A のセッションと順番を決める。E の調査は 10/19 の
記録で行い、測るときは推定器の版（内容の指紋）を書く。

### 3-4. A が推定器の基準を動かし続ける

A のライブの規則は世界の再生にも効くので、直すたびに推定器の内容の指紋と物差し（開発データ 140/174・10/19 の数）が動く。
B・C は測るときの基準の版（内容の指紋・値の指紋・コミット）を記録し、比べるときは同じ版どうしで比べる。

### 3-5. B と E とこのセッションが同じブランチ

B・E・この台帳のセッションが `claude/project-plan-review-byn3lm` を使っている。push の前に必ず `git pull` する。
B が実装に入るとき（`integration/estimator.py` を大きく触る）は B 用に別のブランチを切る。
C の道具（`HandWindow.seeds`・`tools/llm_candidates.py` など）は既定では結果を変えないので残してよい（消すかはオーナー）。

### 3-6. F と B が同じ対応づけを要る

F（値を数える）の最初の段（F1 = 真の列と観測の対応づけの道具）と、B の ① 任意の列の採点は、どちらも「真のアクションの
行を発話・札の離脱に対応づける」部品が要る。先に作った側がそれを台帳に書き、もう片方は作らずに使う。F が
`integration/estimator.py` の値を変えるときは B・A と同じファイルなので、変える前に verify-v1 を取り込む。

### 3-7. G と A がどちらもライブの経路を触る

G は `main.py`（起動の設定）・`integration/engine.py`（時計・`set_level`）・`core/poker_engine.py`（アンテ）を変えた。A が同じ
ファイルを触っているので、G を verify-v1 に入れる前に verify-v1 を取り込む（このブランチで済ませている）。G の変更は既定
（リングゲーム・アンテなし）で記録を変えないので、推定器の物差しの数は動かない（内容の指紋は動く）。

## 4. 進める順（推す案）

1. A の計画を承認する（ほかのトラックと独立。今日のうちに店舗 PC に入れられる）。
2. E はまず開発データ（10/14 まで, このリポジトリにある）で、10/19 の記録が届いたらそれでも「真のベット / レイズの発話が無い」ハンドの原因を数える（マイクに入っていない / VAD で落ちた /
   認識の待ちで遅れた / 聞き違い）。直す前に結果をオーナーに見せる（マイク・VAD はオーナーの許可が要る）。
3. B は ① 任意の列の採点（= オラクルの採点）だけを作る。v1 の採点と v2 の採点の両方で「真の列の点 > 1 番の点」を出す。
4. 2 と 3 の結果を並べて、v2 に進むか（② 以降）・11 月初めの判断をどうするかをオーナーが決める。
   C から分かったとおり、入力に情報が無いハンドは採点をどう直しても正しくならないので、E の結果が v2 の伸びしろの上限を決める。
