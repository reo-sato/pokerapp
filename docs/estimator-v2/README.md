## 1. なぜ作り直すか（v1 の採点の性質）

v1 の採点は手置きの log 確率の足し算で、次の性質がある（2026-10-24 の議論）:

1. 雑音を語として借りるほうが「言われない」より安い（決まり文句をアクションに ≒ −2.4 < 言われない check / call / fold −3.2）。
2. 手の事前が一様（−log 合法手の数）で、現実の行動の割合と合わない（下の §3.2）。
3. 値が 4 席・プレイヤーなしの卓の小さな数から置いた定数で、卓によって変わらない。
4. 事象の確率・時刻の密度・手置きの読みの値が混ざり、仮説ごとに説明する観測の数が違う（何も読まない発話は 0 点）。
5. 持ち上げ（1/200 秒）がデータ 0 件の手置き。
6. 要確認が確率と無関係（直しを使ったら付く）。

## 2. 形（草案）

- 仮説 H = ボタン + 合法なアクションの列（pokerkit）+ 終わり方。観測 O = 発話（Whisper の文・第 2 の耳の候補ごとの点数）+
  札の在否の履歴 + ボードの札の時刻。点 = log P(H) + log P(O | H)。**すべての仮説がすべての観測を説明する**。
- P(O | H)（尤度）: ディーラーがアクションを言う確率 s・発話の事象（アクションの語 / 雑談 / 言い直し / 訂正 / 宣言）と
  音の尤度（第 2 の耳の強制デコードの点数・Whisper の取り違えの表）・札の在否の過程（持ち上げの率・フォールドのラグ）・
  ボードの札の時刻。値はサブプロジェクト F が数える。
- 推論: ADR-0056 D2 の形（局面 × 発話の位置のビーム / 動的計画法）。事後確率で要確認を付け、評価のデータで較正する。
- 段取り（台帳の推す案）: ① 任意の列の採点（= オラクルの採点）→ ② 値を数える → ③ 探索 → ④ 較正。

## 3. 事前 P(H)（2026-10-24 の議論）

### 3.1 何を入れるか

P(H) は**プレイヤーの行動だけ**を表す。ディーラーが口に出すか・聞き違え・札の離脱は尤度の側。誰に配られたか・持ち点は
観測（RFID・記録）で、仮説にしない。ボタン（ディーラーの動かし忘れ）は仮説の一部。v1 の「言われない確率」には
「プレイヤーがそうした」と「ディーラーが言わない」が混ざっていたので分ける。

```
P(H) = P(ボタン) × Π_i P(種類_i | 局面_i) × P(額_i | 種類_i, 局面_i)
```

手番ごとに pokerkit の合法手の中で足して 1 → 完了したハンド全体でも足して 1。アクションの多いハンドほど点が下がるのは
正しい事前になる（v1 の問題は各手番の確率が一様なこと）。

### 3.2 一様の事前と現実の差（開発データの真のアクション 174 ハンド・2,381 アクション）

| ストリート | 状況 | 真のアクションの割合 | v1（一様） |
|---|---|---|---|
| プリフロップ | 向き合う（n=747） | fold 24%・call 48%・raise 28% | 各 33% |
| フロップ | 向き合う（n=307） | fold 28%・call 64%・raise 8% | 各 33% |
| フロップ | 向き合わない（n=386） | check 63%・bet 37% | 各 50% |
| ターン | 向き合う（n=189） | fold 28%・call 63%・raise 9% | 各 33% |
| リバー | 向き合う（n=171） | fold 39%・call 44%・raise 16% | 各 33% |

ポストフロップのレイズは一様だと 1 回あたり log(0.08/0.33) ≒ 1.4 安すぎる。ただし**この開発データはオーナーが 1 人で
何席も打つ練習**（4 席が 156/174 ハンド）で、プレイヤーの方策としては使わない（下の決定 1）。

### 3.3 局面の特徴（少なく持つ）

1. ストリート × ベットに向き合っているか
2. そのストリートのそれまでのレイズの回数
3. ポジション（プリフロップの UTG〜CO / BTN / SB / BB。8 人卓の言われないフォールドの順番に効く）
4. 残りの人数・まだ手番の来ていない人数
5. 持ち点 ÷ 向き合っている額（短いと all-in が増える）・持ち点の深さ（ブラインドの何倍）
6. **卓の種類**（リングゲーム / トーナメント。決定 3）

値は階層で持つ: 一般のポーカーの統計（決定 2）→ 卓の種類ごとの店の値 → セッションごとの値（経験ベイズで上へ縮める）。

### 3.4 額

種類が決まったあと、ポットに対する大きさの区分（½ 以下・½〜1・1〜2・2〜3・3 倍超・all-in）と丸い額（100・500・1000 の倍数）。
額は声で言われるのがふつうなので、効くのは額が聞き取れないときと第 2 の耳の額の候補から選ぶとき。

### 3.5 確かめ方（推定器なしでできる）

事前だけの良さは**真の列の対数尤度**（手番 1 つあたりの log loss）で測る: 一様 / 数えた方策 / ポジション付き / 階層つき。
10/19 の一部で数えて残りで測る（ハンド単位で分ける）。

### 3.6 決定（オーナー, 2026-10-24）

1. **開発データ（1 人で何席も打つ練習）は方策の事前を数えるのに使わない**。方策は 10/19 と今後のプレイヤーありのセッション
   だけで数える。開発データはディーラーの言い方（尤度）を数えるのに使う。
2. **一般のポーカーの統計（公開のハンド履歴など）を、店のデータが少ないうちの出発点（弱い事前）に使ってよい**。店のデータが
   貯まるほど店の値へ寄せる。
3. **店の卓はリングゲームも多い**（トーナメントだけではない）→ 卓の種類を局面の特徴に入れる。
4. **一般の統計はライブの、なるべくルーズな卓のハンド履歴を使う**（オンラインは性質が相当違うので使わない）。アミューズメントの
   卓はさらに緩い見込みなので、店のデータが貯まるほど店の値へ寄せる。
5. **リングゲームとトーナメントのモードを実装して記録を分ける**。あわせてアンテの有無と、事前に登録したトーナメントの
   ストラクチャーに沿って時間でブラインドを自動で上げる機能を作る（ライブの経路の変更 = 台帳の A と順番を決める。設計は別に）。
