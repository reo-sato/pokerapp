# トラブルシューティング

困りごと別の対処です。設定の場所は [設定リファレンス](usage.md#設定-configjson) を参照してください。

店舗 PC では、コマンドはインストール先のフォルダ（`C:\PokerHandLogger`）で `.\venv\Scripts\python.exe tools\<道具>.py …`
の形で実行します（下の `python tools/…` はその略です）。config の 1 項目は
`python tools/set_config.py <項目> <値>` で変えます（値を省くと今の値を表示）。

---

## アプリが起動しない

- **Python が 3.11 未満**: `python --version` で確認。3.11 以上を入れ直してください（店舗 PC のインストーラは 3.12 を入れます）。
- **依存のインストールに失敗**: 特に `pyaudio` は OS 側の PortAudio が必要なことがあります
  → [インストール手順](installation.md#マイク入力portaudioについて)。
- エラーメッセージに `ModuleNotFoundError` が出る場合は `pip install -r requirements.txt` を再実行
  （店舗 PC は `install.cmd` をもう一度）。

---

## マイクが認識されない／録音されない

`tools/audio_check.py`（ADR-0060）で順に確かめます。

1. **`list`** — 録音できるデバイスの一覧（番号・方式・16 kHz で開けるか）。卓のマイクが出ていれば、
   **名前で固定**します（Bluetooth のつなぎ外しで番号がずれても同じマイクを開く）:
   `python tools/set_config.py audio.device_name "Wireless Mic Rx|DJI Mic Mini 2"`
   （名前の一部。大文字・小文字は区別しない。「|」で区切ると優先順の候補）。ロガーは起動のたびに名前でマイクを探し、
   16 kHz で開ける番号（ふつうは MME）を選びます。**どの名前も見つからなければマイクを開きません**（別のマイクで録らない）。
   `audio.device_name` が空のときだけ番号（`audio.device_id`）で選びます。そのときは「16kHz OK」の番号を選びます
   （同じマイクが方式ごとに並ぶ。WASAPI は 16 kHz で開けないことが多い）。
2. **`level`** — 話すとバーが伸びるか。「発話」と出れば拾えています。ずっと 0 なら次の 3・4。
   声が小さい（しきい値 `audio.speech_rms` = 300 に届かない）ときはマイクを口元に近づけるか、Windows の録音レベルを上げます。
3. **RDP でつないでいる店舗 PC**: リモートデスクトップは既定で音声を接続元の端末に回すので、PC に挿した
   マイクがセッションから見えない・無音になることがあります。**`list` に WDM-KS 方式の行しか出ない**ときがこの状態です
   （`list` とロガーの起動時にもその旨が出ます。WDM-KS では Bluetooth のマイクを開けません）。接続元のリモートデスクトップの
   設定で **音声の再生を「リモート コンピューターで再生する」**（Mac / iPad の Windows App は「リモート PC で再生」）にして
   つなぎ直し、`list` / `level` をやり直してください（録音は「録音しない」のままでよい = 接続元のマイクは使わない）。
   この設定は接続元の端末が保存した接続ごとに覚えるもので、PC の側からは変えられません。
4. **Windows のマイクのアクセス許可**: 設定 →「プライバシーとセキュリティ」→「マイク」で「マイクへのアクセス」と
   「デスクトップ アプリがマイクにアクセスできるようにする」をオン（オフだと開けても無音になる）。
5. **`listen`** — 本番と同じ経路で聞き取り、発話ごとに「何と聞こえたか → どのアクションになったか」と
   認識にかかった秒数を出します。ここで読み上げ語彙が拾えていれば、ハンドロガーでも同じに拾えます。

ハンドロガー（`--cli`）は起動時に「音声入力: マイク 番号 N（名前）で聞き取っています」か、開けなかった理由を
表示し、聞き取った文を `[聞き取り] 「…」→ …` と出します（ログファイル `logs\pokerapp.log` にも残る）。

- **起動のときにマイクを開けなかった**（RDP の音声が接続元に回っていた・設定した名前のマイクが見つからない など）:
  ロガーは音声なしで続けながら開き直しを続け、開けたら `● マイクを開けました（…）— 聞き取りを始めます` と出して
  聞き取りを始めます。**ロガーを起動し直す必要はありません**（それでも始まらなければ起動し直してください）。
- **録音の途中でマイクが切れた**（Bluetooth の切断・電池・受信機）: `● マイクが切れました（…）— つながり直すのを
  待っています` と出て、1 秒から 10 秒の間隔で開き直します。戻れば `● マイクを開き直しました（…）— 聞き取りを再開します`。
- **`● 60 秒以上、マイクに声が入っていません`**: プレー中に 60 秒声が入らないと 1 ハンドに 1 回出ます。マイクの電池・
  受信機・音量を確かめ、`python tools/audio_check.py level` で入力の大きさを見てください。

## 音声認識の精度が低い

- **マイクをディーラーの口元に**近づけてください（口元マイク推奨）。周囲の雑音を減らすと精度が上がります。
  配る人・マイクの付け方が替わると声の大きさが半分ほどに変わることがあるので、替わったら `audio_check.py listen` で確かめます。
- **1 アクションずつ区切って**読み上げてください。コール・チェックは毎回言います（フォールドは札が席から離れれば記録されます）。
- 語彙は [アクション語彙](usage.md#アクション語彙) のとおり読み上げてください（言い回しが独特だと拾えません）。
- **モデル**: `audio.whisper_model` は `medium`（既定）を使います。`small` は軽いですが、店舗の実測で金額を聞き違えました。
- **第 2 の耳**（日本語専用の音声認識）: Whisper がアクションとして読めなかった発話を聞き直します（聞き直した行は要確認）。
  モデルは `models\` にあり、無ければ Whisper だけで聞きます。`audio.second_ear.enabled` を `false` にすると使いません。
- **音量が原因か確かめる**: `python tools/audio_check.py gain --session <セッションID>` で、保存した発話をそのままの音と
  声の大きさをそろえた音の 2 通りで聞き直して比べます（発話の保存 `audio.save_audio` が `true` のセッションだけ）。
- それでも崩れるハンドは `needs_review` が付くので、**後から JSON を見直す**運用が安全です。

---

## 聞き取りが遅れる／遅れがたまる

- 音声認識（medium）は CPU で 1 発話 3 秒前後かかります（店舗 PC の実測）。続けて話すと遅れがたまりますが、
  **発話は捨てず**、プレーの切れ目で追いつきます（ADR-0061）。ハンドロガーの `[聞き取り]` の行が遅れて出るのは
  そのためです。
- 遅れている間に打った `n` / `w` などは、先に言われた発話の反映を待ってから入ります（最大 60 秒）。
- **CPU のスレッド数**: `audio.cpu_threads`（既定 0 = Whisper の既定の 4 スレッド）。8 コアの PC では増やすと速くなる
  ことがあります（店舗 PC は 8）。`python tools/audio_check.py bench` で保存した発話（`logs\audio\<セッション>\`。
  `audio.save_audio` を `true` にして録ったもの）を使ってスレッド数ごとに測り、速い設定と、それを config に入れる
  コマンドを表示します（マイク不要）。ビーム幅（`audio.beam_size`）は下げると書き起こしが変わるので下げません。
- **雑音への幻聴**: 札を混ぜる音などに Whisper が「ご視聴ありがとうございました」やプロンプトの繰り返しを書くと、
  1 回に何秒もかかります。声らしくない音は Whisper にかけません（`audio.vad_threshold`、既定 0.5、0 で使わない）。
  幻聴で遅れるなら上げます（店舗 PC は 0.8）。`audio_check.py listen` に `（声ではない音 N 秒 — Whisper にかけず。…）`
  と出た音が言葉だったら下げます（0.7 など）。この音はロガーの画面には出ません（`logs\<セッション>.transcripts.jsonl` に残る）。
- 短い言葉が落ちるときは、`listen` の `（短い音 N 秒 — 認識に回さず。…）` を見て `audio.min_speech_sec`（既定 0.15）を下げます。

## 初回起動が遅い／モデルのダウンロードが進まない

- 初回のみ音声認識モデル（`medium` は約 1.5 GB）をダウンロードします。**ネット接続**と**空き容量**を確認してください。
  ハンドロガーは「音声認識モデル（medium）を読み込んでいます…」と出している間ダウンロードしています。
- 本番の前に `python tools/audio_check.py listen` を一度動かしておけば、ダウンロードが済みます。
- 取得に失敗してもハンドロガーは止まらず、「音声認識モデルを読み込めませんでした」と出して音声なしで続けます
  （キーボードの読み上げ文で進行できる）。
- 回線が細い場合は `audio.whisper_model` を `small` にするとダウンロード量が減ります（精度は下がる）。
- ダウンロードは一度きりです（次回以降はキャッシュを使います）。
- 第 2 の耳のモデル（約 170 MB）はインストール・更新のときに `models\` に取ります。取れなかったときは
  `python tools/second_ear.py --model-only` で取り直せます（取れなくても Whisper だけで続けます）。

## RFID が反応しない（任意機能）

まず `config.json` の `rfid.enabled` が `true`、`rfid.transport` が `"pcsc"` か確認します（正式な構成。
`pip install ".[pcsc]"` が要る。店舗 PC のインストーラは入れます）。ハンドロガーは起動後に
「RFID: リーダー 11/11 台を…読んでいます。」のようにつながり具合を出し、変わったら出し直します。
リーダーにつながらなくても止まらず、5 秒ごとに試し直します（つながれば起動し直さずに使い始める）。

### RDP で操作していると読めない（`0x8010001D`）

- RDP のセッションの中のアプリからは、PC に挿したリーダーが見えないことがあります（`SCardEstablishContext` が
  `0x8010001D`「スマート カード リソース マネージャーが実行されていません」。2026-09-30 の店舗 PC では、スマートカードの
  転送を両側で止めてサインアウトしても同じでした）。ロガーは「⚠ RFID: リーダーにつながりません…」と、
  中継を登録するコマンドを出します。
- **RFID の中継**を一度だけ登録します。中継はシステムの権限のスケジュールタスク `PokerRFIDRelay`（PC の起動時に動く）で
  リーダーを読み、PC の中（`127.0.0.1:8792`, config `rfid.relay_port`）だけに渡します。ロガー・`rfid_check`
  （`probe_pcsc list / check / watch`）・`register_cards run` は、中継が動いていれば中継を通して読みます。
  PowerShell に貼る（管理者の確認には「はい」）:

  ```powershell
  Start-Process powershell -Verb RunAs -ArgumentList '-NoProfile -ExecutionPolicy Bypass -File C:\PokerHandLogger\installer\rfid_relay_task.ps1'
  ```

  登録すると起動して `status` の結果を出します。ロガーは「RFID: リーダー 11/11 台を中継（RDP の外の読み取り）から
  読んでいます。」と出せば使えています。中継のログは `logs\rfid_relay.log`。
- 確かめるコマンド: `python tools/rfid_relay.py status`（中継が動いているか・リーダーごとの読み取り。PASS / FAIL）/
  `python tools/rfid_relay.py watch --seconds 60`（札を置く・外すたびに `+ seat 1 [r0] Ah …` の 1 行）。
- **中継が古い**（アプリを更新したあと）: 更新は動いている中継を止めないので、中継は古い版のまま動きます。
  「中継が古い版です」「⚠ RFID: 中継（RDP の外の読み取り）が止まっています」と出たら、上のコマンドをもう一度実行すると
  新しい版で動き直します。
- `config.json` のリーダーを変えたときは、中継が自動で読み直します（中継の登録し直しは要りません）。
- 中継を消すときは（`uninstall.cmd` も中継のタスクを消します）:

  ```powershell
  Start-Process powershell -Verb RunAs -ArgumentList '-NoProfile -ExecutionPolicy Bypass -File C:\PokerHandLogger\installer\rfid_relay_task.ps1 -Remove'
  ```

### 一部のリーダー（ボードの真ん中など）だけ読めない

- ロガーは、読み取り装置（ESP32）が「使えない」と答えたリーダーを `● ⚠ RFID: 使えないリーダーがあります: ボードの左から
  2 台目のリーダー（reader 9）…` と知らせます。一覧に出ない不調も見張り、ボードのリーダーが 2 ハンド続けて 1 枚も札を
  読まなければ知らせます。
- **`rr`**（ハンドロガーに打つ）で読み取り装置を再起動します。卓に札が無い状態が 2 秒続いたら送ります（札が載っていれば
  片付くのを待つ）。再起動のあいだ（数秒）は全リーダーが読めません。結果は `● RFID: 読み取り装置を再起動しました — 11 台とも
  使えます。` のように出ます。`rfid.auto_restart`（既定 `true`）なら、使えないリーダーがあるとき、卓に札が無い状態が
  10 秒続いたら自動で再起動します（1 つの不調につき 2 回まで）。PowerShell からは
  `python tools/rfid_relay.py restart`（`python tools/probe_pcsc.py restart` も、中継が動いていれば中継を通して送ります）。
- **それで直らない・「ファームウェアに再起動の命令がありません（古い版）」と出る**: 読み取り装置（ESP32）の
  **給電アダプタを抜いて数秒待ってから挿し直します**。店の卓の ESP32 は給電アダプタから電源を取るので、
  **PC との USB を抜き挿ししても再起動しません**（2026-10-06）。リーダーの準備は ESP32 の起動のときだけなので、
  動いている途中でリーダーのコードが抜けた・挿し替えたときも、給電アダプタの抜き挿しが要ります。
- 直ったかは、左・真ん中・右のボードのリーダー（`board [r8]`・`[r9]`・`[r10]`）と席に札を置いて
  `python tools/rfid_relay.py watch --seconds 60` で 1 行ずつ出るか確かめます（中継を使っていなければ
  `python tools/probe_pcsc.py watch --seconds 60`）。
- **使えるリーダーの一覧**は、中継を使っているときは `python tools/rfid_relay.py status`（使えないリーダーは
  `✗ … 使えません`）、直接読んでいるときは `python tools/probe_pcsc.py list`（`使えるリーダー: 0, 1, …`）で見られます。一覧はファームウェアの
  書き換え（契約 v1.11）のあとに出ます。古いファームウェアでは「一覧は出ていません」「非対応」と出て、
  **`✓` はリーダーが「札なし」と答えていることしか示しません**（起動のときに準備できなかったリーダーも「札なし」と
  答え続けます）。リーダーが本当に読めるかは、札を置いて `watch` で確かめてください。
- ボードのケーブルは元の位置（左 #10・真ん中 #12・右 #13）に挿します。
- ファームウェアの書き換え（ESP-IDF の入れ方と店舗 PC の「ESP-IDF 5.3 CMD」の 1 行）は
  `firmware\esp32s3-pn5180-ccid\README.md` の「書き換え」の節にあります（部品の版は esp_tinyusb 1.7.6・tinyusb 0.19 に固定）。

### そのほか

- カードが「未知」（`(未登録)`）になる場合は `rfid_cards.json`（タグ→カード対応表）に登録漏れがないか確認
  （`python tools/register_cards.py run --deck 1`）。スートを取り違えて登録したときは
  `python tools/register_cards.py swap-suits d c`（ダイヤとクラブを入れ替え。もう一度で元に戻る）。
- **HTTP 方式**（補助）: ESP32 が本アプリの `http://<PCのIP>:8787/`（既定ポート `8787`）へ POST できているか、
  PC のファイアウォールでポートが塞がれていないか確認。
  `rfid.bind_host` が既定の `127.0.0.1` のままだと**同一 PC 内からしか受信できません**。
  ESP32 から受ける場合は PC の LAN IP に変更してください（[インストールガイド §5](installation.md#5-rfid-を使う場合)）。
- RFID は**任意**です。うまくいかなくても `rfid.enabled` を `false` にすれば音声のみで記録できます
  （そのときは配る前に `n` を打つか「ハンド開始」と言います）。

## ハンドが始まらない／アクションが「[未適用] … (no_active_hand)」になる

- RFID がある卓では、**2 席以上に手札を置いた時点**でハンドが始まります（`● ハンド N 開始（手札が配られました …）`）。
  出ないときは:
  - ロガーがリーダーにつながっているか（起動後の「RFID: リーダー N/N 台…」の行）。つながっていないと手札を配っても
    ハンドが始まらず、声も聞き取りません（上の「RFID が反応しない」）。
  - 席のリーダーが札を読めているか（卓モニタ・ログの `Hole card detected`）。1 席だけでは始まりません。
  - 起動時に入れた席番号と、`config.json` の席のリーダー（`pcsc_readers` の `seat`）が合っているか。
    卓で使っていない席のリーダーの札は数えません。
  - `config.json` の `engine.auto_new_hand` が `false` になっていないか。
- RFID が無い・読めないときは、配る前に `n` を打つか「ハンド開始」と言います。
- 片付けの途中で 2 席の札が読めて早めに始まったときは、そのまま配れば同じハンドとして続きます（手札は置き直された札で
  差し替わります）。

## 「席の設定が違うかもしれません」と出る

- ハンドを始めて 5 秒たっても、ロガーの席に無い席に手札が 2 枚あると出ます（ハンドごとに 1 回。記録は変えません）。
  例: 「手札は 席3・4・5・6 にありますが、ロガーの席は 4・5・6・7 です（席7 に手札がありません）」。
- 起動時に入れた席と、札を置いている席がずれています。このままだと札の離脱・マックが隣の人のフォールドになります。
  `q` で終了し、**札を置く席の番号**で起動し直してください（起動時の「席」は人数か、札を置く席の番号の並び）。

## ボードの札が読めない（`??`）／チップが動かない

- フロップは 3 枚が同時に出るので、あとから出た札はフロップの空き位置に入れず、ターン以降にします。決め方: 一番右の
  ボードのリーダーだけで読んだ札はターン・リバー、一番左のリーダーで読んだ札はフロップ（遅れて読めたフロップの札）、
  それ以外はフロップの最初の札から 10 秒（`rfid.flop_window_sec`、`null` で従来どおり）より後ならターン以降。
- 読めなかった位置は記録で `??`（例 `3c Kh ?? Kc 9s`、CLI では `?`）になります。ストリートは枚数ではなく位置で決めます。
- ショーダウンで札が読めていないとき: 読めていない札のありうるすべてで勝者が同じなら、その勝者に決めます（要確認）。
  札しだいで勝者が変わるなら **チップは動かしません**（次の手札が配られたとき・終了のときに、各席が出した額を返して確定。
  勝者なし・要確認）。スマホのハンド履歴は「勝者なし — 札が読めず判定できないので、チップは動かしていません」。
  それまでに `w <席>` を打てばその席の勝ちになります。

## ショーダウンの勝者が決まらない／違う

- ショーダウンでは、ディーラーは**必ず「ショウダウン」と言い**、手を見せるたびに**役名を言います**（アウトオブ
  ポジションから。見せると札がリーダーから外れるので、役名が無いと誰が見せたか分かりません）。
- **役名**（「ツーペア」「キングヒット」「クイーンジャック」など）= 次に見せる人が見せた、として記録します（CLI は
  「見せた（ツーペア）」）。手札で役名に合う席がまだ見せていない中に 1 つだけあれば、その席です。
- **見せる前の「フォールド」**= 一番アウトオブポジションの人のマック。**見せたあとの「フォールド」**= まだ見せていない
  次の人のマックです（インポジションの人が見せずにマックしたときもこれで記録できます）。見せずにマックした人は
  手札が強くても負けです（手札の方が強ければ要確認）。
- 残った全員が見せたら手札で決めます。**役名もマックも無いまま 8 秒たったら**、残った全員が見せたとして手札で決めます
  （次の手札を待ちません）。「ハンド終了」と言っても手札で決めます。
- 役名と手札の判定が違えば要確認になります。
- 「勝者を手札で判定できません（席5 の手札 1/2 枚）」と出たら、`w <席>` で勝者を打ちます（上の「ボードの札が読めない」も参照）。
- 自動で決まった勝者が違っていたら、スマホの訂正画面で直します（記録は上書きしません）。

## iPad の画面に「Load failed」と出る／「サーバにつながりません」と出る

- 真のアクション入力・台本・読み上げ集の画面が、PC のサーバにつながらないときの表示です（「Load failed」は Safari の表示）。
  いまの画面は「サーバにつながりません。PC の「真のアクション入力 (iPad から)」の黒い窓が開いているか確かめてください」と出します。
- PC の「真のアクション入力 (iPad から)」の黒い窓が開いているか確かめ、閉じていたら起動し直して画面を再読み込みします。
  「台本のハンド (声だけ)」「札の確認 (RFID)」は、このサーバが動いていなければ別の窓で一緒に起動します（その窓も閉じない）。
- サーバの中でエラーが起きたときは、画面にその中身が出て、黒い窓にも残ります。それを添えて共有してください。

## 記録されたハンドのルールがおかしい

- 既定の `pokerkit` バックエンドはルール準拠で整形しますが、まれに読み上げのズレを誤って補完することが
  あります。その場合 `needs_review` / `review_required` が手掛かりになります。
- どうしても従来の素朴な動作に戻したいときは、`config.json` の `engine.backend` を **`"legacy"`** に
  変更してください（ルール補正・サイドポット計算などは無効になります）。

---

## `needs_review` / `review_required` が多い

- これは**バグではなく仕様**です。自信が低い・矛盾する・自動補完したアクションに付き、
  「人の目で確認してほしい」という印です。
- 認識精度（上記）を上げると減ります。配信後にまとめて該当ハンドだけ見直す運用が効率的です。

---

## ログはどこにある？

- `config.json` の `session.log_dir`（既定 `./logs`）配下に `<セッションID>.json` として追記されます。
  アプリのログは `logs\pokerapp.log`、RFID の中継のログは `logs\rfid_relay.log`。
- PHH に変換するには `python main.py --export-phh logs/<セッションID>.json`。
- 送るときはデスクトップの「ログをまとめる (送付用)」（直近 12 時間のセッションを zip 1 つに）。発話の音声も全部
  送るときは「ログをまとめる (音声付き・送付用)」（25 MB を超えると `_1of3.zip` のように分かれるので全部送る）。

---

それでも解決しない場合は、「ログをまとめる (送付用)」の zip（または `logs/` の JSON と `logs\pokerapp.log`）を
プロジェクト管理者に共有してください。
