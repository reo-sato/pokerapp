# トラブルシューティング

困りごと別の対処です。設定の場所は [設定リファレンス](usage.md#設定-configjson) を参照してください。

---

## アプリが起動しない

- **Python が 3.11 未満**: `python --version` で確認。3.11 以上を入れ直してください。
- **依存のインストールに失敗**: 特に `pyaudio` は OS 側の PortAudio が必要なことがあります
  → [インストール手順](installation.md#マイク入力portaudioについて)。
- エラーメッセージに `ModuleNotFoundError` が出る場合は `pip install -r requirements.txt` を再実行。

---

## マイクが認識されない／録音されない

1. **マイクが OS に認識されているか**を先に確認（他アプリで録音できるか）。
2. **入力デバイスの番号**が合っているか。`config.json` の `audio.device_id`（既定 `0`）を変更します。
3. どの番号がどのマイクか調べたいとき（任意・少し技術的）:

   ```bash
   python -c "import pyaudio; p=pyaudio.PyAudio(); [print(i, p.get_device_info_by_index(i)['name']) for i in range(p.get_device_count())]"
   ```

   表示された番号を `audio.device_id` に設定します。
4. OS のマイク**アクセス許可**（プライバシー設定）も確認してください。

---

## 音声認識の精度が低い

- **マイクをディーラーの口元に**近づけてください（口元マイク推奨）。周囲の雑音を減らすと精度が上がります。
- **はっきり・1 アクションずつ**読み上げてください（「シート3 ベット 500」で一区切り）。
- 語彙は [アクション語彙](usage.md#アクション語彙) のとおり読み上げてください（言い回しが独特だと拾えません）。
- **モデルを大きく**すると精度が上がります: `audio.whisper_model` を `medium`（既定）に。逆に重い場合は
  `small` で軽量化（精度は下がります）。
- それでも崩れるハンドは `needs_review` が付くので、**後から JSON を見直す**運用が安全です。

---

## 初回起動が遅い／モデルのダウンロードが進まない

- 初回のみ音声認識モデル（数百 MB）をダウンロードします。**ネット接続**と**空き容量**を確認してください。
- 回線が細い場合は `audio.whisper_model` を `small` にするとダウンロード量が減ります。
- ダウンロードは一度きりです（次回以降はキャッシュを使います）。

---

## RFID が反応しない（任意機能）

- `config.json` の `rfid.enabled` が `true` か確認。
- **HTTP 方式**: ESP32 が本アプリの `http://<PCのIP>:8787/`（既定ポート `8787`）へ POST できているか、
  PC のファイアウォールでポートが塞がれていないか確認。
- **PC/SC 方式**: `pip install ".[pcsc]"` を実行し、`rfid.transport` を `"pcsc"` にしているか確認。
- カードが「未知」になる場合は `rfid_cards.json`（タグ→カード対応表）に登録漏れがないか確認。
- RFID は**任意**です。うまくいかなくても `rfid.enabled` を `false` にすれば音声のみで記録できます。

---

## 記録されたハンドのルールがおかしい

- 既定の `pokerkit` バックエンドはルール準拠で整形しますが、まれに読み上げのズレを誤って補完することが
  あります。その場合 `needs_review` / `review_required` が手掛かりになります。
- どうしても従来の素朴な動作に戻したいときは、`config.json` の `engine.backend` を **`"legacy"`** に
  変更してください（ルール補正・サイドポット計算などは無効になります）。

---

## `needs_review` / `review_required` が多い

- これは**バグではなく仕様**です。自信が低い・矛盾する・自動補完したアクションに付き、
  「人の目で確認してほしい」という印です。
- 認識精度（上記）を上げると減ります。配信後にまとめて該当ハンドだけ見直す運用が効率的です。

---

## ログはどこにある？

- `config.json` の `session.log_dir`（既定 `./logs`）配下に `<セッションID>.json` として追記されます。
- PHH に変換するには `python main.py --export-phh logs/<セッションID>.json`。

---

それでも解決しない場合は、`logs/` の JSON（該当ハンド）と、起動時のログ出力を添えて
プロジェクト管理者に共有してください。
