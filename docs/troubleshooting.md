# トラブルシューティング

困りごと別の対処です。設定の場所は [設定リファレンス](usage.md#設定-configjson) を参照してください。

---

## アプリが起動しない

- **Python が 3.11 未満**: `python --version` で確認。3.11 以上を入れ直してください。
- **依存のインストールに失敗**: 特に `pyaudio` は OS 側の PortAudio が必要なことがあります
  → [インストール手順](installation.md#マイク入力portaudioについて)。
- エラーメッセージに `ModuleNotFoundError` が出る場合は `pip install -r requirements.txt` を再実行。

---

## マイクが認識されない／録音されない

`tools/audio_check.py`（ADR-0060）で順に確かめます。店舗 PC ではインストール先のフォルダで
`.\venv\Scripts\python.exe tools\audio_check.py <サブコマンド>`。

1. **`list`** — 録音できるデバイスの一覧（番号・方式・16 kHz で開けるか）。卓のマイクが出ていれば、その番号を
   `python tools/set_config.py audio.device_id <番号>` で設定します。同じマイクが方式ごとに並ぶので、
   **「16kHz OK」の番号**（ふつうは MME）を選びます（WASAPI は 16 kHz で開けないことが多い）。
2. **`level`** — 話すとバーが伸びるか。「発話」と出れば拾えています。ずっと 0 なら次の 3・4。
   声が小さい（しきい値 300 に届かない）ときはマイクを口元に近づけるか、Windows の録音レベルを上げます。
3. **RDP でつないでいる店舗 PC**: リモートデスクトップは既定で音声を接続元の端末に回すので、PC に挿した
   マイクがセッションから見えない・無音になることがあります。接続元のリモートデスクトップの設定で
   **音声の再生を「リモート コンピューターで再生する」**（Mac / iPad の Windows App は「リモート PC で再生」）にして
   つなぎ直し、`list` / `level` をやり直してください（録音は「録音しない」のままでよい = 接続元のマイクは使わない）。
4. **Windows のマイクのアクセス許可**: 設定 →「プライバシーとセキュリティ」→「マイク」で「マイクへのアクセス」と
   「デスクトップ アプリがマイクにアクセスできるようにする」をオン（オフだと開けても無音になる）。
5. **`listen`** — 本番と同じ経路で聞き取り、発話ごとに「何と聞こえたか → どのアクションになったか」と
   認識にかかった秒数を出します。ここで読み上げ語彙が拾えていれば、ハンドロガーでも同じに拾えます。

ハンドロガー（`--cli`）は起動時に「音声入力: マイク 番号 N（名前）で聞き取っています」か、開けなかった理由を
表示し、聞き取った文を `[聞き取り] 「…」→ …` と出します（ログファイル `logs\pokerapp.log` にも残る）。

## 音声認識の精度が低い

- **マイクをディーラーの口元に**近づけてください（口元マイク推奨）。周囲の雑音を減らすと精度が上がります。
- **はっきり・1 アクションずつ**読み上げてください（「シート3 ベット 500」で一区切り）。
- 語彙は [アクション語彙](usage.md#アクション語彙) のとおり読み上げてください（言い回しが独特だと拾えません）。
- **モデルを大きく**すると精度が上がります: `audio.whisper_model` を `medium`（既定）に。逆に重い場合は
  `small` で軽量化（精度は下がります）。
- それでも崩れるハンドは `needs_review` が付くので、**後から JSON を見直す**運用が安全です。

---

## 聞き取りが遅れる／遅れがたまる

- 音声認識（medium）は CPU で 1 発話 3 秒前後かかります（店舗 PC の実測）。続けて話すと遅れがたまりますが、
  **発話は捨てず**、プレーの切れ目で追いつきます（ADR-0061）。ハンドロガーの `[聞き取り]` の行が遅れて出るのは
  そのためです。
- 遅れている間に打った `n` / `w` などは、先に言われた発話の反映を待ってから入ります（最大 60 秒）。
- 速さを優先するなら `audio.whisper_model` を `small` にできますが、店舗の実測では金額を聞き違えました
  （「ベット 1200」→ 100）。当面は medium を使います。

---

## 初回起動が遅い／モデルのダウンロードが進まない

- 初回のみ音声認識モデル（`medium` は約 1.5 GB）をダウンロードします。**ネット接続**と**空き容量**を確認してください。
  ハンドロガーは「音声認識モデル（medium）を読み込んでいます…」と出している間ダウンロードしています。
- 本番の前に `python tools/audio_check.py listen` を一度動かしておけば、ダウンロードが済みます。
- 取得に失敗してもハンドロガーは止まらず、「音声認識モデルを読み込めませんでした」と出して音声なしで続けます
  （キーボードの読み上げ文で進行できる）。
- 回線が細い場合は `audio.whisper_model` を `small` にするとダウンロード量が減ります（精度は下がる）。
- ダウンロードは一度きりです（次回以降はキャッシュを使います）。

---

## RFID が反応しない（任意機能）

- `config.json` の `rfid.enabled` が `true` か確認。
- **HTTP 方式**: ESP32 が本アプリの `http://<PCのIP>:8787/`（既定ポート `8787`）へ POST できているか、
  PC のファイアウォールでポートが塞がれていないか確認。
  `rfid.bind_host` が既定の `127.0.0.1` のままだと**同一 PC 内からしか受信できません**。
  ESP32 から受ける場合は PC の LAN IP に変更してください（[インストールガイド §5](installation.md#5-rfid-を使う場合任意)）。
- **PC/SC 方式**: `pip install ".[pcsc]"` を実行し、`rfid.transport` を `"pcsc"` にしているか確認。
- カードが「未知」になる場合は `rfid_cards.json`（タグ→カード対応表）に登録漏れがないか確認。
- RFID は**任意**です。うまくいかなくても `rfid.enabled` を `false` にすれば音声のみで記録できます。

---

## 記録されたハンドのルールがおかしい

- 既定の `pokerkit` バックエンドはルール準拠で整形しますが、まれに読み上げのズレを誤って補完することが
  あります。その場合 `needs_review` / `review_required` が手掛かりになります。
- どうしても従来の素朴な動作に戻したいときは、`config.json` の `engine.backend` を **`"legacy"`** に
  変更してください（ルール補正・サイドポット計算などは無効になります）。

---

## `needs_review` / `review_required` が多い

- これは**バグではなく仕様**です。自信が低い・矛盾する・自動補完したアクションに付き、
  「人の目で確認してほしい」という印です。
- 認識精度（上記）を上げると減ります。配信後にまとめて該当ハンドだけ見直す運用が効率的です。

---

## ログはどこにある？

- `config.json` の `session.log_dir`（既定 `./logs`）配下に `<セッションID>.json` として追記されます。
- PHH に変換するには `python main.py --export-phh logs/<セッションID>.json`。

---

それでも解決しない場合は、`logs/` の JSON（該当ハンド）と、起動時のログ出力を添えて
プロジェクト管理者に共有してください。
