# クラウドの準備（フェーズ 2, ADR-0067）

店外からお客さんが自分の履歴を見られるようにするための、クラウド側の登録と設定の手順です。
**この文書は進み具合に合わせて書き足します**（いまは「1. 登録」まで）。

> 大事な約束: パスワード・接続文字列・キー・トークンは**チャットに貼らないでください**。
> 必要になったら、Google Cloud の「Secret Manager」に入れる手順をこの文書に書きます。

## 全体の形

```
お客さんのスマホ ──(店外から閲覧)──▶ Cloud Run（東京, Google Cloud）──▶ Supabase の Postgres（東京）
                                         ▲
店舗 PC（正本）──(60 秒ごとに変わった分だけ送る, 一方向)──┘
```

- 録音・推論・会計は今までどおり店舗 PC。クラウドは写しを持って、お客さんに見せるだけ。
- クラウドから店舗 PC へは何も送られません（クラウドが乗っ取られても店のデータは変わらない）。

## 1. 登録（いまやっておくこと）

コードの作成（ADR-0067 の 2a〜2d）は登録が無くても進められます。登録は、クラウドに置く段（2e）までに済んでいれば大丈夫です。

### 1-1. Google Cloud（Cloud Run を置く場所）

1. <https://console.cloud.google.com/> を開き、Google アカウントでログインする（お店用のアカウントがあればそれで）。
2. 初めてなら無料トライアルの登録が出る。国・利用規約・支払い方法（クレジットカード）を入れる。
   - 新規の人には 90 日間使えるクレジット（$300）が付きます。トライアルが終わっても勝手に課金はされません（有料に切り替える操作が要る）。
3. 画面上部の「プロジェクトを選択」→「新しいプロジェクト」。名前は例えば `pokerapp-cloud`。作成したら、そのプロジェクトを選ぶ。
4. **予算アラートを設定する**（使いすぎの通知。必須）:
   - 左上のメニュー →「お支払い」→「予算とアラート」→「予算を作成」。
   - 対象のプロジェクト = 上で作ったもの、金額 = 例えば **月 3,000 円**、通知のしきい値 = 50% / 90% / 100%（初期値のままで可）。
   - 通知はお支払いのアカウントの管理者のメールに届きます。
   - ※ 予算アラートは「知らせる」だけで、自動で止めはしません。Cloud Run の上限（同時に動く数 2）を設定で付けるので、
     大きくは増えない作りにします。
5. 教えてほしいこと: **プロジェクト ID**（例 `pokerapp-cloud-123456`。プロジェクトを選ぶ画面に出る英数字）。これは秘密ではありません。

### 1-2. Supabase（データベース）

1. <https://supabase.com/> で「Start your project」→ GitHub か メールで登録する。
2. 「New project」:
   - Organization: 自分の名前のもの（初回に作られる）
   - Project name: `pokerapp`
   - **Database Password**: 「Generate a password」で作った長いもの。**パスワード管理アプリかメモ帳に保存**（あとで 1 回だけ使う。チャットには貼らない）。
   - **Region: Northeast Asia (Tokyo)** ← 必ずこれ
   - プラン: いまは **Free** で大丈夫
3. 作成には 1〜2 分かかります。
4. 教えてほしいこと: **プロジェクトを作ったこと**だけ（接続の情報は 2e で、Secret Manager に直接入れてもらいます）。

#### Free と Pro について

| | Free（いま） | Pro（本物のお客さんのデータを入れる前に） |
|---|---|---|
| 料金 | $0 | 月 $25 から（約 3,800 円） |
| 止まる | 1 週間使わないと一時停止（再開はボタン 1 つ） | 止まらない |
| バックアップ | 自動では取られない | 毎日、7 日分 |

お客さんに閲覧リンクを渡し始める前に Pro に上げます（ADR-0067 D9）。

### 1-3. ドメイン（いまは不要）

最初は Google が用意する `https://〜.run.app` のアドレスを使います（HTTPS は自動）。
お店の名前の入ったアドレス（独自ドメイン）は、他の店に売る前に決めれば十分です。

## 2. クラウドに置く（2e で書き足す）

- API の有効化（Cloud Run・Cloud Build・Secret Manager・Artifact Registry）
- Secret Manager に入れるもの: データベースの接続文字列 / トークン署名の鍵 / 管理トークン
- Cloud Build のトリガー（GitHub の `stable` に進んだら自動でデプロイ）
- Supabase 側: 専用のデータベースユーザー、`pokerapp` スキーマ、RLS の確認

## 3. 店舗 PC をつなぐ（クラウドに置いたあと, 1 回だけ）

店舗 PC で、RDP でつないで PowerShell を開き、フォルダ（`C:\PokerHandLogger`）で実行します。

1. 店舗を作ってつなぐ（**管理トークン**を聞かれます。入力しても画面には出ません。保存もされません）:

   ```
   venv\Scripts\python tools\cloud_link.py link --url https://<クラウドの URL> --name "店名"
   ```

   クラウドが発行した**端末トークン**が `cloud_credentials.json` に保存され、`config.json` の `cloud.enabled` が true になります。
2. いますぐ 1 回送って確かめる:

   ```
   venv\Scripts\python tools\cloud_link.py push
   ```

3. 店舗サーバーを起動し直す（PC の再起動でも可）。以後 60 秒ごとに、変わったものだけを送ります。
4. 状態を見る: `venv\Scripts\python tools\cloud_link.py status`（最後に送れた時刻・送れていない件数・クラウドにある件数）。
   iPad などからは `http://<PC の IP>:8788/api/health` の `cloud` でも見られます。

困ったとき:

- 「端末トークンが違うか取り消されています」→ `tools\cloud_link.py reissue`（管理トークンで発行し直し。前のものは使えなくなる）。
- ネットが切れているとき → 店内はそのまま使えます。送れなかった分は、つながったときにまとめて送ります（最大 15 分おきに試す）。
- この PC のつながりを外す → `tools\cloud_link.py unlink`（クラウドの記録は残ります）。
