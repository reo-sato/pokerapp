## (a) 要約（最重要 5 点）

1. **v0 の失敗は全部「採点」ではなく「表せない」こと。** 店舗で外した 5/18 は 5 つとも N-best の外（再現済）。シミュレーションでも `missing=0.10` は 28→28（候補に入ったのも 28/60）。v1 の編集（無言アクション・語の削除・離脱=持ち上げ・ボタン）はこれを直接狙っており方向は正しいが、**探索空間 = engine の方針 × 編集**のままなので「到達できない真実」が残る（ボードの札の読み落とし・額の別候補・言い直し）。切り替え判定の前に「真実が表せるか / 探索が届くか / 採点が正しいか」の 3 分解を必ず出すこと（§5）。
2. **読み上げ集の p_miss（2.2%）は実卓に持ち込めない。** 09-29 の真のアクション 16 ハンド（今の「全部言う」運用）で、真のアクション数に対する読めた語の比は call 0.77 / check 0.83 / fold 0.80 / bet-raise 0.85（幻聴を含むので聞き落としの下限ではなく上限側、それでも 1 桁違う）。無言 check/call の確率は**実卓の真のアクションからしか較正できない**。これが MAP の正誤にいちばん効くパラメータ（§2）。
3. **採点式は「事前分布 π(A) と発話単位の状態」を足せば log 事後確率として筋が通る。** engine の補い・寄せ・読み替えを観測事象に写す対応は概ね妥当だが、(i) 同じ仮説に別コストの経路が 2 本ある（unresolved −3 と drop −4/−7）、(ii) 額の誤りが読み（fuzzy）と構造（snapped/rounded）で二重に罰される、(iii) 額を「寄せる」のは推定ではなく決め打ち、の 3 点を直す（§1）。
4. **N-best の softmax は今のままでは事後確率にならない。** 手置きの罰は log 確率でないので温度が任意、かつ真実が候補に無い質量（店舗 5/18・sim 34/120）を無視する。v0 の「次点との差」の AUC は 0.75（18 ハンド）で、誤り 5 つを全部拾う閾値（≤3.5）は正しいハンド 6/13 も要確認にする。温度 1 パラメータの較正 + 「候補外」バケット + 構造的な要確認理由が必要（§4）。
5. **切り替え条件「40 ハンドで live+5 ポイント・90% 以上」は検定として成立しない。** 対にした比較で +5 ポイントを有意に示すには「良くなった ≥6・悪くなった 0」が要り、真の改善 +5 ポイントなら期待 2 ハンド/40 → 約 120 ハンド必要。90% も 40/40 でないと下限が 90% を超えない。**「悪くなったハンド 0」＋「誤りは全部要確認が付く（未検出の誤り 0/40 = 上限 7.5%）」＋ 事前登録（コードと値のハッシュ固定）** に置き換える（§6）。加えて、いまの 18 ハンドは開発に使い切っており、真のアクションも記録を初期値に入れている（`ground_truth_ui.py` L398、ブラインドは 1/18）ので評価用には使えない（§7）。

## (b) 項目ごとの所見と推奨

### 1. 採点 = log 事後確率か／engine の補いの写像（重大度: 高）

**所見**
- 生成モデルとして書くと `log P(b) + log π(A|b) + Σ_t log P(e_t|a_t) + Σ_phantom log p_ph + Σ_s log P(離脱_s|A) + Σ log P(宣言|A) + 時刻項`。設計の式は **π(A) が無い**（平坦）。無言アクションは `log p_miss` で暗に罰されるが、「無言コール vs 無言フォールド」「無言 check-check の 1 ラウンド追加」の相対確率は π(A) が決める。平坦事前は合法列の数が額の分だけ膨らむので正規化もできない。最小の代替は**ゲーム木上のランダムウォーク** `π(a|s)=1/|legal(s)|`（正則・長い列を自然に罰する）。ポーカーの振る舞い事前（ベット直面時 fold/call/raise、非直面時 check/bet、額の格子）は Dirichlet(1) 平滑で真のアクションから作れるが、18 ハンドは 3 人卓の一人テストなので**弱い事前**にとどめる。
- 「余計な語」の補数項 `(N_tok − N_ph)·log(1−p_ph)` は定数 + 1 語あたり −log(1−p_ph)≈0.02 で無視可。長さの違う列どうしは、各アクションの観測項が「語あり／無言」で正規化されていれば比較可能（総和則 `P(語あり)+P(無言)=1` を守ること）。
- 対応づけの数: v0 は同じハンド記録に至る割り当てを max で畳んでいる（`_hand_key` で重複除去）。Viterbi として妥当だが、softmax の質量は「和」ではなく「最大」になる（§4）。
- engine の補いの写像:
  - `implied`（離脱前・ストリート前・宣言）→ `p_miss(check/call)` ✓。ただし `players_left_call` は「宣言で裏付け」= 無言 + 宣言尤度の**2 つの項**で表し、「confirmed なら罰なし」の特別扱いを消す。
  - `synth_silent_fold` → `p_miss(fold)·p_nodepart` ✓。
  - `check_facing_bet` / `*_illegal_to_call` → `p_sub` ✓。ただし「ベットが幻聴だった」別解が探索で届くことが前提。
  - `amount_snapped` / `no_amount_heard` → **不適切**。額の聞き違いは混同行列 `P(聞いた額 | 真の額)` で採点し、真の額は選択点（第 2 の耳の候補・音の近い数字・最小額）として探索する。「合法な最小額に寄せる」は決め打ちで、寄せた先が正しい保証がない。`rounded_to_bb` も同じ尤度の一部。v0 は `fuzzy/ambiguous_amount`（読み）+ `snapped`（構造）で**同じ不確かさを 2 回**罰している。
  - `unresolved`（betting_over / no_active_hand）→ 幻聴 ✓。ただし v0 では同じ仮説（その語は余計）が drop（−4/−7）と unresolved（−3）の**2 経路・2 コスト**で表せる。v1 は「反映できない語 = 幻聴 = log p_ph」で 1 本化し、(A, 対応) が同じ候補は重複除去する。
  - `estimated_winner` / `mucked_stronger` → 終端制約 P(勝者観測 | A, 札)。妥当。
- label bias は無い（採点はハンド全体の和）。問題は「engine の決定的な補いが仮説の一部でない」= 表現力の制約（§5）。

**推奨**: π(A) を入れる（まずランダムウォーク）。額は選択点に。幻聴の経路を 1 本化。総和則を単体テストで固定（各アクション種別で `Σ_観測 P(obs|a)=1`）。

### 2. 較正（重大度: 高）

- **出所の割り当て**: 語の種類の取り違え `p_sub`・幻聴 `p_ph`・額の混同行列 → 読み上げ集（519 語）。無言 `p_miss(種類)` → **実卓の真のアクションのみ**（読み上げ集は「間があり全部読む」ので下限にしかならない）。`p_lift` / `p_nodepart` / `p_btn` → 店舗ハンド。振る舞い事前 → 店舗ハンド（弱）。温度 τ・要確認閾値 → 開発用ハンドで当て、前向きの新データで検証。
- **精度**: 2.2%（n=369）の SE は ±0.8%、`p_sub` 1/519 は上限 1%、額 12/約 240 は 5%±1.4%。一方 `p_lift` 9/31 は ±16%、`p_btn` 1/18 は区間 0.1〜26%。後者 3 つは**桁しか分からない**ので Beta 事前（例 `p_lift ~ Beta(2,5)`、`p_btn ~ Beta(1,10)`）を置き、MAP が区間内で反転しないかの**感度掃引**を必ず行う。
- **離脱データの偏り（検証済）**: fixture の `leave` は engine が 3 秒以上の不在と判断して出した信号で、`return` 信号は 0 件（短い持ち上げ・反映前に戻った離脱は sidecar に残らない。`_observe_return` は無音で消す）。よって「離脱 29 のうちフォールド 20」は**フィルタ後の割合**で、持ち上げは過小評価されている。v1 の `p_lift` は卓状態の履歴（生の在否遷移）から数え直すこと。
- **一人テストの偏り**: 17/18 ハンドが 3 人以下、持ち上げるのもディーラーも同一人物。5〜6 人卓・別の配り手のセッションで `p_miss` と `p_lift` は**別の値**になる前提で、セッション（配り手）ごとの層を持つ。
- **感度（MAP 正誤に効く順）**: (1) `log p_miss(check/call) − log p_ph`（語を捨てるか無言を置くかの分岐）、(2) `log(1−p_lift) − log p_nodepart`（離脱をフォールドにするか）、(3) 額の混同行列の似た音の重さ（2↔6 など）。絶対値より**この 3 つの比**が結果を決めるので、掃引はこの 3 軸で。
- **分け方**: 09-27/09-29 の 18 ハンド + 読み上げ集 + 台本 = 較正・開発。これから録る（コードと値を凍結したあとの）ハンド = 評価。評価データは一度使ったら開発に回さない（回すなら次の評価データを新規に取る）。

### 3. 独立性の破れ（重大度: 中）

- **発話単位**: 発話 u ごとに隠れ状態 `z_u ∈ {正常, 丸ごと落ち, 丸ごと幻聴}` を置き、語の事象は z_u 条件付きにする。3 つの確率は読み上げ集の句単位の結果（全語が消えた句・出力が無関係な句）から直接数えられる。店舗の書き起こしは 808 行のうちアクション行 194・アクションでない発話 353・定型幻聴 131 なので、実卓では「余計な発話」の方が多い。
- **2 つの耳**: 掛け合わせない方針は正しい。さらに一歩進めて、**閉じた語彙 + OTHER の 1 つの事後分布**にする: `P(語|音声) = softmax_τ({候補の logp} ∪ {Whisper の読みを候補に追加} ∪ {OTHER = 自由に聞いた文の logp + オフセット})`。τ とオフセットの 2 パラメータを読み上げ集で最尤で当てる。Whisper の確信度は使わない（分布が重なる、既知）。
- **人ごとの癖**: 席 s の `p_lift,s` を経験ベイズで `(α + その席の持ち上げ回数)/(α+β + 離脱回数)`（前のハンドの MAP から更新）。セッション内で自然に学ぶ。
- **RFID と発話の時刻**: 独立ではなく「フォールドの発話の前後 W 秒に離脱」の窓尤度にする（設計の窓の方針で可）。

### 4. N-best の softmax と要確認（重大度: 高）

- 前提: スコアが log 確率の尺度であること（§1 を直せば近づく）。それでも近似なので**温度 τ を 1 パラメータで較正**（MAP の正誤を目的変数に log-loss 最小化。18 ハンドでも 1 パラメータなら当たる）。
- **候補外の質量**: `P(真実 ∉ N-best)=λ` を開発データで推定して事後に混ぜる（店舗では 5/18）。これを入れないと MAP の確率は常に過大。
- 信頼度図は 18 ハンドでは無理。代わりに**リスク‐カバレッジ曲線**（margin で並べ、累積誤り）と AURC を出す。v0 の margin は誤り 5 ハンドが 0.53〜3.5、正しいハンドに 0.09/0.77/1.14 が混じり AUC 0.75。表現できない誤りは margin に出ないので、**要確認は margin と「構造的な理由」の OR** にする: 無言を置いた・離脱を持ち上げにした・語を捨てた・額を候補で置き換えた・宣言と人数が合わない・ボードのストリートより前で終わった・離脱がフォールドに対応しない。
- 近い重複: 記録が同じ候補は和にする（max でなく logsumexp）。額だけ違う候補が並ぶと 1 位の確率が割れて見えるので、要確認の判定は「記録の同値類」で行う。

### 5. 探索（重大度: 高）

- **3 分解を報告する**: 真のアクションごとに (i) 編集で表せるか（オラクル編集列を構成）、(ii) 表せるなら `score(truth)` と `score(MAP)` の比較（truth が高い = 探索誤り、低い = モデル誤り）、(iii) 表せない = 表現力の誤り。v0 の実測: 店舗 5/5 が (iii)、台本 3/3 が (iii)、sim は候補に入って外した 24/86 が (ii) = モデル誤り 28%。この 3 つの数字を bench に常設する。
- **編集の追加候補**（既知の失敗から）: ボードの札の読み落とし（RFID に無い札 1 枚を許す）/ 額の別候補 / 言い直しの併合 / 手番より前の席の無言フォールド（席指定なし）。
- **再生ベースの妥当性**: 統計的には「engine の方針で条件付けた再ランキング」であり、方針が誤った所（例: 額の寄せ）は編集で覆せない限り直らない。直接の整列デコーダ（状態 × 語 index の DP）は厳密で速いが、engine の規則の二重管理になるという ADR の判断は妥当。折衷: **チェックポイントからのハンド単位の再生**（`_take_checkpoint` は既にある）でビームを伸ばし、セッション全体の再生を繰り返さない。B=10・深さ 4・編集候補 10 でセッション再生なら約 400 回 → 1 分の制約を超えるので、ここが実装上の要。
- ビーム幅の誤りは「B を 2 倍にして MAP が変わる率」で測る（決定的なので再現可能）。

### 6. 評価プロトコル（重大度: 高）— §(d) に集約

### 7. その他の統計的な穴（重大度: 中〜高）

- **真のアクションの独立性**: 入力画面はブラインドでなければ記録を初期値に出す（L398）。ブラインドは 18 のうち 1 で、それは誤っていて記録で直された。2e658148 は「記録をオーナーが確認」= 記録そのもの。測る側の誤りが誤り全体の約 17%（自前の集計）。評価用ハンドは**全部ブラインドで入れ、照合の変更を記録し（`reconciled` は既にある）、食い違いは音声/映像で裁定**。
- **持ち点の持ち回り**: 各ハンドを記録の `stack_start` から再生し、真のアクションのオールイン額も記録の持ち点で決めている。前のハンドの記録が誤っていると両者が同じ誤りを共有し、一致が水増しされる。評価では持ち点も真のアクション側で確定する。
- **どのハンドに真のアクションが付くか**: 覚えているハンド（d0f055fb 7 は除外、6・9 は無し）。難しいハンドが落ちる方向の選択。評価セッションは**全ハンド**に付ける。
- **シミュレータ**: 誤りが発話ごと独立・語の種類に一様、第 2 の耳の候補に**常に真の語が入る**（`_ear` の実装）、RFID 無し、雑談率 15%（実測は発話の 6 割超が非アクション）。候補入り 86/120 は楽観。読み上げ集の混同行列と発話単位の状態で生成し、離脱/持ち上げも入れた上で「探索誤りの診断と感度」に限定（精度主張に使わない方針は正しい）。
- **物差し**: `hand_fully_correct` はホールカードを見ず、ボードは順不同一致、street が無ければ比べない。全か無かで情報量が少ないので、副指標として「正すのに要る編集数（挿入/削除/置換）」を並べ、対の Wilcoxon で見る。

## (c) v1 の最小推奨モデル

ハンドごと、観測 O = (発話列 U, RFID, 宣言, ボード時刻, 操作)、隠れ量 (b, A, 対応, z):

```
log P(b, A, 対応, z | O) = const
  + log P(b)                                  ボタン: 記録 1−p_btn, 隣 p_btn/2 ずつ      [店舗, Beta(1,10)]
  + Σ_t log π(a_t | s_t)                      事前: 1/|legal(s_t)|（後で Dirichlet 平滑の振る舞い表）
  + Σ_u log P(z_u)                            発話状態 {正常, 落ち, 幻聴}                  [読み上げ集 句単位]
  + Σ_t log P(e_t | a_t, z)                   語あり: (1−p_miss(a))·[(1−p_sub)·P_amt(â|a) or p_sub]
                                              無言:   p_miss(a)（bet/raise は ε + 額不明フラグ）
                                                      p_miss(check/call/fold) は実卓の真のアクション [Beta(1,10)]
                                                      p_sub, P_amt（似た音の混同行列）は読み上げ集
  + Σ_余計な語 log p_ph(長さ, 確信度)            読み上げ集 11/519 + 店舗の非アクション発話
  + Σ_s log P(離脱_s | A)                      フォールド席: 離脱 1−p_nodepart / 無し p_nodepart
                                              非フォールド席: 離脱 p_lift,s（戻り: 軽、終了まで戻らず: 重）
                                              p_lift,s = (α+lifts_s)/(α+β+deps_s)、α,β は生の在否遷移から
  + Σ 宣言 log P(N | A)                        合う 1−p_np / 合わない p_np                   [読み上げ集 + 店舗]
  + Σ_t log 1[a_t の時刻 ∈ ストリート窓]        ボード時刻をハード制約（±1 秒の余裕）
音響: P(語 | 音声) = softmax_τ( 候補 logp ∪ Whisper の読み ∪ OTHER )   τ, オフセットは読み上げ集で最尤
事後: P(hand_k | O) ≈ (1−λ)·softmax_τ'(logsumexp over 同じ記録) 、λ = P(真実 ∉ N-best)（開発データ）
```

パラメータは 12 前後。値は全部 `params_hash` に入れ、Beta 事前の (α,β) も記録する。

## (d) 評価と切り替え条件の推奨

- **主指標** 全部正しいハンドの割合（ハンド単位、出所ごと）。**副指標** 正すのに要る編集数、要確認の再現率（誤りのあるハンドのうち要確認が付いた割合）と負担（要確認アクション割合・ハンドあたり件数）、3 分解（表現/探索/モデル）。
- **区間**: Wilson。12/18 = [0.44, 0.84]、13/18 = [0.49, 0.88]。v0 の +1 ハンドは McNemar 正確 p=1.0（差は示せない）。
- **対にした検定**: 同じハンドで live / 推定。悪くなった 0・良くなった b なら正確二項 p = 2^−b（片側）: b≥5 で 0.03。
- **データ**: 較正 = 既存 18 + 読み上げ集 + 台本 + sim。評価 = 凍結後に録る新規ハンド（全ハンド真のアクション、ブラインド入力、5〜6 人卓 ≥2 セッション、配り手はオーナー以外を含む）。評価に使ったハンドは以後の開発に使わない。
- **切り替え条件（追記 1 §4 の置き換え案）**
  1. 事前登録: 評価セッション前にコード・`params_hash`・要確認閾値を固定し報告に書く。
  2. 安全: 対にして**悪くなったハンド 0**（40 ハンド）。「推定 ≥ live」は必要条件であって改善の証明ではない。
  3. 改善: 良くなった ≥5・悪くなった 0（p<0.05）。+5 ポイントの数値目標は**点推定の参考**にとどめる（有意に示すには約 120 ハンド）。
  4. 要確認: 40 ハンドで**誤りのあるハンドの 100% に要確認**（未検出率の上限 3/40≈7.5%）、要確認アクション ≤30%、ハンドあたり ≤2 件（オーナー基準）。
  5. 絶対水準: 90% は 40 ハンドでは検証不能。「40 ハンドで誤り ≤4、かつ全部要確認付き」を条件にし、正本化は表示運用 2 セッションで「訂正が要確認外に出なかった」ことで判定。
  6. 決定性（同じ入力 → 同じ結果）・1 セッション 1 分以内は維持。
