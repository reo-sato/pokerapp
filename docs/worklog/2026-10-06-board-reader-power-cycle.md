# 2026-10-06 ボードの真ん中のリーダーが読めない → ESP32 の給電アダプタを抜いて再起動で直った

## 経緯（店舗）

- オーナー: RFID のリーダーのコードが 1 本抜けた → 挿し直した（どのコネクタが使えないかの確認: #4・#11 は BUSY 線の
  不通で予備、ボードは #10・#12・#13）。
- そのあと「ボードの真ん中のリーダーが調子悪くて読めない」。`tools/rfid_relay.py watch` で、真ん中（`board [r9]` =
  コネクタ #12）の行が 1 つも出ず、真ん中に置いた札を左右（`r8`・`r10`）が端で拾った。`status` は「✓ board [r9]」
  （起動時に準備できなかったリーダーにも、ESP32 は「札なし」と答え続けるので、✓ はリーダー本体が動いている証拠に
  ならない。ファームウェアは準備できなかったリーダーを poll から外す = `pn5180_reader.c` の `dev == NULL`）。
- こちらの案内で「コードの挿し直し → ESP32 の USB の抜き挿しで再起動」→ 直らず。真ん中と右のケーブルを入れ替える
  （#12 ↔ #13）と、真ん中も右も読めなくなった。
- オーナーが **ESP32 の給電アダプタを抜いて再起動**すると読めるようになった。

## わかったこと

- この卓の ESP32 は給電アダプタから電源を取っているので、**PC との USB を抜き挿ししても ESP32 は再起動しない**
  （リーダーも準備し直さない）。リーダーの準備（`pn5180_init`）は起動時だけなので、動いている途中でコードが抜けた
  リーダー・挿し替えたリーダーは、**給電アダプタを抜いて再起動**するまで読まない。こちらの案内（USB の抜き挿し）は
  この構成では誤りだった。
- リーダー本体・コネクタ #12 の故障ではなかった（給電し直しで読めた）。

## 運用（あとで `docs/troubleshooting.md` にまとめる = §7b）

- リーダーのコードが抜けた・挿し替えた・読めないリーダーがあるとき: **ESP32 の給電アダプタを抜いて数秒待って挿す**
  → `tools/rfid_relay.py watch` で左・真ん中・右（`board [r8]`・`[r9]`・`[r10]`）と席に札を置いて確かめる。
- ボードのケーブルは元の位置（左 #10・真ん中 #12・右 #13）に。入れ替えたままでもボードの何枚目かは配った順で決まるが、
  配り直しの「同じか隣のリーダー」の判定は左から右の並び（config の順）を使う。
