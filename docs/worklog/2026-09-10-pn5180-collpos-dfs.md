## 実機結果（改良前 = commit `73ecd29`, 1 slot）

| 状態 | probe 最大 | 1 周 |
|------|-----------|------|
| カード無し | 1 | **15 ms**（目標達成） |
| 2 枚重ね | 5 | max 64 ms |
| **3 枚重ね** | **14** | **≈150 ms** |
| 1 枚を載せて動かす（`CCID_SLOT_COUNT=2` / ready 1 slot） | **16 = 上限** | min/avg/max = 6/72/160 ms |

- Stay Quiet は効いている（2 ラウンド目の root が NONE で終わる）。3 枚重ね・ちらつきは解消済み。
- 3 枚の内訳（手計算が実測と一致）: UID を **LSB-first** で見ると先頭バイトが `2E`(…1D:2E) /
  `B3`(…35:B3) / `CE`(…00:CE) で、**`2E` と `CE` の下位 5 bit が同一**（0,1,1,1,0）。1 bit ずつ
  伸ばす DFS では衝突が 6 段続き、各段で「札のいない兄弟枝」を RX timeout(10 ms) いっぱい待つ →
  root 1 + 衝突 6 + 空枝 NONE 5 + UID 3 + 確認 NONE 1 = **14 probe**。
- 1 枚で 16 に張り付くのは、**「バイトはあるが CRC/protocol error（衝突フラグ無し）」を COLLISION に
  倒していた**ため。磁界の縁のノイズ受信のたびに DFS が 2 分木を上限まで広げる（ノイズは子枝でも
  ノイズなので分割では消えない）。

## Goal

- 3 枚重ねで **probe ≤ 8 / 1 周 ≤ 60 ms（1 slot）**、11 台全載せで **1 周 ≤ 300 ms**。
- 1 枚しか載っていない reader が **ノイズで probe 上限に張り付かない**。
- 取得できる枚数・UID・host 契約（v1.1 §6/§7）・既定 off の切り替えは変えない。

## Expected Behavior

- **A（coll_pos DFS）**: 衝突応答から「最初に食い違ったビット位置」を取り、そこまでの共通 prefix を
  mask にして 2 分割する。両方の子に必ず札がいるので、空枝を RX timeout いっぱい待つ probe が消える。
  3 枚 = root 衝突 1 + 子衝突 1 + UID 3 + 確認 1 = **6 probe**、2 枚 = **4 probe**。
- **B（確認間引き）**: 1 ラウンド目で前回 cache と同じ集合が揃ったら、確認 root probe は
  5 poll に 1 回だけ。集合が変わった poll / 前回 0 枚 / カード無しは従来どおり毎回確認する。
- **C**: RX timeout 8 ms（応答は ≈5.5 ms で来る）。カード無しの reader 1 台 = 8 ms。
- **D（ノイズ）**: 衝突フラグ無しの壊れた受信は同じ node を 1 回だけ再 probe し、駄目なら NONE。
  DFS を広げないので 1 枚 + ノイズでも 2〜3 probe で終わる。
- 取得できる UID 集合・順序・CCID の Get UID バイト列は変わらない。

## Implemented Behavior

上記のとおり。**ESP-IDF がこの container に無いため実ビルド・実機検証は未実施**（スタブ・
フルコンパイルと register-level simulator で検証。下記 Test Results）。

実装上の判断:

- **RX_COLL_POS の基準は実機未確認**（フレーム先頭 = `flags DSFID UID` の bit 0 起点と仮定し、
  UID bit = `coll_pos - 16` とした）。`coll_pos >= 16` かつ「衝突ビットを含むバイトまで受信済み」
  かつ「取れた prefix が cur.mask の既知ビットと一致」の 3 条件を満たさなければ **fallback**。
  基準が違って pos がズレても、①ズレ先が全応答で共通のビットなら空枝が 1 本増えるだけ、
  ②行き過ぎて片方の枝を落としても **Stay Quiet + root 再 probe** が同じ poll で拾う（それも
  外れたら次の poll と UID 単位 hold）。つまり**正しさは落ちず効率だけが落ちる**設計にした。
  実機での確定用に、slot ごと最初の 3 回だけ生値を INFO で出す。
- **partial データは `readData` で読む**。PN5180 は衝突を含む部分バイトも `RX_STATUS` の
  受信バイト数に数えるので、`n >= 2 + pos/8 + 1` を確認してから `min(n,10)` byte 読む。
  衝突ビット以降のビットは不定として**使わない**（simulator ではそのビットを反転させて検証）。
- **衝突フラグが立っていない COLLISION 相当（CRC/長さ異常）では coll_pos を使わない**。
  受信データ自体が壊れているので prefix を信用できない。
- 実装 B の集合比較は「1 ラウンド目の検出集合」と「前回 cache（hold 中の UID を含む）」。
  hold 中の札が混ざっていれば「同じではない」= 確認を省かない（安全側）。
- `PN5180_FAST_CONFIRM_EVERY=0` で従来の「毎 poll 確認」に戻せる。

## Test Results

ESP-IDF が無いので実ビルドの代わりに以下（`gcc 13` + ESP-IDF/ドライバのスタブヘッダ）。

### 1. スタブ・フルコンパイル

- `CCID_SLOT_COUNT`(1/2/11/13) × `POLL_STATS_INTERVAL_MS`(0/10000) ×
  `PN5180_RF_OFF_BETWEEN_READERS`(0/1) × `PN5180_BUSY_VIA_MUX`(0/1) × `PN5180_TRY_ISO14443`(0/1) ×
  `PN5180_FAST_INVENTORY`(0/1) = **128 構成で警告 0 / エラー 0**（`-c -std=gnu17 -Wall -Wextra`）。
- 既定構成に `-Wshadow -Wundef -Wvla -Wformat=2 -Wpointer-arith -Wcast-align -Wstrict-prototypes
  -Wmissing-prototypes -Wswitch-enum -O2` を足しても **警告 0**。
- **`RX_COLL_POS_START/MASK` を持たないヘッダ**でもビルドできること（`#ifndef` fallback）を確認。

### 2. register-level simulator（実 `pn5180_reader.c` / `ccid_slot.c` をリンク、ASan/UBSan）

`sim_capture.c` に **RX_COLL_POS の模擬**（衝突時: `coll_pos = 16 + 最初に食い違う UID bit` /
受信バイト数 = 衝突ビットを含むバイトまで / 衝突ビットより前は正しい値・**それ以降は反転**）と
**ノイズ**（バイトはあるが CRC error・衝突フラグ無し）を追加。UID は実機と同じ 3 枚。

| シナリオ | probe | 結果 |
|---|---|---|
| 3 枚（`2E`/`B3`/`CE`, 下位 5bit 同一を含む）初回 poll | **6** | 3 枚とも取得 ✅ |
| 同 3 枚 定常 5 poll | 5,5,5,5,**6** | 確認 probe は 5 poll に **1 回だけ** ✅ / 3 枚のまま |
| 1 枚外した poll | 4 | **確認あり**（集合が変わったので間引かない）✅ |
| 2 枚の定常 poll | 3 | 確認省略 ✅ |
| 1 枚足した poll | 6 | **確認あり** + 3 枚取得 ✅ |
| coll_pos 無効（0xFF）で 3 枚 | **14** | fallback DFS で 3 枚（実機の probe 最大と一致）✅ |
| 2 枚 | 4 | 2 枚取得 ✅ |
| capture effect（衝突フラグ無しで強い方だけ）+ 3 枚 | 4 | Stay Quiet 再 probe で 3 枚 ✅ |
| ノイズ常時（1 枚） | **2** | 再試行 1 回で NONE 扱い、DFS を広げない ✅ |
| ノイズ断続（1 通目だけ壊れる） | **3** | 再試行で UID を取得 ✅ |
| 既存: capture 2/3 枚・quiet 失敗・UID 単位 hold（欠け 1〜3 回 / 復帰 / 全外し） | ≤ 16 | 前回同様 ✅ |
| `PN5180_FAST_INVENTORY=0`（ドライバ経路） | — | 同じ cache 形式・UID 単位 hold も同様 ✅ |

- ESP_LOGD を無効化したビルドで、`coll_pos=…` の **INFO は slot あたり 3 行**で止まることを確認。
- `sim_multi.c`（Stay Quiet も coll_pos も模擬しない旧 sim）でも Get UID のバイト列は不変で、
  fallback 経路が probe 上限内に収まることを確認。

## Mismatches Found During Testing

1. **ノイズ断続時の probe 数の見積り違い**: 「UID(2) + 確認(2) = 4」と予想したが実測 **3**。
   確認 root は「見つけた札が Stay Quiet で黙っている」ので応答が無く、ノイズも起きない（1 送信）ため。
   期待値をテスト側で 3 に修正した（firmware の変更は不要）。
2. **simulator のドライバ経路が「取りこぼし」を模擬していなかった**: `PN5180_FAST_INVENTORY=0` で
   UID 単位 hold の hold 切れテストが失敗していた（`drv_uids()` が `g_skip_tag` を無視して常に全枚数を
   返すため）。**HEAD の firmware でも同じく失敗する**ので本タスクの回帰ではないが、harness を
   直した（fast 経路と条件を揃えた）。

## Fixes Applied

1. simulator の期待値を 3 に修正（上記 1）。
2. simulator の `drv_uids()` が `g_skip_tag` を尊重するよう修正（上記 2）。fast/driver 両経路とも
   **失敗 0 件**。
3. 新しい probe 数アサーションは fast 経路専用なので `#if PN5180_FAST_INVENTORY` で囲った
   （ドライバ経路は probe を送らないため）。

## Remaining Gaps / Out-of-Scope

- [ ] **RX_COLL_POS の基準を実機で確定**する（本タスクの最重要の未検証点）。起動後 slot ごと 3 回の
      `reader N: coll_pos=%u（UID bit %d）, 受信 %u byte, cur.len=%u → 採用/fallback` を見る。
      2 枚重ねの root 衝突なら `coll_pos = 16 + (最初に違う UID bit)` のはず（bit0 で違うなら 16）。
      `fallback` ばかりなら基準が違う（生値が 16 未満 = UID 先頭起点）ので、`fast_fill_coll` の
      `- 16` を外す。
- [ ] **3 枚重ねの実機 probe / 1 周時間**（期待: probe ≤ 8 / ≤ 60 ms）と、`poll 統計` の
      `coll_pos fallback` / `ノイズ再試行` の値。
- [ ] **11 台全載せの 1 周 ≤ 300 ms**（段階 1 → 2 → 11 の実機検証は未消化）。
- [ ] `PN5180_FAST_CONFIRM_EVERY=5` の妥当性（capture で隠れた札の発見が最大 5 poll ≈ 1.5 s 遅れる）。
      置いた瞬間の検出は「集合が変わる poll = 必ず確認」なので影響しないが、実機で遅れが目立つなら
      3 に下げる。
- [ ] `PN5180_SPI_HZ` 1MHz → 5MHz、`PN5180_FAST_RF_CONFIG` の ASK100/ASK10 確定（前 worklog から継続）。
- [ ] host 側の contract v1.2（`FF CA 00 <k> 00` の P2 = 物理 reader index）は**別作業で進行中**。
      本タスクの変更は物理 reader 単位の inventory 内部なので直交するが、firmware 側の Get UID /
      slot 構成の追随はそちらのタスクで行う。
