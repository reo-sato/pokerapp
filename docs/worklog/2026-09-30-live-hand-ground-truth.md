# 2026-09-30 進行中のハンドを真のアクション入力の画面に出す（フロップから）

## Goal

オーナー: 「ハンド進行中に真のアクションを入力したいので、フロップがディールされるタイミングで UI に表示するように
してください」。

前は、画面に出るのはハンドの記録（`logs/<sid>.json`）に入った = 終わったハンドだけだった。

## 作り

- **ロガー**（`IntegrationThread(live_hand=True)`、CLI と GUI のロガーだけ）:
  - フロップが配られた（ボードが 3 枚 / ストリートがフロップ以降）ハンドの、ここまでの記録を
    `logs/<sid>.live_hand.json` に書く（`JsonWriter.write_live_hand`）。形は確定したハンドと同じ（勝者・結果は無し）
    に `street`・`in_progress` を足したもの。
  - 変わったとき（ストリート・アクションの数・ボード・手札・ボタン）だけ書き直す。run() の 1 周ごとに確かめる。
  - ハンドが終わったら消す（`_finalize_hand` の書き出しのあと。終了 `q` で閉じるハンドも同じ）。フロップの前・
    ハンドの外でも消す。
  - replay・テストは書かない（既定 `live_hand=False`）。
- **画面**（`tools/ground_truth_ui.py`）:
  - `_load_live_hand`: 進行中のファイルを読む。もう確定したハンド（消す前に読んだ）は無視する。
  - 一覧: いちばん上に「進行中（フロップ）」の行。集計（一致の率）には入れない。セッションの一覧には出ない
    （`x.live_hand.json` はセッションではない）。
  - 開く: 確定したハンドと同じ（`_get_hand` が進行中のハンドにも答える）。発話と札の流れは、いままでの分をすべて。
  - 進行中は、途中で保存してもブラインドのまま（記録を見ずに入れ続ける）。照らし合わせはハンドが終わってから。
  - 保存: 「記録どおり」は 400（記録が途中）。「保存」は受け、一致の計算はしない（記録が途中なので）。勝った席が
    未定でも確かめない。保存したら一覧に戻り「途中まで保存」。
  - ハンドが終わると、同じハンド番号の真のアクションとして残り、いつもの照らし合わせ（ブラインド→照合）になる。

## 確かめたこと

- ブラウザ（ヘッドレス Chromium, iPhone の幅）: 一覧を開いたあとに進行中のファイルができる → 6 秒以内に
  「進行中（フロップ）」の行 → 開くと「このハンドは進行中です（フロップ）」、「記録どおり」のボタンは無い → 行を足して
  保存 → 一覧に「途中まで保存」。保存した真のアクションはブラインド（`blind_entry` 付き）で、ボードはフロップの札。

## Remaining

- 開いている間にターン・リバーが配られても、ボードは開いた時点のまま（開き直すと出る）。アクションのストリートは
  入れた列から自動で決まるので、入れるのには困らない。
- ハンドの途中で保存したブラインドの内容は、そのハンドの最後まで入れていないことがある（「記録を見ずに入れた内容」の
  測り方は、ハンドの途中までの分を含む）。
- 進行中のハンドの訂正（staff の訂正パネル）は付けない（終わったハンドだけ）。
