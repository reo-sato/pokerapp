## 並行か順番か（検討）

- B の ① オラクル（`tools/oracle_estimator.py`、別のセッション）は対応づけの部品を作らず、推定器の直しの語彙の中で真に寄せて探す。
  真の説明が出るのは真に届いたハンドだけで、その説明は今の値の点で選ばれる。F1 が要るのは値に依存しない対応づけを全ハンドで。
  → 部品は重ならない（台帳 §3-6 に書いた）。F1・F2 は並行でよい。
- F3（差し替えの感度）・F4（値の提案）はオラクルの「点で負けた群」で順を決める。誤りの大半は「表せない」なので、値を変えて効く
  上限もオラクルが決める → 待つ。

## 実装

- `tools/count_penalties.py align`: 窓の発話を読みの選択肢ごとに語の列にし、真の行と単調に組む動的計画法（行 = 語と組む / 言われない、
  語 = 行と組む / 余計）。組める条件 = アクションの群が同じ・話し始めがそのストリートの札の 3 秒前より後・次の札の 3 秒後より前。
  点 = 種類と額まで合えば 30・額かチェック ↔ コールだけ違えば 20、同点は音の証拠の強い読み（Whisper > ライブの規則 > 短い語の分類器）。
  札の離脱は真のフォールドに組み（戻らなかった離脱・声に近いもの）、残りを降りたあと / ハンドの終わり / 持ち上げに分ける。
- `count`: README §3 の値ごとに今 / 数えた値 / 区間 / x / n（層 = データ × 卓の人数）。`--md`・`--json`。
- テスト `tests/test_count_penalties.py`（15 件。うち 1 件は開発データ 845da8e6#1 の対応づけを固定 = slow）。

4. ベット ↔ レイズを同じ種類に（額だけの語は「ベット」と読む = 15cad555#3）。
