# 2026-09-27 ロードマップ S2 — 聞き取りの採点

## Goal

ADR-0056 追記 1 の S2。オーナーの質問「表記揺れレベルの聞き間違いは一個ずつ潰すしか無いか」への答え（音の近さでの
照合・保存した音声の採点し直し）を実装する。オーナーの「進めてください」を受けて実装。

1. 辞書に無い書き起こしゆれを、片仮名の語とアクションの語の音の近さで読む（ライブの読み取りに入れる）。
2. 保存した発話の音声を店舗 PC の Whisper で採点し直し、別候補と候補の文の確からしさを残す（S3 の推定器の入力）。
3. 評価ツールで、書き起こしを今の読み取りで読み直した再生・採点し直した文での再生を真のアクションと比べる。

## Changed files

- `audio/phonetic.py`（新規）: モーラ列（子音・母音・長音/促音/撥音。エイ・オウ・同じ母音の続きは長音 = 「レイズ」=
  「レーズ」）、置き換えの重さ（有声・無声の違い 0.3 / 近い子音・近い母音 0.4 / ほか 0.8、上限 1）、長音・促音・
  撥音の有無 0.5、母音だけの拍 0.6、語尾の脱落 0.6、語頭の無関係な音 ×1.5。距離 = 重さ / アクションの語のモーラ数。
  しきい値 3 拍 0.2 / 4 拍 0.35 / 5 拍以上 0.45、意味の違う語との差 0.15 以上。照合する語 = `ACTION_KEYWORDS` の
  片仮名の語（bet/call/raise/check/fold/allin/showdown/heads_up、2 拍の語とマックは除く）+ チェックアラウンド。
  アクションでない語（卓の用語・相づち・役名・勝者/チョップ/マック）にいちばん近ければ読まない。`rank` は全候補の距離。

## Expected vs implemented

- 期待（ロードマップ S2）: 音の近さの照合 + 店舗 PC での強制アライメント・N-best + 評価（テキストの読み / 採点の
  1 位 / N-best）。
- 実装: 採点は `align` ではなく、文を与えた生成の各ステップの分布から測った（全語彙で正規化された確率になり、
  文のあとの「終わり」の確率も同じ呼び出しで取れる。`align` は終わりと特殊トークンを除いて正規化する）。評価は
  「採点の 1 位で読み直した再生」まで。N-best 全体を使うのは推定器（S3）で行う（どの候補を選ぶかは卓の流れと
  合わせて決めるもの）。

## 確かめたこと

- **店舗の書き起こし全体**（2 つの zip のすべての発話）で、変わったのは 3 発話だけ: 「ここまでのヘッドゾップです」→
  ヘッズアップ、「フォールド、フォール」→ フォールド 2 つ、「フォール」→ フォールド（すべて要確認）。会話・卓の用語・
  「トーン」「トップ」「フローク」「ローピック」「マッケー」は読まないまま。
- **店舗で辞書に足したゆれ 14 個**（ベッド・ゴール・ホールド・フォルド・オーリン・ソーダウン・ヘッドアップ・
  ヘッドホップ・ヘッドロップ・ヘッドゾップ・チッカーランド・チェックアランド・チェックアウンド・フォール）は、
  辞書から外して正準の語だけにしても音の近さで全部読める（テストで固定）。最初の版は相づちの候補に
  「チェックアウト」を入れていてチェックアウンドを読めなかった → 外した。全体テストで「ホールドする」（会話の
  動詞）を読んでいた → 4 拍以下の語は辞書の短い語と同じく前後が区切りのときだけにした。
- **Whisper の呼び方**（ここでは Hugging Face からモデルを取れない）: 重みが乱数の小さな Whisper（CTranslate2 の
  WhisperSpec に乱数の重み + 文字単位の tokenizer.json）を作り、faster-whisper 1.2.1 / CTranslate2 4.8.2 で:
  候補をまとめた採点と 1 つずつの採点が完全に一致 / 生成の各ステップの分布が `align` の確率（テキストの語彙で
  正規化し直す）と 1e-6 で一致 = ステップの位置合わせが正しい（ライブのプロンプト付きでも）/ 「終わり」を出した
  ステップの分布も返る（終わりを強くしたモデルで確認）/ 店舗の zip の WAV で最後まで動く、を確かめた。
- **評価ツール**: 店舗の 2 回目の zip で、書き起こしを今の読み取りで読み直すと 5 セッションで変わるハンドが出る
  （記録のあとに入れた読み取りの修正 = シーン・参戦・発表・疑問文のあとの額・会話の中のコール・ヘッドアップ・
  音の近さ がすべて効く。記録したときの読みと今の読みが違う発話を 1 つずつ確かめ、読み直しの仕組みによる差は無い）。
  8d08c010 のハンド 3 はボードの 1 枚目も変わる: 読み直しでハンドが長く続き、記録したときの古い RFID の解釈
  （ハンドのあとの札の読み直しを差し替えとして出していた。片付けの検出で直した挙動）がそのハンドに効くため。
- 全体 1832 passed / 6 skipped、ruff clean。

## Remaining gaps

- 本物の Whisper（medium）での採点は店舗 PC で動かす（1 発話あたりの時間・別候補の中身はまだ見ていない）。
- 採点の効果（採点し直した文の方が真のアクションに合うか）は、真のアクション（S1）がたまってから測る。
- 仮名の額（「ロープヘッグ」= ロッピャク）は音の近さの対象外（数の読みの照合は別の仕組みが要る）。
- 「オーリー」はオーライ（相づち）とオールインの間で決めない（読まない）。
- 次は S3（推定器 v0: 別候補・音の近さ・札の離脱を選択点にしたビーム探索）。
