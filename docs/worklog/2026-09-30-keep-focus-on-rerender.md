# 2026-09-30 入力中にキーボード・ロールダウンが消える（画面の作り直し）

## Goal

オーナーの報告（iPhone の画面録画つき）:「UIでロールダウンやキーボードが消えちゃう　前にセッションを選ぶロールダウンでもこの症状があった」。

## 原因

- 録画は読み上げ集の画面。「読む人」の欄を押すとキーボードが出て、約 1 秒で消える。
- 読み上げ集の画面は 2 秒ごと（読んでいる間は 0.4 秒ごと）に状態を取りに行き、そのたびに画面全体（`innerHTML`）を
  作り直していた。入力中の欄も作り直されるので、フォーカスが外れてキーボードが閉じる。打ちかけの文字も消える
  （欄の値は `onchange` = 欄を離れたときにしか覚えていなかった）。
- 真のアクション入力の一覧も 5 秒ごとに読み直して作り直す → セッションを選ぶロールダウンが閉じる（前の報告）。
  編集の画面も、手番の確認（行を変えたあと裏で問い合わせる）の結果で作り直す → 別の欄（メモ・額）に移っていると
  キーボードが閉じる。
- 台本の画面は 3 秒ごと。メモの欄（textarea）だけは作り直さないようにしてあった。

## 直したこと

3 つの画面で同じ規則にした: **文字の欄・ロールダウンを触っている間は、裏で届いた結果で画面を作り直さない。
離れたら（`focusout`）作り直す。**

- `editing()`: いまフォーカスがある要素が画面の中の SELECT / TEXTAREA / 文字の INPUT か（チェックボックス・ラジオ・
  ボタンは含めない = それらは押したときに作り直す）。
- 読み上げ集: 読み直し（`poll`）は `renderWhenFree()`。名前の欄は `oninput` でも覚える。
- 台本: textarea だけの判定を `editing()` に。
- 真のアクション入力:
  - 一覧の 5 秒ごとの読み直しは、入力中は飛ばす。結果が届いたときに入力中なら、離れてから作り直す。
  - 手番の確認の結果は `whenFree(renderEdit)`。
  - メモは `oninput` でも覚える。
  - 額の欄から「追加」したときは、欄を離れてから作り直すので、追加した行がすぐ出る。
  - 利用者の操作での作り直し（セッションを選んだ・行を消した など）は従来どおりすぐ行う。

## Test results

- ブラウザ（Chromium, Playwright）で確かめた:
  - 読み上げ集: 名前を打っている間に読み直しが 2 回来ても、欄と文字が残る。離れたら作り直り、打った名前も残る。
  - 一覧: ロールダウンを開いている間は、5 秒の読み直しが来ても残る。離れたら読み直す。
  - 編集: メモを打っている間に手番の確認の結果が届いても、欄が残る。離れたら作り直し、メモも残る。
  - 額の欄から追加すると、行がすぐ増える。
  - 直す前のコードでは同じ確認が失敗することも確かめた（「名前の欄が作り直された」）。
- 画面の中身の回帰テスト 3 件を追加した（`tests/test_read_corpus.py`・`tests/test_test_script.py`・`tests/test_tools_ground_truth_ui.py`）。
