# 2026-05-22 — Phase 5-K: round close 自動検出によるストリート自動推移

## Context

ユーザー報告 (live test, 15:59 セッション):

```
15:59:22  [preflop] 席2 SB_POST  1  pot=1
15:59:22  [preflop] 席3 BB_POST  2  pot=3
15:59:32  [preflop] 席1 raise    5  pot=8
15:59:37  [preflop] 席2 call     4  pot=12
15:59:41  [preflop] 席3 call     3  pot=15
15:59:51  [preflop] 席1 bet     10  pot=25  ⚠要確認
```

3-handed で 席1 raise / 席2 call / 席3 call の後、preflop は全員 contrib=5 で
閉じているはずだが、`gs.street` は preflop のまま貼り付いた。原因:

- `_try_advance_street_from_rfid` は board card 検出が条件 (= RFID 必須)
- 音声経路にも `advance_street` keyword は無い
- manual input には street advance トリガが無い

結果として 席1 が次の入力 (= 本来 flop の opening bet になるべき "bet 10") を
preflop の再 open として扱い、`bs.is_opened=True` + action=bet で
「bet vs raise mismatch」を立てて `⚠要確認` を出していた。

CLAUDE.md の Phase 5-I scope-out に「manual action からの round close 判定は
audio 経路にも実装されていない既存仕様」と書いていた箇所。ユーザー希望で
オプション (2) "round close 自動検出" を実装する。

## Decision

`BettingState.is_round_closed()` を導入し、`bs.update_after_action` の直後
(audio / manual) で round close 判定 → 順方向 1 街 advance。

### Round close 判定条件

`BettingState.is_round_closed() -> bool` の真理値:

1. `is_initialized=True` (= hand state machine が走っている)
2. `live = active_seats - folded_seats` の人数 >= 2
   (1 以下は fold_win 待ちなので closed 扱いしない)
3. `must_act = live - all_in_seats` の全 seat について:
   a. `player_contrib_this_street[seat] == current_bet`
   b. `seat in acted_this_street` (= voluntary 行使済み)
4. `must_act` が空 (= 全員 all-in) なら (3) を vacuously True

### acted_this_street の semantics

- voluntary action (raise / call / check / bet / fold / allin) で
  `update_after_action` から `.add(seat)` する
- SB_POST / BB_POST (`_record_post`) では **追加しない**
  → preflop everyone-limp 時に BB の option が消化されるまで closed にならない
- `reset_for_new_street()` / `reset_for_new_hand()` で `.clear()`

### Auto-advance のスコープ

- 順方向のみ: preflop → flop → turn → river
- river close は **showdown 待ち** (= winner 音声 / RFID で finalize)、auto-advance しない
- 1 action あたり 1 街進行のみ (all-in showdown のマルチ街 escalation は将来)

### 呼び出し点

- `_handle_manual_action_event`: `bs.update_after_action` の `else:` 直後
- `_handle_audio_event`: `bs.update_after_action` の直後 (gs.apply_action 成功時のみ)

## Alternatives considered

- **GUI ボタン「次のストリート」** (option 1): 最小変更だが押し忘れ運用に依存。
  ユーザーが (2) を選択
- **音声キーワード ("フロップ" / "ターン" / "リバー")** (option 3): RFID 無し
  ディーラーには有効だが、誤認識で勝手に進む懸念。本フェーズ未対応 (将来 candidate)

## Out of scope

- **音声キーワード ("フロップ" / "ターン" / "リバー") による明示的 street 進行**:
  RFID 無し環境向け。将来 candidate (= speech_normalizer の `action_aliases` +
  engine の `advance_street` handler)
- **all-in showdown のマルチ街 escalation**: 全員 all-in で残ストリートを
  一気に飛ばす最適化。現状は 1 action あたり 1 街のみ。next action が来ない
  ので showdown に到達しない。Phase 5-K の round close で `must_act が空`
  パターンが closed になることは確認済みだが、その後の自動推移ループは未実装
- **river close → showdown 自動遷移**: river の round close で `gs.street`
  を SHOWDOWN にすると、winner が来る前に hand が「終わった」ように見える
  GUI 表示問題が出る。意図的に河止め
- **HU (heads-up) のテスト**: 3-handed のみ。`is_round_closed` は HU でも動く
  はずだが (compute_blinds で BTN=SB、preflop first actor=BTN、postflop first
  actor=BB)、テストは無い。動作確認は将来
- **fold で actor が round 末端まで進んだケース**: 例えば preflop で raise →
  call → fold だと live=2 で closed (raiser と caller が contrib=raise_to で
  両者 acted) になる可能性。仕様としては正しい (= 残り 2 人が contrib 揃って
  acted なら closed)、e2e テストでカバー済み
