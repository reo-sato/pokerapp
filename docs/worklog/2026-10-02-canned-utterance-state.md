# 2026-10-02 決まり文句になった発話を推定器の「発話単位の状態」に

## Goal

オーナー: 「決まり文句に置き換わった発話を推定器が判断する部分の実装も進めてください」。作業計画の監査（2026-10-01）が
最優先に挙げた推奨: 「決まり文句に置き換わった発話の扱いを、ライブの規則でなく推定器の『発話単位の状態』として入れる。
P(アクション | 決まり文句, 耳の候補あり) を全セッションで数え直し、閉じないラウンド・言われないベットの罰と組み合わせて
推定器に決めさせる（ライブは保守的なまま）」（`docs/worklog/2026-10-01-plan-audit.md` §6 の 1）。

## 数え直し（全セッション）

対象: 店舗の fixture 7 セッション（9/27〜29）・9/30 夜のログ 1・10/01 の練習 6（真のアクションあり）・台本 7（9/30 の 6 と
10/01 13:55。正解は台本）。決まり文句 = 書き起こしが `is_prompt_echo`（定型の幻聴・プロンプトの繰り返し）。

数え方: ハンドごとに、真のアクションの並び（配る人が言う行 = `eval_store.truth_tokens`）と、ハンドの時間帯の発話の並び
（ライブと同じ規則で読む）を順に対応づける。**読めた語の対応を最大にしたうえで**、残った真のアクションの穴を、ライブで
読めなかった決まり文句の発話（どのアクションにも合う 1 枠）が埋めるかを見る（最初は穴を埋める点を高くしすぎて、読めた
語の対応を押しのけていた = 9/30 の 322f4a78 で、ハンドが終わったあとの笑い声の決まり文句が「500」「フォールド」を埋めた）。

| | 決まり文句（ライブで読めない） | うち穴を埋めた |
|---|---|---|
| 全部 | 93 | 20（0.22） |
| 店舗の fixture（9/27〜29 の一人テスト） | 60 | 6（0.10。9d1d8536 ハンド 4 = 10 分のハンドの雑談の 40 のうち 1） |
| 9/30〜10/01 のログ（卓） | 26 | 11（0.42） |
| 台本 | 7 | 4 |
| **読めた賭けの語から 15 秒以内** | **51** | **17（0.33）** |

- 穴を埋めた 20 のうち 17 が読めた語から 13 秒以内。遠い 3 つ（58・278・286 秒）は偶然の一致とみる → 推定器で
  選択点にするのは 15 秒以内の決まり文句だけ（`canned_near_sec`）。
- 対照: 決まり文句でない読めない文（雑談）を同じ数え方にすると、15 秒以内で 66/225（0.29）が穴を埋める。雑談にも崩れた
  アクションが混じるので全部を偶然とはいえない。偶然を全部引くと (0.33 − 0.29) / (1 − 0.29) ≈ 0.06。
- 監査役の目視（10/01 の自由ハンドの決まり文句 38 のうち少なくとも 4 がアクション）≈ 0.11。
- → **r = 0.2**（上限 0.33 と下限 0.06〜0.11 の間）。感度は 0.1・0.3 で開発データを回して確かめた（下）。
- 第 2 の耳の候補: 穴を埋めた決まり文句で真のアクションがコールのとき、耳の候補の 1 つのアクションに読めるもののうち
  いちばん上がコールだったのは 6/9。チェック・フォールドは耳の候補にほとんど出ない（額が上位を占める）→ 一様 + 耳の
  候補の重み。

10/01 の決まり文句の例（時刻の前後で確かめた）: 42f7b964 ハンド 2 のリバーのコール（耳「コロン」→ コール）・ハンド 3 の
プリフロップのコール・ハンド 1 のフォールド、1709932e ハンド 3 のコール、4c252c77 ハンド 2 の 900（耳「強くて」→ 九百点が
差 −0.3）。

## やったこと

- **決まり文句の発話の 2 つの状態**（`tools/estimate.py:_canned_options`）: ライブの規則でも読めなかった決まり文句の
  発話は「雑談・雑音だった log(1 − r)」（既定）/「アクションを言った log r + log q(a)」。q = フォールド・チェック・コールに
  一様 + 第 2 の耳の候補（1 つのアクションに読める・差 −8 以上）の重み exp(差 / 2)（自由に聞いた文も重み 1 で分母。賭けは
  候補の額の上位 3）。`canned_action` > 0 のときだけ（v1 の `READING_OVERRIDES` で 0.2。v0 は 0 = `drop_heard` のまま）。
  前の v1 は「捨てる −0.1 / 耳の候補 −2.0 + 0.4 × 差」で、耳の候補に無いアクション（フォールド・チェック）を読めず、
  コールも高くついた（作業計画の監査:「推定器が救えない」）。
- **探索**（`integration/estimator.py`）:
  - 決まり文句の読みの直しは、読めた賭けの語から 15 秒以内の発話だけ。その前にも聞こえなかったアクションを入れられる
    （4c252c77 ハンド 2: 決まり文句の 900 の前に言われない SB のコール）。最初は全部の決まり文句を選択点にしていて、
    9d1d8536 ハンド 4（10 分・決まり文句 34）の直しが 74 → 289、推定が 176 秒（再生 2384 回）になった。絞って直し 77・
    再生 688 回・43 秒（変更前 50 秒）。
  - **記録を変えない直しでも、得点が良ければその記録の説明として残す**（候補は広げない）。42f7b964 ハンド 2: エンジンが
    補った「言われないコール」（−3.22）より、決まり文句の下のコール（読み −2.48 + 言われた −0.04、既定の雑談 −0.22 と
    比べて +0.92）の方が良いのに、「何も変えない直しは捨てる」で捨てていた。
- **ショーダウンの声の項**（`p_showdown_word` 0.03）: 「ショーダウン」・役の名前（`end_hand` + `hand_name`）があるのに
  全員降りて終わった仮説を下げ、要確認の理由にする。真のアクションの 92 ハンドで、声のあった 23 ハンドはすべて
  ショーダウン、全員降りて終わった 45 ハンドで声 0。これまで推定器は役の名前を採点に使っていなかった（賭けの語だけ）。
  42f7b964 ハンド 2 は、決まり文句の下のコールを読んでも「リバーで言わずに降りた」別解に 0.8 負けていた（別解では
  配る人の「ストレート」が説明されないまま）→ この項で正しい記録が 1 番に。
