# 2026-05-22 — Phase 5-J: manual action actor mismatch is strict reject

- **Branch**: `claude/bayesian-action-estimation-opjfz`
- **Implementation commit**: (this commit)

## Goal

Phase 5-I の積み残し残課題 "手動入力時の actor mismatch を strict reject にする
(現状 permissive warning のみ)" を解消する。`event.seat != bs.actor_seat` の
manual action は `gs.apply_action` / `bs.update_after_action` を呼ばず
`ActionRecord` も積まず state を変えずに reject する。GUI には専用通知
(`on_manual_rejected`) で review log を出す。

Issue: [0002-manual-action-permissive-warning-too-soft](../issues/0002-manual-action-permissive-warning-too-soft.md)
Design: [ADR-0002](../adr/0002-manual-action-actor-mismatch-strict-reject.md)
(部分的に ADR-0001 の Consequences を supersede)

### `_handle_manual_action_event` の actor 検証ブロック

Before (Phase 5-I, permissive):
```python
if bs.is_initialized and bs.actor_seat is not None and seat != int(bs.actor_seat):
    needs_review = True
    notes.append(f"actor mismatch: input seat={seat}, expected={bs.actor_seat}")
# ... 続けて gs.apply_action / bs.update_after_action が走る
```

After (Phase 5-J, strict reject):
```python
if (
    bs.is_initialized
    and bs.actor_seat is not None
    and seat != int(bs.actor_seat)
):
    expected = int(bs.actor_seat)
    logger.warning(
        "Manual action rejected: actor mismatch "
        "(selected seat=%d, current actor=%d, action=%s, amount=%d)",
        seat, expected, action, amount,
    )
    if self._on_manual_rejected is not None:
        rejection = ManualActionRejection(
            seat=seat,
            attempted_action=action,
            attempted_amount=amount,
            expected_actor=expected,
            reason="actor_mismatch",
            timestamp=float(event.timestamp),
        )
        try:
            self._on_manual_rejected(rejection)
        except Exception:
            logger.exception("on_manual_rejected callback raised")
    return  # <-- 早期 return: 以降の apply / record / on_action は走らない
```

### GUI の dispatch 経路

```
IntegrationThread.thread
   ↓ on_manual_rejected(rejection)        (= worker thread からの callback)
GUIDashboard.on_manual_rejected
   ↓ self._manual_rejection_queue.put     (= スレッド安全)
   ─── main thread に渡る ───
GUIDashboard._poll_updates                  (= 100ms 周期で動く)
   ↓ get_nowait()
GUIDashboard._apply_manual_rejection
   ↓ _append_log(msg, tag="review")
GUI history pane に review log として表示
```

## Mismatches found during testing

実装中に test 側で 1 件 (production code には影響なし):

### Mismatch 1: `test_full_scenario_from_user_log` の to_call 期待値

更新前は 2 回目 seat 3 raise が apply されることを前提に `current_bet=900`、
`to_call=800` を assert していたが、strict reject なら `current_bet=600`
(= 1 回目 raise のまま) で `to_call = 600 - 100 (SB contrib) = 500` になる。
test を `assert actions[-1].amount == 500` に修正。

production code (= `bs.call_amount_for` の計算ロジック) は無変更。

## Out of scope

- audio 経路の actor mismatch を strict reject にする (= 意図的に非対称維持)。
  audio は observation で reconstruct で修正できる前提。
- patch_proposal / reconstruct への manual rejection の取り込み (= reject は
  apply されていないので reconstruct baseline には影響しない)。
- actor mismatch を config / runtime flag で permissive に戻す機能 (= Option C
  rejected, ADR-0002 §"Alternatives considered" 参照)。
- manual `new_hand` event の追加 (= manual-only でハンド開始するための SB/BB
  auto-post 経路、Phase 5-I で既に scope-out 済み)。
- street 自動進行のトリガー拡張 (= board cards / `advance_street` audio に依存)。
- replay-based rollback (= reject 時の state 巻き戻しは不要、そもそも apply されない)。
