# 2026-09-27 事後推定へのロードマップ（ADR-0056 追記 1）と S0 = 評価の土台

## Goal

オーナーの依頼「事後の推定（ADR-0056）に辿り着くまでのロードマップを Fable 5.1 と一緒に考えて」。Fable 5.1 と
開発側が独立に案を作って突き合わせ、統合案をオーナーが承認した（「この案で問題ない」）。承認した案を
ADR-0056 追記 1 に記録し、1 手目（S0 = 評価の土台）を実装する。

## ロードマップ（要点。詳細は ADR-0056 追記 1）

- 推定器は別実装にせず、いまの engine を決定的な再生器として、engine が規則で決めている判断（無言だった人数・
  発話を捨てる・別の読み・離脱をフォールドにするか・聞き落としたベット）を「選択点」にし、その選択列を
  ビーム探索する（Fable 5.1 の案。ディーラーの言い方の規則を二重に持たない）。
- 音声は保存した WAV を店舗 PC で後から採点する（強制アライメント・N-best）。ライブで n-best を残す必要はない。
- S0 評価の土台 → S1 真のアクション 40〜50 ハンド（入力画面の手間減らし）→ S2 聞き取りの採点 → S3 推定器 v0
  → S4 表示と訂正（action_id、margin で要確認）→ S5 正本化（影 → 表示 → 正本）。
- Fable 5.1 が店舗データで数えた実測: 記録の行の出所は 音声 65% / 補ったチェック・コール 21% / RFID のフォールド
  13%、無宣言の bet / raise は 0、Whisper の確信度は正しい発話と幻聴で重なる、札の在否の反転の約半分が戻り。

## S0 で作ったもの

- `tools/eval_store.py`: pack_logs の zip / 展開したフォルダ / `logs` を再生して評価。記録から卓の設定を取り
  （席・最初に配られたときの持ち点・最初のハンドのブラインドとボタン）、記録時の結果との違い、行の出所、真の
  アクションとの一致率・要確認の精度と再現率・聞き取りの自信、`--timeline`（発話・札・信号の時刻順 + 真の
  アクション・記録・再生の行の比較）、`--export-fixture`（回帰テスト用の書き出し。baseline は下げない）、`--json`。
- `tests/test_store_fixtures.py`: 書き出したセッションが真のアクションとの一致で悪くならないこと（いまは 0 件 =
  真のアクションがたまったら書き出す）。
- **再生の忠実さ**: 店舗の zip を再生すると、記録と違う結果になるセッションがあった。
  - 15dd2034: 起動したときに卓に残っていた前のセッションの札（席の手札 + ボード 6 枚）で、再生だけが存在しない
    ハンドを始めた（live は在否を見てボードに札がある間は配布としない）。
  - 配る前の発話を待ってからハンドを始める live の動きを、再生は持っていなかった。
  → 在否で決めた配布を `deal` 信号（`cards` = "席:札"）、ハンドを始めた時点を `hand_start` 信号として記録し
  （`reconstruction_event` 0.9）、replay は記録にそれがあれば札の読み取りから配布を決め直さずに従う。
  信号の無い古い記録は従来どおり（評価ツールが注記を出す）。
- `replay_events(button_seat=..., close_open_hand=...)`（1 ハンド目のボタン、最後に開いたままのハンドを終了と
  同じ規則で閉じる）。`recording.enabled` を既定 on（`audio.save_audio` は会話が入るので off のまま）。
