# 2026-10-26 卓の形の入力画面: 次のハンドを出すタイミング

## ゴール

オーナー:「真のアクション入力 UI の次にハンドを表示するタイミングは、前のハンドが終了したタイミングではなく、前のハンドが開始した
タイミングにしてください」。確かめた対象は卓の形の画面（`/table`, 店の PC）。

## 変えたこと

- `tools/table_entry.py:current_hand_id`: 開いたとき（・セッションを選んだとき）に入れるハンドを、進行中のハンドがあればそのハンド
  → **ロガーのいちばん新しいハンド（進行中を含む）の次**（まだ配っていない = `pending`）に。前のハンドが配られた（ロガーが
  `live_hand.json` を書いた）時点で次のハンドに移る。進行中・終わったハンドは「← 前」で開ける。
- 次のハンドの見込み（席・持ち点・ボタン・ブラインド）は前と同じく前のハンドから（前のハンドが進行中なら収支はまだ無いので、
  前のハンドの真のアクションを保存していればその収支）。

## 試験

- `tests/test_table_entry.py`: 前のハンド（2）が進行中になったら、開いたときのハンドは 3（`pending`）。

## 追記: 持ち点を数えないモード（同日）

オーナー:「この UI ってスタック無視モードに対応してる？」→ 対応していなかった:

- 次のハンド（`pending`）の席を前のハンドの終わりの持ち点から作っていて、持ち点を数えないモード（記録に持ち点が無い =
  `core/stackless.py:strip_hand`）では席が 0 になった（開いたときに出るのが次のハンドになったので、画面がほぼ使えない）。
- 席に内部の仮の持ち点（`STACKLESS_STACK` = 1 兆）が出ていた。

直したこと（`tools/table_entry.py`）: `skeleton_after` は前のハンドが `stackless` なら前の席（真のアクションの「いなかった」を除く）を
持ち点 0（分からない）で並べ、`stackless` を引き継ぐ。`_base_of` も `stackless` を渡す。`seat_view` は持ち点を出さず、オールインした席の
出した額も出さない。`table_legal` はオールインに向き合ったコール（額が分からない行）の席の出した額を出さない。画面は持ち点の欄を出さず、
ポットが分からなければ「—」、オールインに向き合ったコールは「コール」とだけ出す。見本のデータで画面を開いて確かめた。
