## 調べたこと

- ボタンが真と違うのは d01277f8 の 68 ハンド中 25（記録）。いつも「前のハンドで持ち点 0 と誤って記録した席」のあとから
  1 席先にずれたまま続く（43 = 席6・55 = 席7・74 = 席1）。原因: 手札が 2〜3 席に載った時点（`DEAL_STABLE_SEC`）でハンドを
  始めるので、その席の札があとから載ると「持ち点 0 の席に配られた → 戻す」が効かず、ハンドに入らず、ボタンが飛ばした。
- 配った順（手札を最初に読んだ時刻）から真のボタンを当てられたのは 72 ハンド中 36。プレイヤーがいる卓では順が崩れる
  （`button_from_deal` の救済はほぼ効かない）。
- 札が 1 枚も載らない席を外す規則は誤りが多かった: 8 人卓では手札が配ってから 25 秒あとに読めることがある（a64ec4ad
  ハンド 2 の席7）、フロップの時点で 1 枚も読めていない席もある。→ 入れない。
- 久しぶりに札が載った席（d01277f8 ハンド 9 の席2 = 新しく座った人）を入れるとボタンがずれた（オーナーの真のボタンは

## 実装

- A1 再生（`integration/replay.py`・`IntegrationThread` の `hand_start`）: 記録した `hand_start` は発話の待ちを見直さずに
  `force` で始める。すでに始めていれば何もしない（前は「始める」が次の配布まで残り、次のハンドを配った瞬間に始めていた）。
  発話の処理で出した札の離脱より、その発話で始めたハンドの `hand_start` を先に流す。d01277f8 は同じコードで 21 ハンドが
  記録と違っていた → 0。`tests/test_store_2026_09_29.py` の並びのテストを新しい意味に直した（開発データの再生は不変）。
- A2 `tools/eval_store.py`: `table_match`（ボタン・配られた席が真と同じハンド）、真のアクションにボタンが無ければ入れた
  ときの記録のボタン（`fill_truth_table`）。`check_fixture` は評価から外したハンドを数えない（65c412b2 ハンド 18 = オーナーが
  外した「前ハンドの誤ったオールインでアクターが消えている」= 新しい規則が直す形）。
- A3 入力画面: 席ごとに「いた / いない」・始めの持ち点。`core/truth_hand.py:with_table`（真のアクションの席で記録を直す）を
  手番の計算・保存の確かめ・`materialize_truth` が使う。`table_seats`（セッションで卓にいた席と持ち点の見込み）。
- B4/B5 `integration/engine.py:_check_hand_seats` → 信号 `hand_seats`（reconstruction_event 0.20）→ `_apply_hand_seats` →
  `_reseat`（`_rebutton` と同じく始めの状態に戻して入力を流し直す）→ `PokerkitGameState.restart_hand_with_seats`
  （ボタンは前のハンドのボタンから進め直す。手で・配った順で直したボタンがこの席にあれば保つ）。配り終えた（フロップか
  `HAND_SEATS_SETTLE_SEC` = 20 秒）あとに載った札では組み直さない。replay は記録にこの信号があればそれに従い、無い古い記録は
  同じ規則で決める。推定器の世界の再生は決め直す（`DERIVED_SIGNALS`）。持ち点は 0 になる前の持ち点（`_last_positive_stack`）。
  `_restore_dealt_busted_seats`（配った時点で 2 枚あった持ち点 0 の席）も同じ持ち点に戻す。
- B7 ボードの 6 枚目を足さない・`award_with_unknown_cards` は 6 枚以上のボード・3 枚以上の手札で None。
