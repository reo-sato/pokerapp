# Worklog: 卓の入力の画面が新しいセッションに移る

## Date

2026-11-18

## Scope / Task

オーナー「前回テストセッションを始めたとき、卓 UI の方に新しいセッションが現れて入力できるまでに時間がかかった。原因を調べて
改善してほしい」。対象は真のアクション入力のサーバーの `/table`（`tools/table_entry.py`、店の PC の卓の形の入力画面）。

## Goal

ロガーを起動し直して新しいセッションが始まったら、卓の入力の画面が数秒でそのセッションの最初のハンドを開くこと。

## 調べたこと（11/09 のログ, `data/store/2026-11-09/`）

| セッション | 開始 | ハンド 1 の配布 | 真のアクションの保存 |
|---|---|---|---|
| ca12f9cd | 19:32:23 | — | （1 分で閉じた） |
| ae82f48f | 19:34:12 | 19:34:49 | ハンド 1・2 は無し。最初はハンド 3（19:39:09） |
| 559af646 | 20:51:37 | 20:52:19 | ハンド 1・2 は 20:57 にあとから（メモ「サイズ聞こえなかった」）、ハンド 3 は 20:58 |

- 原因: `/table` の画面は、セッションの一覧を開いたとき（`start()`）に 1 回しか読まなかった。2 秒ごとの読み直し（`tick`）は
  開いているハンドだけを読む。切り替えの一覧にも新しいセッションが入らないので、画面を開き直すまで前のセッションのままだった。
- ロガーの側は問題なし: 記録のファイルはセッションの開始時に作る（`JsonWriter.ensure_created`）。卓の設定 `table` も最初に書く。
- iPad の一覧の画面（`/`）は、もとから 5 秒ごとにいちばん新しいセッションへ移る。
- セッションの一覧の処理（`list_sessions`）の重さは原因ではない。店舗の全 19 セッションで 0.06〜0.09 秒。

## Changed Files

- `tools/table_entry.py` — 画面の JS を次のように変えた。
  - `loadSessions`・`followNewSession`・`openCurrent` を足した。
  - `tick` で 5 秒ごとに一覧を読む。
  - `pickSession` と `openHand` に引き継ぎを足した。
- `tests/test_table_entry.py` — 画面が一覧を読み直して新しいセッションに移る仕組みがあること。
- CHANGELOG。

## Implemented Behavior

- 5 秒ごとにセッションの一覧を読み、開いたときに無かったセッションが現れたら、いちばん新しいものに移る。
- 卓の設定がまだ無いうちは「卓の設定を待っています」と出し、2 秒ごとに読み直して最初のハンドを開く。
- まだ配っていないハンドに入れかけていたアクション・勝者・メモは、新しいセッションのまだ配っていないハンドへ引き継ぐ。
  ロガーを起動し直すあいだに入れ始めた分を失わないため。
- 配られたハンドに保存していない入力があれば「このハンドを保存したら移ります」と出し、保存のあとに移る。
  ふつうは 0.7 秒で自動で保存する。
