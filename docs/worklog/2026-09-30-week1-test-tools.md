## 作ったもの

### 読み上げ集（`tools/read_corpus.py`, 画面 `http://<PC の IP>:8791/corpus`）

- 163 句（アクション 19・ベット 17・レイズ 20・額だけ 12・言い回し 6・続けて言う 20・ポジション 14・席 8・制御の
  言葉 17・役の名前 7・言い直し 5・アクションでない言葉 18）。正解は句ごとの `event_key`（ベット・レイズ・額だけは
  「wager N」= 手番が決めるので区別しない）。言い直し 2 句は、いまの読み取りでは読めないと分かっている（`known_gap`）。
- 真のアクション入力の画面のサーバ（ポート 8791）に同居（ポート 8792 は Windows のファイアウォールに管理者の許可が
  要るため使わない）。スマホ / iPad に句を 1 つずつ大きく出し、読んだら「次へ」。PC のマイクで録り続け、句を出した
  時刻から「次へ」を押した時刻（前 0.3 秒・後 0.6 秒の余白）を切り出す。やり直し・戻る・飛ばす・途中で終わる・続きから。
- マイクは 2 本まで同時（`m1` / `m2`）。録りながら本番と同じ聞き取り（AudioThread と同じ切り出し → Whisper → 読み取り
  → 第 2 の耳）を裏で回し `transcripts.jsonl` に書く。終わった画面に残りの句数と目安の時間を出す（0 になるまで
  ハンドロガーを始めない = 同時に動かすと聞き取りが遅れる）。
- 出力 `logs/corpus/<日時>_<名前>/`: `meta.json`・`labels.jsonl`・`<句>_t<回>_m<マイク>.wav`・`transcripts.jsonl`・
  `full_m1.wav`（ずっと録った音声。送付には入れない）。`tools/pack_logs.py` が直近の読み上げ集を zip に入れる
  （`--session` 指定時は入れない、manifest に `corpora`）。
- 開発側: `python tools/read_corpus.py eval <zip>...`（句ごとの正誤・方式ごと）/ `transcribe <フォルダ>`（あとから聞き取り）。

### 台本のハンド（`tools/test_script.py`, 画面 `http://<PC の IP>:8791/script`）

- **声だけ**（ショートカット「台本のハンド (声だけ)」= `start_script.cmd` = `main.py --cli --log-file --script voice`）:
  6 人の仮想の卓・30 ハンド（1 ハンド約 11 行）。場面の割合: ふつう 50%・マルチウェイ 10%・オールイン 10%・
  サイドポット 6%・ショーダウンで見せずに降りる 10%・チョップ 4%・ヘッズアップ 10%。RFID は使わない。卓の設定は
  台本から（入力なし）。セッション ID の末尾は `_script_voice`。
- 画面の「ハンド N を始める」で、ロガーは台本のボタンと持ち点で新しいハンドを始める（制御 `script_hand`: 次の
  new_hand で持ち点とボタンを台本の値に置き換える。前のハンドの聞き違いややり直しでずれても正解と同じ卓から）。
  制御の受け手は、先に言われた発話の聞き取りを待ってから積む（前のハンドの最後のアクションを次に入れない）。
- **札の確認**（ショートカット「札の確認 (RFID)」= `start_cards.cmd` = `--script cards`）: 席 4・5・6、1 ハンド目の
  ボタンは席 6。6 手順（ふつうに配る・ボタンを動かし忘れる・持ち上げて戻す・卓の中央へマック・フロップを 3 枚同時・
  ターンを置き直す）を「始める → やってみる → できた / ちがった」。
- 画面の操作は `logs/<sid>.script_marks.jsonl`、台本は `logs/<sid>.script.json`。`tools/eval_store.py` が台本を
  真のアクションとして評価し（始めた時刻で記録のハンドと対応づけ）、手順ごとの「できた / ちがった」も出す。
- 台本のセッションは真のアクション入力の一覧に「台本」と出て、入力は要らない（ブラインドにもならない）。

### 真のアクションの入れ方（`tools/ground_truth_ui.py`）

- **全部のハンドをブラインドから**（`BLIND_EVERY` 5 → 1）。保存すると記録と並べて見せ、違う行を黄色に（照らし
  合わせ）。直して保存し直すと `reconciled`、最初に入れた内容は `blind_entry` に残る（入れる側の誤りと、記録への
  引きずられを測る）。
- **食い違いの警告**（編集中も、開いた時点でも）:
  - ボードの枚数とアクションの終わったストリートが合わない（9d1d8536 ハンド 2 の型）。
  - 記録にあるストリートのアクションが無い（ボードに無いストリートは訊かない = 記録がストリートを進めすぎた
    d0f055fb ハンド 2 で誤って出ていた）。
  - 手札が一番強い席がショーダウンで見せずに降りた（a6ee12e4 ハンド 1 の型）。
  - RFID が読んだ札が、入れたボード・手札に無い（d0f055fb ハンド 5 の型。札を直したのが正しいこともあるので止めない）。

### 計測の修正（`tools/measure_capture_accuracy.py`・`tools/eval_store.py`）

- オールイン = 同じ額（0 でない）のコール / ベット / レイズ（`same_action_type`）。
- **別の人・別のストリートの行を正しいと数えない**（`same_place` / `row_correct`）: 行の対応づけ（difflib）の
  「置き換え」の区間では席やストリートの違う行が並び、種類と額だけで比べていた（a6ee12e4 ハンド 1 の
  「席5 フォールド」と記録「席4 フォールド」、9d1d8536 ハンド 2 の「席5 フォールド」と「席4 フォールド」）。
  ストリートの無い古い真のアクションの行はストリートを比べない。
