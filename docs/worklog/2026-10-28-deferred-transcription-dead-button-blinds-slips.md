# 2026-10-28 10/26 を受けた直し: 書き起こしの後回し・デッドボタン・ブラインドの上がり方・言い間違い

## ゴール

10/26（2bbd480e）を家で入れた真のアクション 26 ハンドで評価すると、全部正しいハンドは 0/26 だった。主な原因は 2 つ。

- 聞き取りが 2〜7 分遅れた。907 の発話をすべてその場で Whisper にかけ、処理に話した長さの約 1.6 倍かかった。
- ボタンと席がずれた。

これを受けたオーナーの決定（2026-10-28）は次の 4 つ。

1. テスト中の書き起こしは全部後回しにする。
2. デッドボタンは、SB か BB の人がバストしたときだけにする。
3. ブラインドは遷移時刻の次のハンドから上げる。そのハンドの最初のアクションまでに宣言が無ければ、もう 1 ハンド遅らせる。
4. 言い間違いらしい発話のあとに、それと矛盾するアクションがあれば言い間違いとみる。ショーダウン以外の発話も同じ。

## 変えたファイル

### 1. 書き起こしの後回し（114d0b6）

- `audio/recorder.py`: `live_transcribe=False` のときの動きを足した。
  - プレー中の発話は音声を保存し、第 2 の耳でブラインドの宣言だけを聞き分ける（`_process_live_ear`）。
  - Whisper は裏の worker（`_deferred_loop` / `_process_deferred`）で順に書き起こす。
  - 書き起こした行には次の印を付ける。
    - `deferred=True`
    - `heard_at` = 話し始め + 長さ
    - `transcribed_at`
  - `backlog()` などは後回しの分を数えない。
- `main.py`:
  - 後回しのときは音声のフォルダを必ず作り、印 `.deferred` を置く。
  - CLI に後回しの行は出さない。
- `tools/offplay_audio.py`:
  - 書き起こしの行が無い `<ms>.wav` を、終了のときと「ログをまとめる」のときに書き起こす（`transcribe_deferred`）。
  - 途中で止めても続きから書き起こす。
- `tools/eval_store.py`:
  - 後回しのセッションでは、その旨を表示する。
  - `with_offplay`: ハンドの間に言ったブラインドの宣言を、話した時刻で読み直しに足す。
- `output/transcript_log.py`, `config_default.json`（`audio.live_transcribe`, 既定 true）

### 3. ブラインドの上がり方（114d0b6）

- `audio/recognizer.py`: 宣言の文を `blind_up` の入力にする。アクションにはしない。
  - 「ブラインド上がります」「上がってます」
  - 「次のハンドからブラインド」
  - 「SB… BB…」「ブラインド 800、1600」
- `integration/engine.py`: 時計の時間で入ったレベルは「上がる予定」（`_level_wait`）として持つ。
  - 宣言が届いていれば、次のハンドから上げる。
  - そのハンドの最初のアクションより前に届けば、新しいブラインドで始め直す（`restart_hand_with_blinds`）。
  - 宣言が無ければ、その次のハンドから上げる。
  - 手で動かした時計の操作（`clock_now`）は、いままでどおりすぐ上げる。
- `reconstruction_event` 0.22（印 `clock_now`）。
- 10/26 の読み直し（聞き流した発話の宣言も入れる）で、上がったレベルは次のとおり。
  - ハンド 9 → レベル 7
  - ハンド 23 → レベル 8
  - ハンド 24 → レベル 9
  - ハンド 32 → レベル 10

### 2. デッドボタン（8219783）

- `core/positions.py`:
  - `next_hand_button`: 前のハンドも次のハンドも 3 人以上のときに働く。
    - SB だけ抜けた → 空いた SB の席がボタン。
    - BB だけ抜けた → ボタンを動かさない。
    - それ以外 → 1 つ進める。
  - `seat_order_from_button` / `position_map`: デッドボタンに対応した。並びは空いた席の次から。BTN の名前は誰にも付けない。
- `core/poker_engine.py`:
  - `new_hand` と `restart_hand_with_seats` が `next_hand_button` を使う。
  - `set_button` は空いた席も受ける。
- `core/truth_hand.py:start_state`: ボタンが空いた席なら、デッドボタンとして扱う。
- `tools/table_entry.py`: まだ配っていないハンドの見込みのボタンも、同じ規則で出す。
- `tools/ground_truth_ui.py`: ボタンの選択肢に空席も出す。

### 4. 言い間違い

- `integration/engine.py`:
  - リバーの前（ボード 5 枚未満）の「ショーダウン」は、いままでどおりすぐに閉じていないベッティングを閉じる。
  - ただし閉じる前の状態をチェックポイントとして残す（`_pending_showdown`）。
  - 宣言よりあとに話した賭けの語が届いたら、言い間違いとみる（`_showdown_was_a_slip`）。
    - チェックポイントに戻す。
    - 宣言のあとの入力を流し直す。
    - 要確認にして知らせる。
  - 次のものでは戻さない。
    - 札が出るだけ（ランアウト）。オーナーの決まりは「リバーのアクションがあった場合」なので。
    - 宣言より前に話した語が、遅れて届いた場合。
  - 最初は「すぐ閉じずに保留し、札か賭けの語で捨てる」形で書いた。これは店舗 09-27 の試験に合わなかった。その試験では、
    宣言のあと札を持ち上げてもフォールドにしない・ランアウトして手札で判定する、を求めている。それで上の形に変えた。
- `integration/estimator.py`:
  - 制御の語（`showdown` / `heads_up` / `players_left` / `end_hand` / `blind_up`）を捨てる直しを候補に足した。
  - 捨てた語には `p_slip`（0.03）を払い、要確認の理由「言い間違いとみた「…」」を付ける。
- `docs/estimator-v2/README.md` §3.8: 原則「以降のアクションと矛盾する発話は言い間違いを考える」を v2 の要件として書いた。
- `tests/test_showdown_slip.py`（5 件）。
  - 賭けの語で戻す。
  - ランアウトでは戻さない。
  - 前に話した語では戻さない。
  - 続きが無ければ閉じたまま。
  - replay も同じになる。
