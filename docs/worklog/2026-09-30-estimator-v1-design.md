## いまの v0（`tools/estimate.py`）

- ライブと同じ engine を決定的な再生器にする。発話ごとの読みを選択点にする: Whisper の読み / 第 2 の耳の候補（上位 3）
  / 捨てる。
- 採点 = 読みの確からしさ（手置きの log）+ engine が補った・直したことへの罰（補ったチェック・コール −1.5、補った
  フォールド −2、反映できない発話 −3、額を寄せた −2、読み替えた −2.5 …）。
- 山登り（1 回に 1 つの選択点を変える, 最大 4 回）。ハンドは記録の持ち点から始まるので互いに独立。
- 限界: 選べるのは「聞こえた発話の読み」だけ。聞こえなかったアクション・余計な 1 語・札の離脱の意味・ボタンは
  選べない。罰の値は手置きで、確率として較正していない。山登りは 2 か所を同時に直す必要があるハンドに届かない。

## v1 の確率モデル（案）

### 隠れた量（ハンドごと）

- ボタン席 b（記録のボタン、または隣の席 = ディーラーが動かし忘れ / 動かしすぎ）。
- アクションの列 A = (a_1, …, a_T)。pokerkit で合法（合法でない列は確率 0 = ハードな制約）。手番の人は規則で決まる。
- 各アクションと発話の中の語（トークン）の対応: 語に対応する / 言われなかった・聞こえなかった（無言）。
- 対応しない語 = 余計な語（雑談・幻聴・言い直し）。
- 札の離脱ごとの意味: フォールド / 持ち上げ（手に持つ・見る）。

### 観測

- 発話: 話し始めの時刻・Whisper の書き起こし（と確信度）・第 2 の耳の自由に聞いた文と候補の確からしさ。
  いまの読み取り（`parse_actions`）で 0 個以上の語（fold / check / call / bet・raise / 額だけ / allin / check_around /
  heads_up / players_left N / showdown / 役の名前）にする。語の読み方の候補（Whisper・第 2 の耳の候補）も持つ。
- RFID: 手札の配布（席・時刻）、札の離脱・戻り（席・時刻）、卓の中央を通ったマック、ボードの札（位置・最初に見えた時刻）。
- 操作: 勝者（w）、台本のハンドの開始。

### 採点 = log 事後確率（定数を除く）

score(b, A, 対応) = log P(b) + Σ_アクション log P(観測 | アクション) + Σ_余計な語 log P(余計な語)
                   + Σ_札の離脱 log P(離脱 | A) + Σ_残り人数の宣言 log P(宣言 | A) + 時刻の項

| 項 | 値（log） | 出所・数え方 |
|---|---|---|
| 語 = そのアクションの読み（種類が合う） | log(1 − p_miss − p_sub) + 読みの確からしさ | 読み上げ集 3 つ（461 句・519 語）: 正しく読んだ語 92.7% |
| 無言（語が無い）: check / call / fold | log p_miss(種類) | 読み上げ集の聞き落とし: アクション・額・続けて言う句で 8/369 = 2.2%（役の名前・進行の語は別）。店舗の運用はすべて言う（2026-09-29 から）。無言の fold は札の離脱があれば軽い |
| 無言の bet / raise | ほぼ 0（額が分からない。置くなら最小額 + 要確認） | 店舗の実測で無宣言の bet / raise は 0（ADR-0056 追記 1） |
| 語の種類の取り違え（check ↔ call など） | log p_sub | 読み上げ集 1/519 = 0.2%。engine の「読み替え」がこれに当たる |
| 額の聞き違い（語の額 ≠ アクションの額） | log p_amt | 読み上げ集 12/519 = 2.3%（額のある語の中では約 5%）。似た音の数字（2 ↔ 6 など）は重く、似ていない数字は軽く |
| 余計な語 | log p_phantom（語の確信度・長さで変える） | 読み上げ集 11/519 = 2.1%（言い直しの句で 5）、アクションでない句 56 から 2 語 |
| 札の離脱 = フォールド（離脱の近くでその席がフォールド） | log(1 − p_lift) | 店舗の真のアクションのある 18 ハンド: 離脱 29 のうちフォールド 20・ショーダウンの席 5・勝者 4（p_lift ≈ 0.3） |
| 札の離脱 = 持ち上げ（その席はフォールドしない） | log p_lift、戻ったら軽く・ハンドの終わりまで戻らなければ重く | 同上。engine の「札が離れたままならフォールド」は 11 件中 3 件が誤り |
| フォールドしたのに札が離れない | log p_nodepart | 札が読めていない席・札を持って離れた席 |
| 残り人数の宣言 N（ストリートの移り） | 合えば log(1 − p_np)、合わなければ log p_np | 読み上げ集の「N プレイヤーズ」: 聞き落としはあるが取り違えはまれ |
| ボタン = 記録のボタン | log(1 − p_btn) | 動かし忘れ 1/18（店舗） |
| 時刻 | ストリートの窓（ボードの札の時刻）の外の語は重く | 話し始めの時刻は正しい。聞き取った時刻は最大 45 秒遅れる（使わない） |

- 値はスムージング付きの割合（Beta 事前分布）で、較正に使うデータと評価に使うデータを分ける（下）。
- 事後の近似: N-best の得点の softmax。要確認 = 1 番と 2 番の差（log-odds）が小さいハンド・位置。

### 独立性の仮定（破れているのが分かっているもの）

- 語の誤りは発話の中で相関する（1 つの発話が丸ごと幻聴になる / 丸ごと落ちる）。発話単位の事象（丸ごと落ちる・
  丸ごと余計）と語単位の事象を分ける。
- Whisper と第 2 の耳は同じ音声を聞くので独立な証拠ではない。第 2 の耳は「読み方の候補」として扱い、Whisper の
  読みと掛け合わせない。
- 札の離脱は人ごとの癖（持ち上げる人）で相関する。
- 読み上げ集は読んだ声（台本どおり・間がある）で、実卓の声より誤りが少ない。

## 探し方（案）

- engine を決定的な再生器として使う（追記 1）。選択点 = 上の隠れた量を engine への入力の編集として表す:
  - 発話の読み（Whisper / 第 2 の耳の候補 / 捨てる）
  - 発話の中の 1 語を捨てる（余計な語）
  - 無言のアクション（fold / check / call）を発話の前に入れる
  - 札の離脱を持ち上げとして無視する
  - ハンドの始まりでボタンを隣の席にする
- engine が自分で補ったもの（補ったチェック・コール・フォールド、額を寄せた、読み替えた、反映できない語）は、上の
  観測の事象（無言・額の聞き違い・取り違え・余計な語）として同じ表で採点する（罰の手置きをやめる）。
- ハンドごとのビーム探索（幅 B・深さ D）。ハンドどうしは記録の持ち点から始まるので独立。1 回の再生で全ハンドの候補を
  同時に採点する（いまと同じ）。決定的（同じ入力 → 同じ結果）。
- 探索の誤りとモデルの誤りを分ける: 真のアクションの列の得点を同じ式で計算し、推定より高ければ探索の誤り、低ければ
  モデルの誤り。

## 選択点で届くかの確認（崩れた 8 ハンドに正解の直しを入れて再生）

正解を知っている人が 1〜2 か所だけ入力を直したら、engine の再生でハンドが丸ごと正しくなるか（= v1 の選択点で
正解に届くか。得点で選べるかは別の問題）。

| ハンド | 直し | 丸ごと正しく | 正解を選ぶ手がかり |
|---|---|---|---|
| 台本 #3 | 「600」の前に無言のフォールドを 1 つ | ○ | 3 人残っているのに「ヘッドアップ」（残り人数の宣言） |
| 台本 #11 | 「フォールド、フォールド、オールイン」の「オールイン」を捨てる | ○ | 既定ではあとの 5 語が反映できない |
| 台本 #22 | 「1400点」の前に無言のチェックを 1 つ（別の発話として） | ○ | 既定はリバーでチェックできるのにフォールド。弱い |
| 店舗 d0f055fb #3 | 「900点」の前に無言のチェック | ○ | 既定の無言は 1 つ（コール）、正解は 2 つ（チェック・コール）。証拠は無い = 聞くしかない |
| 店舗 d0f055fb #5 | 「スリーベン」を「スリーウェイ」に（音の近い語の 2 番目） | ○ | 既定のレイズであとが崩れる |
| 店舗 fded6f75 #1 | フロップとリバーで 2 番目の人の無言のチェック（2 か所） | ○ | リバーは最後の「フォールド」の瞬間に席5 の札が離れた。フロップは弱い |
| 店舗 9d1d8536 #4 | ボタンを席5 に | フロップまで○ | ターンは聞き取りの遅れ（最大 13 秒）で発話と札の離脱の順が入れ替わっている |
| 店舗 027e4b15 #1 | — | — | 真のアクションにショーダウンのマックの行が無い（入力の決めごとの差。直しの対象ではない） |

- 選択点（無言のアクション・1 語を捨てる・音の近い語の別の読み・ボタン）で 8 ハンド中 6 ハンドが届く。
- 無言のアクションはどれも**直前と同じアクションの繰り返し**（2 人目のチェック・3 人目のフォールド）か、最初の
  チェック。無言の確率は「繰り返しかどうか」で分ける必要がありそう（店舗 2026-09-26 の運用「連続する同じコール /
  チェック / フォールドは 2 回目以降を言わない」の名残）。
- **時刻**: 発話は聞き取った時刻（ライブの記録の時刻）に置いている。実際に話した時刻に置き直すと店舗の 18 ハンドで
  12 → 9〜10 に下がった（札の離脱と発話の順に engine の規則が合わせてある）。順番は決め打ちせず、数秒の範囲の
  入れ替わりを選択点（または尤度）で扱う必要がある。

## 評価の手順（案）

- 目標の数字 = 全部正しいハンドの割合（出所ごと）。行の一致は参考。
- 較正（値を決める）: 読み上げ集 3 つ・台本 16:50。評価（良くなったかを見る）: 店舗の真のアクションのある 18 ハンド
  と、これから集める実戦のハンド。シミュレーションは開発用で、精度の主張には使わない。
- 対にした比較（同じハンドで推定器なし / あり）。悪くなったハンドは個別に見る。
- 表示・正本に切り替える条件（追記 1 の 4.）は、目標の数字を「全部正しいハンド」に置き換えて見直す。

## 監査の反映（Fable 5.1, `docs/worklog/2026-09-30-estimator-audit.md`）

採る（v1 の中身。オーナーの判断は要らない）:

1. 物差しに **3 分解**（真実が編集で表せない / 表せるが探索が届かない / 届くが採点で負ける）と副指標（正すのに
   要る編集の数）、区間（Wilson）と対の比較（良くなった・悪くなったハンド）を常設する。上の確認では 8 ハンド中 6 が
   「表せる」側に移る。
2. 採点を log 事後確率にそろえる: 事前 π(A) = 合法手の数で割るランダムウォーク（弱い事前）、発話単位の状態
   {正常・丸ごと落ち・丸ごと幻聴}、各アクション種別で「語あり + 無言 = 1」の総和則をテストで固定。額は寄せずに
   選択点（第 2 の耳の候補・音の近い数字・最小額）にして混同行列で採点。反映できない語と捨てる語は 1 本の経路
   （幻聴）にする。engine の補いは観測の事象として採点（手置きの罰をやめる）。
3. 較正の出所: 無言の確率 p_miss(check/call/fold) は**実卓の真のアクションだけ**から（読み上げ集の 2.2% は実卓の
   約 20% の読めない率と 1 桁違う）、取り違え・幻聴・額の混同は読み上げ集（句の組で層別）、持ち上げ p_lift は
   卓状態の履歴（生の在否）から数え直す（fixture の離脱は 3 秒以上の不在だけで、短い持ち上げが抜けている）、
   ボタン p_btn は Beta(1,10)。値の少ないものは Beta 事前 + 感度の掃引（無言 vs 幻聴・離脱 = フォールド vs
   持ち上げ・似た音の額の 3 軸）。
4. 事後確率: 温度 τ を 1 つ較正、候補の外の質量 λ を混ぜる、同じ記録の候補は logsumexp で足す。要確認は
   「1 番と 2 番の差が小さい」**または**構造的な理由（無言を置いた・離脱を持ち上げにした・語を捨てた・額を候補で
   置き換えた・人数の宣言と合わない・ボードより前のストリートで終わった）。
5. 探索: ハンド単位でチェックポイントから再生してビームを伸ばす（セッション全体を毎回再生しない）。ビーム幅を
   2 倍にして 1 番が変わる率で探索の誤りを測る。

オーナーに決めてもらうこと（監査の推奨）:

- 表示・正本に切り替える条件（ADR-0056 追記 1 の 4.）の置き換え: 評価の前にコードと値を固定して書き残す /
  対にして**悪くなったハンド 0** / **良くなった 5 以上** / **誤りのあるハンドには全部「要確認」が付く** /
  40 ハンドで誤り 4 以下（90% は 40 ハンドでは確かめられない）/ 表示で 2 セッション運用して要確認の外の訂正が
  無ければ正本。
- 評価のデータ: 値を固定したあとに録る新しいセッション（**全ハンド**に真のアクション、記録を見ずに入れる = いまの
  入力画面の既定、5〜6 人の卓で 2 セッション以上、できればオーナー以外のディーラーも）。いまの 18 ハンドは開発に
  使ったので評価には使わない。

## 監査で見てほしいこと

1. この採点は log 事後確率として筋が通っているか。engine が補ったものを観測の事象として採点する対応づけは妥当か。
2. 値の較正: 少ないデータ（読み上げ集 519 語・台本 30 ハンド・店舗 18 ハンド）での推定と、較正と評価の分け方。
   読み上げ集（読んだ声）を実卓に使う偏り。
3. 独立性の仮定の破れの扱い（発話単位の相関・2 つの耳・人ごとの癖）。
4. N-best の softmax を事後確率として使うこと、要確認の決め方（差の閾値の較正）。
5. 探索（ビーム・深さ）の近似の誤りの測り方。
6. 評価: 18 ハンドでの判断のしかた（区間・対にした検定）、過学習、切り替えの条件。
