# Worklog: Phase 2.2 — hand logger × S2 session/seating 最小統合

## Date

2026-06-03

## Scope / Task

Phase 2.2（ADR-0008 Pattern A / `docs/contracts/hand-integration.md`）。S2 core
（`core/session*.py`）と既存 hand logger world を **config-gated な write-through** で
最小接続する。コードに手を入れる初回タスク。

## Goal

- `config.session_layer.enabled = true` のとき:
  - session 開始時に `SessionRepository.create_session()` で UUID4 hex の session_id を採番。
  - hand 開始時に現在の seating を `assign_seat` バッチで session レイヤへ write-through。
  - `HandSummary.session_id` に UUID4 hex、`players[i].player_id` を additive に流す。
- flag off のとき従来の hand logger 単独動作（rollback path）。
- **PHH はバイト不変**、JSON は **additive のみ**。

## Changed Files

- `config_default.json` — `session_layer.enabled`（default false）+ 説明コメントを追加。
- `core/hand_log.py` — `HandSummary.session_id` / `players[i].player_id` の additive 意味を
  docstring/コメントで明記（構造変更なし）。
- `integration/engine.py` — `IntegrationThread` に `session_repo` / `session_id` / `seating`
  を DI 追加。`_start_new_hand` で `_assign_seats_for_hand`（assign_seat バッチ）、
  `_finalize_hand` で `players[i].player_id` additive 付与 + session レイヤ有効時は
  canonical session_id を採用。
- `main.py` — `_init_session_layer()` ヘルパを追加。`run_cli` / `run_gui` が flag に応じて
  session レイヤを初期化し、IntegrationThread に DI。
- `tests/test_session_integration.py` — 新規。ON/OFF/耐障害性の統合テスト。

## Expected Behavior

- flag on: session が作成され、hand 開始ごとに `(session_id, hand_id, seat_no, player_id)` が
  session レイヤに記録され、`resolve_hand_ref` が読める。HandSummary に UUID4 session_id と
  player_id が入る。
- flag off: SessionRepository を一切呼ばず、従来の timestamp session_id・player_id なしの
  HandSummary を出力。旧 JSON reader 互換。
- PHH は両モードでバイト一致、player_id を載せない。

## Implemented Behavior

期待どおり。実装上の判断:

- **session_id の source of truth**: flag on のとき `_init_session_layer` が UUID4 を採番し、
  それを JsonWriter（ログファイル名）と HandSummary の双方に使う。`_finalize_hand` は
  session レイヤ有効時 `self._session_id`、無効時 `json_writer._session_id` を使い分ける
  （両者は wiring 上一致するが、明示して取り違えを防ぐ）。
- **player_id の住処**: `HandSummary.players` は `list[dict]` なので構造体追加は不要。
  session レイヤ有効 + seating にエントリがある seat だけ `player_id` キーを additive 付与。
  無効時はキーごと省略（旧 reader が無視できる）。
- **assign_seat 失敗時**: `SessionError` を捕捉し warning に留め、hand logger の進行は止めない
  （degraded; UX を壊さない）。失敗 seat は session レイヤに記録されない。
- **seat 選択 UX は未実装**（ISSUE-0006, Phase 2.3）。`main.py` の `seating` は現状空 dict。
  つまり `main.py` 経由では flag on でも player_id は実際には付かず、session 作成と
  session_id 切替のみが効く。seating を渡したときの write-through 本体は
  `IntegrationThread` 単体テストで検証。
- **PHH 不変**: `PHHExporter._build_phh_dict` は seat/name/stack のみ参照し player_id を無視。
  player_id 有無で export がバイト一致することを確認済（下記）。
