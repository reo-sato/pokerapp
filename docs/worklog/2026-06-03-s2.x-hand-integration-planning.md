## Expected Behavior

本タスクは planning であり「動作」は持たない。期待される成果は:

- 読者（次の実装者）が `hand-integration.md` と ADR-0008 を読むだけで、Phase 2.1/2.2/2.3 で
  「何を additive に足し」「何を絶対変えない」かを判断できる。
- ISSUE-0006 / 0007 が残 open question として明示され、scope-creep を防ぐ。

## Implemented Behavior

期待どおり、docs のみで以下を確定:

- 接続パターンとして Pattern A（write-through, additive）を採用（ADR-0008）。
- player_id は `HandSummary.players[i].player_id` に additive、PHH には **載せない**。
- session_id は Phase 2.2 で UUID4 hex（session レイヤ採番）に切替。legacy timestamp は schema 上は
  opaque 文字列として許容。
- `hand_ref` は HandSummary に埋め込まず、SessionRepository 側に住む（drift 回避, ADR-0006 Consequences）。
- hand 開始時に `assign_seat` バッチを呼ぶことで `hand_ref` が以降読める。
- Phase 2.0（現状）→ 2.1（schema sketch + config flag）→ 2.2（session_id 切替 + assign_seat 連携）→
  2.3（seat UI）→ 2.4（legacy reconciler, 任意）→ 3.x（ledger 連携）。
- rollback path として `config.session_layer.enabled` フラグを planned に追加（実装は別 phase）。
- legacy logs/*.json は **破壊しない**。必要なら sidecar + reconciler tool で後付け（ISSUE-0007）。
