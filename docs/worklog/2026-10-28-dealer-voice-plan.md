# 2026-10-28 ディーラーの声の照合（台帳 I）— 計画と I1 の道具

オーナー（10/28）:「音声書き起こしについて、雑談との切り分けに困っています。ディーラーの声質を覚えるというソリューションの
可能性を検討してください」→ 検討の答え（下の「効く範囲」）を受けて「やってみましょう。事前にディーラー名を登録しておいて、
なんらかの台本を読んでもらって声を覚えて、ディーラー交代時に名乗ってもらう。みたいな運用が良いと思います」。

## 効く範囲（期待しすぎない理由）

- マイク（DJI Mic Mini）はディーラーの口元にある。声の照合で分けられるのは**ディーラー以外の声**（お客さん・隣の卓・店員）。
  **ディーラー本人の雑談は同じ声なので分けられない**。こちらは今までどおり声の大きさ（宣言は +3.5 dB）と第 2 の耳・短い語の
  分類器に任せる。
- 前の検証（`2026-10-03-voice-style-study.md` の Stage 0）では、決まり文句の発話に「雑談かアクションか」の正解を全部渡しても
  推定器の結果が変わったハンドは 0 だった。いまの誤りの中心は取りこぼし・読み違い（真の賭けの額: 発話に無い 6%・
  Whisper の読み違い 23%）。
- 効くのは「お客さんの『コール』『フォールド』をディーラーの宣言と取り違える」場面。この数はまだ数えていない → I1 で数える。
- 1〜2 秒の短い発話では声の判定がぶれる。

## 運用（オーナー案）

1. ディーラー名を登録する。
2. 台本を読んでもらって声を覚える → **読み上げ集**（`tools/read_corpus.py`, 真のアクション入力の画面の `/corpus`）を名前を
   入れて読む。句ごとの音声がそのまま登録に使える（新しい画面は要らない）。30 句以上（5 分ほど）。全部読めば聞き取りの比較にも使える。
3. 交代のときに名乗る（「ディーラー交代、<名前>です」）→ I2。名前の聞き取りが崩れても、声で登録の中から選び直す
   （名乗りは「ここで替わった」という時刻の印として使う）。

## 段取り

- **I1 確かめる（オフライン・ライブは変えない）= 道具を作った**: 音声付きの zip（読み上げ集 + 同じ日のセッション）で、
  登録した声とセッションの発話の近さを数える。
- **I2 登録と名乗り（ライブには記録だけ）**: 登録を `dealer_voices.json`（店舗 PC ごと、更新で保持）に保存する。名乗りを
  読んで、ハンドの記録にディーラーを足す（additive）。発話ごとの近さを `transcripts.jsonl` に足す。ライブの読みは変えない。
  B の「ディーラーをセッションごとに記録できるか」の答えにもなる。
- **I3 推定器の証拠に**: 近さを「この発話はディーラーの声か」の観測として推定器の読みの選択肢の重みに入れる（第 2 の耳と同じく
  推定器だけ）。物差し・前向きの成績表で測ってから。

## I1 の道具（このコミット）

- `audio/dealer_voice.py`: 話者の埋め込み（k2-fsa が配る ONNX。既定は 3D-Speaker の CAM++ 192 次元 約 28 MB、ほかに ERes2Net・
  WeSpeaker）。入力は第 2 の耳と同じ 80 次元の対数メルから時間の平均を引いたもの。登録 = 発話の埋め込みの平均（外れた 1 割を
  除いて平均し直す）、近さ = コサイン類似度。0.3 秒未満の発話は測らない。
- `tools/dealer_voice.py`:
  - `fetch` = モデルを `models/speaker/` に。
  - `score <zip…>` = 読み上げ集を読んだ人ごとに登録（1 本目のマイクの句だけ）→ セッションの発話（音声のあるもの）ごとの近さを
    `logs/voice/<sid>.voice.jsonl` に。要約は「アクションに読めた / 決まり文句 / それ以外」の近さの分布・しきい値（既定 0.40）
    未満のアクションの数・アクションの発話がそれ以外より近く出る確率（AUC）・オーナーが聞いた決まり文句の 51 発話
    （`docs/dogfood/canned51-labels.json`）の action / none の AUC・登録が 2 人以上なら 10 分ごとのいちばん近い登録
    （交代を声だけで追えるか）・**近さの低いアクションの発話の一覧（聞いて確かめる）**。
  - 読み上げ集が無ければセッションのアクションの発話で仮に登録する（`--no-corpus` でも）。
- 試験: `tests/test_dealer_voice.py`（偽の埋め込み）。本物のモデルは合成の音で通るのを確かめただけ（1 発話 25〜29 ms）。
  **本物の声ではまだ試していない**（開発データに音声が無い・公開の話者の試験音声はこの環境から取れなかった）。

## I1 の合格の目安（先に決めておく）

次の 2 つが両方そろえば I2 に進む。そろわなければ止める。

1. 近さの低いアクションの発話（一覧の上位）をオーナーが聞いて、ディーラー以外の声だったものが**プレー 1 時間あたり 3 件以上**ある
   （取り違えが実際にある）。
2. その一覧で、ディーラー本人の声だったもの（誤って低く出た）が半分以下。

ディーラーの交代を声だけで追えるか（10 分ごとの表）は I2 の名乗りが要るかの判断に使う（追えても、名乗りは時刻の印として残す）。

## 店舗で要るもの

- 各ディーラーが名前を入れて読み上げ集を読む（30 句以上）。
- 同じ日のセッションを音声付きで（`audio.save_audio=true`、`pack_logs_audio.cmd`）。
- 送ってもらった zip を `python tools/dealer_voice.py score <zip…>` にかける（開発側）。
