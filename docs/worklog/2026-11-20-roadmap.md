## 2. 店舗の確認を 2 晩で → 最初の stable

**1 晩目**（20 分ほど + ふだんのプレー）

1. 開店前: 更新 → 版を控える → `asr_check.cmd` → iPad で `/staff/` が開くか。
2. iPad で「卓を始める」→ 1 ハンド → 「終了」→ もう一度始めて本番。
3. 10 ハンド目ごろ: 推定が数分で出ているか（iPad）・タスク マネージャーの CPU。
4. 動いている間に更新のコマンド → 断られるか。
5. 中盤: Wi-Fi を 60 秒切って戻す → 「送り直し待ち」が 0 に戻るか。
6. 卓 UI でボタンを 1 回動かす（`ground_truth.feed_button`）。
7. iPad で終了 → 「ログをまとめる（音声付き）」。

**2 晩目**

- PC の電源を入れ直し、RDP なしで iPad から始められるか（自動サインイン → 店舗サーバー → 起動）。
- 店舗サーバーのタスクを止めても、子のロガーが残るか。

**別の日**

- firmware v1.11 の書き込み（営業の無い日。失敗すると卓が使えないので stable と分ける）。

**最初の stable の関門**

- 1 晩目の 1・2・4・7 が通る。
- 電源の入れ直しで自動起動する。
- バックアップから戻す試しを 1 回する。
- その版の CI が緑。
- 戻す先の版を控える。
- 推定の成績と firmware は関門にしない。

通ったら `tools/release.py promote` を行い、店舗 PC は `update.cmd -Branch stable` にする。

**評価のモードの入力の負担**: 真のアクションを評価のモードで入れるのは、1 セッションの最初の 40 ハンドまで。残りは任意。
