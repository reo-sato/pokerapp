# 2026-10-28 テスト記録をリポジトリに置く

## ゴール

オーナー（10/28）:「他のセッションでもテスト記録を利用できるようにしたい」。

- 確認への回答は「文字のログに音声も加えてリポジトリへ」と「手元に保管して都度アップロード」の 2 つ。
- これまで記録は、セッションの一時的な領域とアップロードにしか無く、コンテナが消えると使えなかった。

## 決めたこと

- 文字のログは、開発のブランチの `data/store/<日付>/` に置く。
- 音声は、データ専用のブランチ `store-data`（orphan）に置く。
  - 開発のブランチに 480 MB を入れると、毎回のセッションの clone が重くなり、ディスクの上限に当たる。
  - 別のブランチなら、要るときだけ取れる。
- オーナーは、元の zip を手元にも保管する。
- 前の決まり「店舗の音声はリポジトリに入れない」は、この指示で「store-data ブランチにだけ置く・公開しない」に変える。

## 変えたファイル

- `tools/store_data.py`（新規）
  - `add`: 分割 zip から音声を除いて 1 つにまとめる・アップロードの名前の頭を外す・真のアクションは
    `truth_manifest.json` の時刻が最新の版・聞き取りの印はそのセッションの日のフォルダ・一覧を書き直す。
  - `stash-audio`: 別の作業用フォルダで store-data にコミットする。
  - `audio`: `git fetch` してから `git archive` で取り出す（ブランチを切り替えない）。
  - `list`
- `data/store/README.md`（使い方と一覧）、`data/store/2026-10-14・10-19・10-26/`
- `CLAUDE.md`（店舗ログのメモの節・ディレクトリ構成）、CHANGELOG
- `tests/test_store_data.py`

## 結果

- 文字は約 7 MB、音声は 17 個の zip で約 480 MB。
- store-data は日付ごとに 3 回 push した。
- `data/store/2026-10-26/*.zip` で評価すると、いまと同じ数字（コール 36/61・フォールド 45/84）が出た。
- `audio 2026-10-26` で 9 個を取り出せ、元の zip と同じだった。

## 残り

- 次の店舗ログからは、受け取ったら `add` と `stash-audio` をする。
