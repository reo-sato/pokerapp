# Worklog: Phase 2.3 — seat selection UX（desktop hand logger）

## Date

2026-06-03

## Scope / Task

Phase 2.3（ADR-0008 Pattern A / `docs/contracts/hand-integration.md` §7 Phase 2.3、ISSUE-0006）。
実運用で seat と player を紐づける最初の UX を desktop hand logger に追加する。scope は最小。

## Goal

- `config.session_layer.enabled == True` のとき:
  - hand 開始前に seat→player を選べる（モーダルダイアログ）。
  - carry-forward（直前 hand の seating を初期値）。
  - 選択結果が `IntegrationThread.update_seating` → `_assign_seats_for_hand` に渡り、
    SessionRepository に記録され、HandSummary に session_id / player_id が載る。
- `enabled == False` のとき従来 UX を維持（seat UI を出さない）。

## Expected Behavior

- flag on: 「新ハンド」→ seat ダイアログ（carry-forward）→ OK で write-through、キャンセルで hand 不開始。
  「席割り当て」ボタンで hand を開始せず seating だけ編集も可能。
- flag off: seat UI 非表示、「新ハンド」は従来どおり直接 new_hand。

## Implemented Behavior

期待どおり。設計上の判断:

- **スレッド越境**: seat 選択は GUI スレッド、`_start_new_hand` は IntegrationThread。GUI が
  `update_seating()` で seating を**同期的にセットしてから** new_hand イベントを enqueue するため、
  `_start_new_hand` は最新 seating を読む。`_seating_lock` で read/write を保護。
- **new_hand とダイアログの連結**: ダイアログは非ブロッキング（CTkToplevel + コールバック）。
  `on_confirm` で `update_seating` → `_enqueue_new_hand` と連鎖。Cancel は `on_confirm` を呼ばないので
  hand は開始されない（write-through もしない）。
- **carry-forward**: ダイアログ初期値は `get_seating()`（IntegrationThread が保持する直近 seating）。
  毎 hand「OK を押すだけ」で同じ seating を再適用、各 hand に独立 snapshot が記録される。
- **player 候補**: ダイアログを開くたびに `PlayerRepository.list_players()` を取得（起動時キャッシュ
  しない）。registry を参照するだけで player を作らない（CRUD は S1 別画面の責務）。
- **空席**: 「（空席）」選択 = seating に入れない（`build_seating_map` で除外）。
- **テスト可能性**: 純粋ロジック（`build_seating_map`）と GUI 構築を分離。dialog は customtkinter を
  モックして `_cmd_ok` / `_cmd_cancel` を直接検証。dashboard フローは `SeatAssignmentDialog` を patch
  して `update_seating` 呼び出し・new_hand enqueue を観測。

## 試した案 / 断念した案

- **案A（採用）**: GUI が `update_seating` で seating をセット → new_hand を enqueue。書き込み起点が
  hand 開始時の 1 箇所のままで、Phase 2.2 の write-through をそのまま使える。
- **案B（不採用）**: ダイアログ結果を AudioEvent のペイロードに載せて IntegrationThread に渡す。
  → AudioEvent の意味が肥大し、seating 編集（hand 非開始）に使えない。却下。
- **案C（不採用）**: `_start_new_hand` 内で GUI コールバックを同期呼び出しして seating を取得。
  → GUI スレッドと IntegrationThread の同期がデッドロック源になりうる。却下。
