## 監査の要点（コードの行番号は 6c92979 時点）

### 判定

- 配慮ゼロの一般的な発声だけで、**人手の確認なしに正しい**ハンド履歴を出すことは、今の機材（ワイヤレス
  マイク 1 本 + CPU の Whisper medium）では届かない。届かないのは「ベット・レイズの額とその主体」の層だけ。
- **骨格**（ハンドの開始・ストリートの区切り・残っている人・ショーダウンの勝者）は RFID だけでほぼ決まる。
  この上に音声を「疎で欠けのある観測」として当てはめれば、**額が聞き取れなかった所だけが不明として残る**記録
  になる = 訂正画面で直す所が分かっている記録。これが現実的な目標。
- 今の設計の最大の問題は ASR より **「聞いた順に、次の手番の人へ即確定する」**こと。1 つの聞き落としが以降の
  全員をずらし（2 ハンド目のプリフロップ）、`apply_corrections` が矛盾（コールする額が無いのに「コール」=
  ベットの聞き落としの証拠）をチェックに書き換えて証拠を消す（1 ハンド目のフロップ）。**RFID のストリート
  境界・マック通過・在否という一番確かな信号が推定に使われていない**（表示専用）。
- ASR の天井は「短い単語と数字」。長い自然文は正しく、1〜2 拍の語（「コール」「1500」「オールイン」）が崩れる
  （信頼度 0.27〜0.71、「ロープヘッグ」「ポループ」「オーリー」）。収録条件（マイクの距離・SN 比・語頭の
  切れ）と切り出し（RMS ゲート + 64 ms のプリロール）が主因の候補で、モデルの選択は二の次。

### 一般的なディーラーの発声（実測）と engine の前提の食い違い

ディーラーが言うのは、プレイヤーに伝える必要があること（ベット・レイズの額、オールイン、ヘッズアップ、
ストリート、ポット）。ロガーが必要とすること（誰がフォールド・チェックしたか）は言わないことが多い。
engine は「全員のアクションが順に 1 つずつ聞き取れる」前提。3 人卓の今回は省略が少なく、6〜8 人卓では
破綻が大きくなる（テストデータは問題を過小評価している）。

### 層ごとの天井

1. 骨格（ハンド・ストリート境界・残っている人・ショーダウンの勝者）: 音声なしで可能。
2. ベット・レイズ・オールインの額と主体: 音声が唯一の源。額は発明できない。主体は残っている人 + ルール +
   額の順序 + 時刻でかなり絞れるが、ヘッズアップの「チェック→ベット→コール」と「ベット→コール」は語だけ
   では区別できない。
3. 宣言されないチェック・コール・フォールド: ルールと残っている人から含意できる。

### 推奨する形（ADR-0056 の具体化）

観測層（音声 WAV + 全書き起こし + RFID の出現・消失・マック + 時刻）→ 骨格層（RFID から決定的に）→ 整列層
（発話を発話開始時刻でストリートに割り当て）→ 推定層（pokerkit の合法列 × 骨格の制約で制約付きビーム探索、
MAP + 周辺確率 + flag）→ 表示層（ライブは暫定 ⊕ 推定 ⊕ スタッフの訂正）。

- ストリート境界（ボードの札が最初に見えた時刻）は硬い制約。ラウンドは境界で必ず閉じる。
- 境界ごとの残っている人: 境界の時点で席に札がある（強）/ 境界前に中央を通過（強、回収と区別）/ 消えて
  戻らない（中）/「ヘッズアップ」（強）/ ショーダウンで手札が読めた（強）。
- 額が無い bet/raise は最小額で埋めて `amount_unknown`。ポット額の宣言は検算（チェックサム）。
- faster-whisper は n-best を返さないので、単語ごとの確率（`word_timestamps`）+ 語彙への音の近さ（カタカナの
  編集距離: ヒットアップ↔ヘッズアップ、オーリー↔オールイン、ロープヘッグ↔ロッピャク）で代える。別名の
  逐次追加が要らなくなる。
- ライブ経路は残すが、**RFID の境界でラウンドを強制的に閉じる**（含意したアクションを要確認で入れる）のは
  今すぐ入れる。1 つの聞き落としの影響が 1 ストリート内で止まる。
- 今の記録には推定に要るものが無い: `EventRecorder` はパース済みの AudioEvent だけを残し、読めなかった発話
  （「ヘッズアップでーす」「ロープヘッグ」）・札の消失・マック通過・音声は残らない。

### ASR / 収録の改善（期待効果とコストの順）

1. 発話の音声（WAV）と全書き起こし（読めなかったもの・雑音判定・単語確率・no_speech_prob・ゲートの統計）
   の保存 — 以後の判断をすべて店舗の実データで再現できる。最優先。
2. 口元マイク（ヘッドセット / ラベリア）+ 発話ごとの入力レベルの記録 — 効果は最大。発声は変えない。
3. 切り出しの改善: Silero VAD / プリロール 64 ms → 250〜300 ms / 無音の待ち 0.5 → 0.7〜0.8 秒 / 上限 5 → 15 秒。
4. プロンプトの書き換え: 語の列挙をやめ、実際の発声に近い自然文に（オウム返しの幻聴を減らす）。
5. 音の近さによる語彙照合。
6. モデルの比較（medium / large-v3-turbo / kotoba-whisper / large-v3）— 要計測。turbo 等はエンコーダが large
   相当で、この CPU では medium より遅い可能性が高い。事後の再書き起こしなら遅くてもよい。
7. 事後の再書き起こしのバッチ化。8. 文法制約つきの副認識器（語彙語・数字専用）。
9. RDP / デバイスの堅牢化（マイクを番号でなく名前で選ぶ、読めなくなったら開き直す）。10. スレッド数・beam。

### 妥協案（小さい順）

1. 口元マイク（発声は変えない）。2. ベット・レイズは語 + 額 + 点で言う（「レイズ 2500点」）。3. ストリートの
終わりにポット額を言う。4. アグレッサーだけポジションを言う（方針と衝突しうる）。5. 要確認のハンドだけ
スタッフが直す（既存の訂正画面）。6〜8. 配布直後に札をリーダーに置く運用 / 第 2 マイク / チップの追跡（高額）。
「フォールドを必ず言う」は求めない（RFID で代える）。

### 止める・戻すもの

1. BB 倍数への丸め（→ aac807e で済: チップの最小単位に）。2. 状態と矛盾する明示席の適用（保留にする）。
3. コールする額が無い「コール」を黙ってチェックにする射影（ベットの聞き落としの疑いとして要確認に）。
4. 1 ハンドごとに別名・除外語を足していくのを主な手段にすること。5. プレー中でない間の音声を録らないこと
（書き起こしは止めても録音は残す）。6. VAD なしの有音下限 0.15 秒。7. 厳しすぎる配布の検出（配ってすぐ
持ち上げると始まらない）— 緩めるなら計測してから。8. RFID のストリート遷移を no-op のままにすること。
9. 信頼度 0.40 未満の短い語に一律に付く要確認。

### 店舗で取る数字

M1 語彙語・数字の認識率（モデル × マイク × ゲート）/ M2 アクションの種類ごとの無宣言率 / M3 真のフォールドの
うち中央通過・消えて戻らないで取れる割合、残っている人の最長の不在（覗き見）/ M4 境界付近の発話と札の時刻の差 /
M5 ゲート設定ごとの幻聴率 / M6 認識時間と発話の長さ / M7 配布検出の失敗・遅れ。

### 不確かな点

店舗の faster-whisper の版（turbo の有無）、代替モデルのこの CPU での速さ、2 ハンド目で席4 の中央通過が
検出されていたか、「ロープヘッグ」が語頭の切れによるものか（音声が無いので確かめられない）、マイクの距離。

## 提案（オーナーの決定を入れた方針）

### フォールド（オーナー決定の具体化）

- 判定は RFID: 手札が卓の中央（ボードのリーダー）を通過したら即フォールド / 席のリーダーから札が消えて
  N 秒戻らなければフォールド（N は覗き見と区別する秒数。M3 で決める）/ 次のストリートの札が置かれた時点で
  札の無い席はフォールド。
- 音声の「フォールド」は次の手番の人に付けない。手番の人の札が離れかけているときに N 秒待たずに確定する
  裏付けにだけ使う。札が残っているのに聞こえたら、別の席（札が離れた席）のフォールドか聞き違いとして扱う。
- 手番でない席の札が離れたとき: その席より前の人のアクションが聞き取れなかったとみなし、間の人を
  チェック / コール（要確認）で補ってからフォールドを入れる案と、手番前のフォールドとみなして順番を待つ案
  （オーナーに決めてもらう）。前者なら 2 ハンド目は「席6 = 何か（コールで仮置き, 要確認）→ 席4 フォールド →
  席5 レイズ 2500 → 席6 コール」となり、ポットも正しくなる。
- ショーダウン: ベッティングが終わったあと最初に札が離れた人がマック（負け）。

### 次のサイクルの候補

1. フォールドを札の離脱で判定（上記）。
2. ストリートの同期（次のストリートの札のあとに話された発話が来たら、前のラウンドを閉じてから付ける）。
3. 記録の完全化（発話の音声・全書き起こし・札の離脱 / 中央通過をイベントに）。音声の保存はオーナーの判断が要る。
4. プリロール 300 ms。
5. 店舗で M1〜M7 を取る。

中期: 事後推定（ADR-0056）を正本に、表示は暫定 ⊕ 推定 ⊕ 訂正、要確認を構造（不明な額・補ったアクション・
候補の差）から付ける、音の近さによる照合。

## 実装（オーナーの回答を受けて, 同日）

オーナーの回答: 手番でない席の離脱 = 前の人の聞き落とし / 離脱 3 秒でフォールド / 発話の音声を保存してよい /
範囲は「フォールドを札の離脱で」「記録の完全化」「語頭の取りこぼし対策」（ストリートの同期は今回入れない）。
追加の指示: 札が戻って再検知されたら少なくともその時刻まではフォールドではない / 手番前に誤ってフォールドした
場合はたいてい札が再検知される / 音声のフォールドはショーダウン後のアウトオブポジション等を除いて補助に使って
よい / 見せずにマックしたらディーラーが「フォールド」と言う / ショーダウンは札を前に出すので必ずリーダーから
離れる（最初に離れた人をマックにしてはいけない）。監査の「手番まで待つ」「ショーダウンを在席で判定」は、
この指示で採らなかった。
